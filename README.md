# 灰銀の継承者 — ハクスラRPG（縦切り版）

`../game_design_prompt.md` の設計を、**戦闘 → 宝箱 → 鑑定 → 装備 → 再戦闘** という中核ループが
実際に回るところまで実装したものです。

## 起動

`index.html` をブラウザで開くだけです。ビルド不要、依存パッケージなし。

開発中はローカルサーバー経由を推奨します。ブラウザのキャッシュが効いてしまい
「直したのに反映されない」という事故が起きるため、キャッシュ無効ヘッダを返す開発用サーバーを
同梱しています。

```bash
python hakusura-rpg/tools/devserver.py 8124
```

検証テストは `test/index.html` を開くと自動実行されます。

## 技術的な選択

ES Modules と `fetch()` による JSON 読み込みは `file://` では CORS に阻まれ、ダブルクリック起動が
できなくなります。そのためモジュールではなく**クラシックスクリプト＋単一のグローバル名前空間 `RPG`**
を採用し、データカタログも JSON ではなく「オブジェクトリテラルを `RPG.data.*` に代入するだけの .js」
にしています。データ駆動の要件（§9.2「コンテンツ追加＝データファイルへの追記のみ」）は
これで満たされます。

型は `// @ts-check` + JSDoc で付けています。Node がある環境なら以下で型検査のみ実行できます
（トランスパイルは発生しません）:

```bash
npx -p typescript tsc --noEmit -p hakusura-rpg/jsconfig.json
```

## 実装済み

- **ダメージ計算 (§3 全ステップ)** — 基礎ダメージ／系統タグ倍率（同タグ加算・異タグ乗算）／
  固有ユニークバフの独立乗算／除算型防御軽減／属性相性／クリティカル／ランダム揺らぎ／上限減衰
- **ターン制コマンド戦闘 (§2.2)** — パーティ順行動 → 敵行動のループ、対象選択、撤退
- **連戦・フィールド (§10)** — 1/5/10連戦、HP引き継ぎ、報酬蓄積、最終ウェーブのボス補正1.5倍。
  **フィールド7種（推奨Lv1〜150）／敵21種／ボス7種**
- **キャラクター35体 (§8)** — レジェンド未満は7属性それぞれ2人ずつ。
  **レジェンド21体**はそれぞれ固有の特殊パッシブ／特殊技を持つ
- **バランス検証 (§14.2)** — 実測に基づく数値設計。`test/balance.html` で再検証できる
- **宝箱 → 鑑定 → 装備 (§7)** — 戦闘中は宝箱IDと個数のみ加算し、拠点で能力値を生成
- **スキルプラグイン機構 (§9.1)** — 多段/防御無視/毒/各種バフ/回復
- **ガチャ・限界突破・還元 (§6)** — 通貨はゴールドのみ。被りは自動で凸(+SP)に、完凸後はレアリティ別に
  ゴールド還元。主人公は排出プールから除外
- **スキルツリー (§5)** — 累計投資レベルによるティア解放（初級→中級5→上級10）、全キャラ共通テンプレート、
  **252ノード（初級102／中級100／上級50）**。装備スロット拡張、属性戦略のパターン、**アクティブ技の習得**、
  攻撃・生存の特殊パッシブ、レベル比例のリセット費用
- **被ダメージ軽減と無敵化 (§3.1-3)** — ツリー・装備・バフの軽減率は加算され、合計100%で被ダメージ0
- **データ駆動 (§9.2)** — キャラ・敵・スキル・装備・フィールド・ツリーはすべて `data/` の追記のみで増える
- **キャラクターアート (§1.3)** — `data/characters.js` の `art` パラメータからアニメ調SVGを生成。
  バストアップのアイコンと半身の立ち絵の2構図。主人公のみ男性、他は全員美少女で統一
- **主人公の名前入力 (§8.1)** — 初回起動時にダイアログで入力。編成タブと装備タブから変更可能。
  表示名は必ず `RPG.state.charName(id)` を経由するので、戦闘ログまで一貫して反映される
- **立ち絵の差し込みと顔アイコンの自動切り抜き (§1.3)** — `assets/characters/` に置くだけで反映。
  顔位置は自動検出し、`test/art.html` で微調整・PNG書き出しもできる
- **周回のQoL** — オート戦闘、高速化、同じ場所への再出撃、宝箱の一括開封、自動装備、
  装備の並べ替え・絞り込み・ロック・一括売却、キャラクターの並べ替えと検索（編成中を先頭固定）
- **装備の自動売却 (§7.4)** — レアリティとスコアで対象を決め、鑑定した瞬間に適用もできる。
  「パーティの誰かの装備より強いものは売らない」安全装置つき
- **装備プリセット (§7.5)** — キャラごとに3枠。今の装備を名前をつけて保存し、ワンタップで戻せる
- **装備の強化・厳選 (§7.6)** — +1〜+10の強化（ゴールド＋不要装備を素材に消費）と副オプションの振り直し。
  費用が装備の等級に比例して伸びるので、終盤のゴールドの使い道になる
- **装備セット (§7.7)** — 6種類。数値を足すだけのものは作らず、
  弱点コンボの挙動を変える／戦況を火力に変える／大きな代償と引き換えにする、のいずれかに絞ってある
- **派遣 (§10.4)** — 放置して実時間の経過ぶんだけ報酬を受け取る。同時1件、早送り不可。
  受け取り時に本物の戦闘を回すので、勝てない場所へ送れば何も持ち帰れない
- **オート回数 (§10.5)** — 手動は無制限のまま、オート戦闘だけが1戦闘につき1回消費する。
  実時間で回復し、手動を強いるクエストの報酬で上限が永続的に伸びる
- **弱点コンボ (§10.6)** — 属性有利や弱体中の敵を狙い続けるとパーティ火力が最大+40%。
  オートAIは目先の最大ダメージしか見ないので、段取りを組める手動のほうが強い
- **エンドレスタワー (§10.7)** — 上限の無い階層。HPが階をまたいで持ち越され、
  回復はボス階を越えたときだけ。到達報酬は最高到達階の更新時にしか出ないので周回で稼げない
- **図鑑 (§13)** — キャラクター・敵・フィールドの記録。**専用カタログを持たず `data/` から導出する**ので、
  データを1行足せば図鑑にも自動で並ぶ。敵は遭遇・撃破数、フィールドは出撃回数を記録。
  立ち絵はクリックで **832×1216 の原寸表示**（切り抜きなし）
- **セーブ/ロード** — localStorage。SPは §6.5 の式で復元するため保存しない
- **セーブの書き出し・読み込み** — JSONファイル／テキストで外部保存。検証付きの復元と5世代の自動バックアップ
- **戦闘演出** — ダメージ数字のポップ、会心・属性有利の強調、被弾の揺れ、HPバーの追従、
  撃破・復活・再行動の表示、ウェーブ／勝敗バナー
- **クエスト (§10.3)** — 縛り条件つきの戦い8種。人数／レベル上限／属性限定／ラウンド制限／
  全員生存／オート禁止と、敵レベル・能力倍率の上書きに対応。初回クリアにのみ専用装備・
  レジェンドキャラなどの報酬が出る（2回目以降は通常戦闘と同じ報酬なので周回の金策にならない）
- **報酬の経済設計 (§10.1)** — 経験値の人数割りを緩和し、直接ゴールドを圧縮して宝箱の売却を主収入化。
  全行動を自分で選んで勝つと報酬 +50%。`test/balance.html` の「4. 経済バランス」で常時検証している
- **状態異常 (§5.8)** — 6種。効くタイミングが全部違うので「どれを撒くか」が戦い方の選択になる
- **クラス (§12)** — 6種。1人1つ専任で、5レベルに1ポイントしか配られない代わりに1つ1つが重い。
  クラス技には「解禁ラウンド」と「クールタイム」があり、手動で戦うほど活きる
- **検証テスト (§11)** — 478項目

## スマートフォンで遊ぶ (§15)

サーバーと一切通信しない静的サイトなので、**ファイルをどこかに置けばそのまま遊べます**。
そのうえで、外出先で使うための仕込みが3つ入っています。

### 1. ホーム画面に追加できる（PWA）

`manifest.webmanifest` と `sw.js` があるので、スマホのブラウザで開いて
「ホーム画面に追加」すると、アドレスバーの無い全画面で起動します。

### 2. 圏外でも動く

初回に開いた時点で **103ファイル全部**を端末に保存します。
以降は電波が無くても起動し、戦闘も育成も普通に動きます（実測: サーバーを停止した状態で戦闘10回とも完走）。

> **ファイルを変更したときは**
> 1. `python tools/build_precache.py` で `sw.js` の一覧を作り直す
> 2. `sw.js` の `CACHE_VERSION` を1つ上げる
>
> 2 を忘れると端末に古い版が残り続けます。逆に、開発中に
> 「CSSを直したのに反映されない」ときは、たいていこれが原因です。
> `CACHE_VERSION` はファイル単位ではなく**まとめて捨てて取り直す**ための番号で、
> 新旧のJSが混ざって読み込まれる事故を根本から防いでいます。

### 3. 指で操作できる

- ノッチ／ホームバーを避ける（`safe-area`）
- ボタンの当たり判定は最低40〜44px
- 入力欄は16px以上（iOSの勝手なズームを防ぐ）
- hover でしか出ない情報を作らない（タッチ端末には hover が無い）

375px幅の全10画面で、横スクロールの発生と小さすぎるタップ領域が
どちらも0件であることを確認しています。

### 画像を追加・差し替えたときの手順

キャラや敵の絵を足す／透過させる／描き直したときは、**公開前に必ずこの2つ**を実行します。
1つ目を忘れると生成プロンプトが画像ごと配られ、2つ目を忘れると端末に古い絵が残り続けます。

```bash
python tools/cutout_background.py --apply     # 背景の透過（未処理のものだけ）
python tools/detect_faces.py --sheet          # 顔アイコンの位置を計測して確認
python tools/detect_faces.py --write          # characters.js に書き込む
python tools/strip_png_metadata.py --apply    # 生成メタデータの除去
python tools/build_precache.py                # 事前キャッシュ一覧の作り直し
python tools/bump_cache_version.py            # CACHE_VERSION を1つ上げる
python tools/publish_check.py                 # 公開前の総点検
```

順番に意味があります。透過は Pillow で保存し直すため PNG のテキストチャンクが消えるので、
プロンプトとシードの控えは `cutout_background.py` が `recover_metadata.py` を呼んで
退避画像から自動で回収します。

背景が「白い枠＋色の付いた板」の二重構造になっている絵は、
`--deep ファイル名.png` で名指ししたときだけ2段階で処理します（自動化していません。理由はツール内のコメント参照）。

NovelAI の PNG には生成プロンプト全文・シード・署名が埋め込まれています。
新しく置いた画像は当然それを持っているので、毎回取り除く必要があります。
既に処理済みの画像は自動で飛ばされ、控え（`tools/image_metadata_backup.json`）には**追記**されるので、
何度実行しても過去の記録は消えません。

そのうえで `sw.js` の `CACHE_VERSION` を1つ上げます。
**同じファイル名で差し替えたときは特に重要**で、上げないと端末に残った古い絵がそのまま表示され続けます。

画像を**増やした**ときは、これも実行します（差し替えただけなら不要）。

```bash
python tools/build_precache.py
```

キャラ・敵の絵も含めて初回にまとめて落とす方針にしてあります（現在143ファイル・約43MB）。
実行時キャッシュに任せると「圏外で初めて引いたキャラの絵が出ない」ことになり、
外出先で遊ぶという目的と噛み合わないためです。

#### 顔アイコンの切り抜き

`tools/detect_faces.py` が立ち絵から位置を計測し、`data/characters.js` の `art.face` に書き込みます。
`--sheet` を付けると切り抜き結果を並べた `face_sheet.png` が出るので、**書き込む前に必ず目で見てください**。

仕組みは「横幅を上から見ていき、**首のくびれ**を見つけて頭だけを切り出す」というものです。
大きさは頭の幅ではなく**全身の高さからの比率**で決めています。
幅は髪の広がり・角・翼・武器で簡単に倍近く膨らみ、実測でも 0.32〜1.00 まで散らばって使えませんでした。

手で `face` を書いてあるキャラは**上書きしません**（作者が意図して決めた値のため）。

透過（背景抜き）については、顔アイコンの自動切り抜き (`src/ui/facecrop.js`) が
四隅のアルファ値を見て透過背景を判定する作りになっているため、**透過させても壊れません**。
むしろ背景色との差で被写体を探す必要がなくなるぶん、検出は安定します。

| `tools/image_metadata_backup.json` | 画像から抜いたプロンプト・シードの控え |

これで 243MB → 約44MB になります。
`data/artprompts.js` はゲーム本体が読んでいないので、外しても遊ぶうえで影響はありません
（`test/index.html` は読みますが、無ければその節を飛ばします）。

> **順番に注意**
> `data/artprompts.js` は `tools/novelai_gen.py` が画像を作るときの元データでもあります。
> **必要な画像を全部作り終えてから**公開してください。
> 先にプロンプトを変えたり外したりすると、後から作る絵の画風が既存のものと揃わなくなります。

### 置き場所

HTTPS が必要です（Service Worker の条件）。無料で使えるものだと:

| 方法 | 向いている場面 |
|---|---|
| **GitHub Pages** | いちばん手軽。リポジトリに置いて Pages を有効にするだけ |
| **Cloudflare Pages / Netlify** | フォルダをドラッグするだけで公開できる |
| 自宅サーバー＋固定URL | 家の外から繋ぐ設定が別途必要 |

いずれも**公開範囲に注意**してください。URLを知っていれば誰でも開けます。

### セーブデータの持ち運び

セーブはブラウザごと（`localStorage`）なので、**PCとスマホでは別物**になります。
移すには「データ」タブから:

1. PC側で **ファイルに保存** または **テキストを表示**
2. スマホ側で **ファイルから読み込む** / **テキストから読み込む**

自動では同期しません。行き来しながら遊ぶ場合は、その都度移す必要があります。

## クラス (§12)

スキルツリーが「浅く広く積む」場所なのに対して、クラスはその逆です。

| | スキルツリー | クラス |
|---|---|---|
| ポイント | レベルごとに1（Lv100 で99） | **5レベルごとに1**（Lv100 で20） |
| 持てる数 | 全ノードから自由に | **1人1つ専任**（転職可） |
| 1つの重さ | 軽い | **重い** |
| 全部取れるか | 到底無理（252ノード） | 無理（各クラス 67〜71%まで） |

`data/classes.js` に6種。効果種別はスキルツリーと共通なので、
新しいクラスを足すときもデータを1つ書くだけで動きます。

| クラス | 役割 | 素質 | クラス技 |
|---|---|---|---|
| **守護者** | 味方の被害を引き受ける | HP+15% / DEF+20% | 絶対防壁 — 味方全体の被ダメ1ターン80%減 |
| **癒し手** | 倒れた仲間を数に戻す | 回復量+25% / 魔力+10% | 再臨の光 — 倒れた味方を全員HP50%で蘇生 |
| **破壊者** | 一撃の重さに全部を寄せる | ATK+18% / 大技+15% | 終焉の一撃 — 威力800% |
| **呪術師** | 状態異常で盤面を作る | 継続ダメ+30% / 弱体持続+1 | 疫病の坩堝 — 敵全体に6種すべての弱体 |
| **戦術家** | 手番を操る | 開幕バフ+20% / バフ持続+1 | 刻の号令 — 味方全員がもう一度行動 |
| **暗殺者** | 会心に全部を寄せる | 会心+15% / 会心倍率+0.25 | 首刈り — 確定会心＋防御無視 |

### クラス技に必ず鍵がかかっている理由

「全体蘇生」「全体8割軽減」を無条件で撃てると、戦闘の組み立てそのものが消えます。
そこで2つの鍵をかけてあり、**どちらもラウンドを数えるだけ**で表現しています。

| 鍵 | 意味 | 生まれる判断 |
|---|---|---|
| `readyRound` | このラウンドに入るまで撃てない | 短期決戦ビルドでは使えない、という差別化 |
| `cooldown` | 撃つとこのラウンド数は使えない | 「いつ切るか」 |

どちらもオート戦闘では活かしきれないので、**手動で戦う理由**をもう一段作る仕掛けにもなっています (§10.6 と同じ狙い)。
新しいクラス技を足すときは `data/skills.js` に `readyRound` / `cooldown` を書くだけで、エンジン側の変更は要りません。
検証テストが「鍵の無いクラス技」を落とすので、書き忘れは通りません。

### 無敵ビルドの作り方 (§3.1-3)

設計書は「複数の軽減手段を組み合わせて被ダメージ0（無敵）を実現可能にする」としています。
軽減の供給源は次の4つで、**すべて加算**されます。

- ツリー「受け流し」Lv5 … +20%
- ツリー「金剛不壊」Lv3 … +24%
- 装備の副オプション「被ダメージ軽減」 … 1枠あたり最大約11%（スロットは最大6枠）
- アクティブ技「不動明王」 … 3ターン +40%

ツリーだけで44%、「不動明王」を重ねて84%、装備で埋めると100%に到達して被ダメージが0になります。

## バランス（§14.2）

`test/balance.html` が検証ツールです。実際の戦闘エンジンとオート戦闘を回して、
ダメージ曲線・周回時間・収益効率を測ります。**敵の数値はこの実測から逆算して決めています。**

- 通常敵HP … 推奨レベルのパーティ火力の約0.6ラウンド分
- ボスHP … 同じく約4ラウンド分（ボス補正1.5倍込み）

| 始まりの草原 | 1 | 100% | 3.6 | 84% | 303 |

### 報酬の経済 (§10.1)

もともと「ゴールドは人数割りしないが経験値だけ人数割りする」という非対称性があり、
周回するほどゴールドだけが余ってレベルは上がらない状態になっていました。決定を
`src/core/economy.js` に集約して直しています。

- **経験値の分配** — 分母は `1 + (人数-1) × 0.3`。4人でも1人あたり全体の約53%を受け取る（旧: 25%）
- **直接ゴールドの圧縮** — `gold_mult` は「このフィールドは金持ち」という値ではなく調整つまみ。
  直接ドロップが総収入の4割に収まるよう校正してあるため単調増加しない
  （プレイヤーから見て意味があるのは1周の総収入で、そちらは単調に増える）
- **手動ボーナス** — 全ての行動を自分で選んで勝つとゴールド・経験値が +50%。
  一度でもオートに任せると付かない。オートを罰するのではなく手動を優遇する形にしてある

`test/balance.html` の「4. 経済バランス」が常時の監視役です:

| フィールド | 直接G | 宝箱G | 直接の比率 | 1レベルに何周 | ガチャ何回/レベル |
|---|---|---|---|---|---|
| 始まりの草原 | 303 | 454 | 40% | 3.7周 | 2.8回 |
| 崩れた廃坑 | 730 | 1,102 | 40% | 4.1周 | 7.5回 |
| 灼獄竜の巣 | 1,746 | 2,589 | 40% | 5.1周 | 22.3回 |
| 忘却の遺構 | 2,357 | 3,535 | 40% | 4.2周 | 24.9回 |
| 終焉の深淵 | 3,243 | 4,872 | 40% | 3.0周 | 24.0回 |

**終盤のゴールドについて**: ガチャの費用は 1,000 G 固定で、需要も有限（20体 × 完凸5 = 120回）
なので、そのままだと終盤はゴールドが余ります。その受け皿として
[装備の強化・厳選](#装備の強化厳選-76) を用意しました。費用が装備の等級に比例して伸びるため、
稼ぐほど使い道があります（竜の宝箱のレジェンド1個を +10 にするのに約31万 G）。

## セーブデータの管理

localStorage はブラウザの設定変更やサイトデータの削除で簡単に消えます。
周回で積み上げたものを守るため、右上の **データ** ボタンから次のことができます。

| | 内容 |
|---|---|
| **ファイルに保存** | `hakusura-rpg-save-YYYYMMDD-HHMM.json` としてダウンロード |
| **テキストを表示** | 同じ内容をテキストで表示（選択済みなので Ctrl+C でコピー） |
| **ファイルから読み込む** | JSONファイルを選んで復元 |
| **テキストから読み込む** | 貼り付けたテキストから復元 |
| **自動バックアップ** | 最大5世代。起動時・読み込み前・初期化前・復元前に自動で作られ、一覧から任意の時点に戻せる |
| **データを初期化** | 最初からやり直す。直前の状態は控えに残る |

読み込みは必ず検証を通します。**壊れたJSON・別ゲームのJSON・セーブ版数違い・主人公が居ない・
所持金が負数・未知のキャラID** はすべて拒否し、そのとき現在のデータには一切触れません。
読み込む前には内容の要約（主人公名・所持金・装備数・戦績）を提示して確認を取ります。

書き出したJSONには `"format": "hakusura-rpg-save"` の目印が入ります。
包みの無い素のセーブデータも読み込めるので、開発中に手で書き換えたものも流し込めます。

## 戦闘演出

戦闘エンジンはログ（読むもの）とは別に、**イベント列**（見せるもの）を出します。
`battle.events` に「誰に・何が・どれだけ」が積まれ、UIがそれを再生します。
ゲームロジックはイベントを一切参照しないので、演出を止めても結果は変わりません。

| イベント | 画面での見え方 |
|---|---|
| `damage` | 対象の上にダメージ数字が浮く。会心は金・大きめ、属性有利は橙・大きめ、軽減100%は「無効」。カードが揺れる |
| `heal` | 緑の `+数値` とカードの緑フラッシュ |
| `buff` / `debuff` | 効果名が浮く。軽減100%到達時は「無敵」 |
| `down` | グレーアウトしながら縮んで倒れる |
| `revive` / `extra` | 「復活」「再行動」が浮く |
| `action` | 行動したキャラのカードが前に出る |
| `wave` | 画面中央に `WAVE n` / `BOSS` / `VICTORY` / `DEFEAT` のバナー |

HPバーには**削れた分を遅れて追いかける帯**を出しているので、一撃でどれだけ入ったかが目で追えます。

高速モードでは演出間隔を 105ms → 22ms に詰め、多段ヒットで一度に大量のイベントが出るときは
さらに自動で間引きます。`prefers-reduced-motion` を設定している環境ではアニメーションを無効化します。

## クエスト (§10.3)

通常のフィールド周回はオートで回せる作業でよい、という前提に立っています。そのぶんクエストは
**手動で考えることを要求するもの**と**推奨レベルでは届かない格上**の2種類に絞り、
初回クリアにだけ強い報酬を置きました。2回目以降の報酬は通常戦闘と同じなので周回の金策にはなりません。

縛り条件は `data/quests.js` の `rules` に書くだけで効きます。

| 条件 | 効果 | 判定場所 |
|---|---|---|
| `maxParty` | 出撃人数の上限 | 出撃前 |
| `maxLevel` | 出撃できるキャラのレベル上限 | 出撃前 |
| `elements` | 出撃できるキャラの属性 | 出撃前 |
| `maxRounds` | 通算ラウンドの上限。超えたら失敗 | 戦闘中 |
| `allAlive` | 誰か倒れた時点で失敗 | 戦闘中 |
| `noAuto` | オート戦闘を禁止（トグル自体を隠す） | 戦闘中 |

`enemyLv` と `enemyScale` で敵のレベルと能力倍率を上書きできます。
**難度倍率は報酬に効きません** — 効かせると「強い敵を出す設定にして稼ぐ」抜け道になるためです。

出撃前の条件は破っているものを**全部まとめて**表示します（1つ直すたびに出撃し直させないため）。
戦闘中も画面上部に縛り条件のチップを出し続けるので、何をすると失敗かを忘れません。

現在8種類。`q_solo_plain`（単騎・オート禁止）から始まり、
`q_blitz_ruins`（10ラウンド以内）→ `q_trial_aegis`（敵Lv75・能力×1.35でレジェンド獲得）→
`q_beyond_end`（敵Lv130・能力×1.9で専用最強武器）と繋がります。

## 周回まわりの操作

ハクスラは同じ場所を何度も回るので、その往復を短くする仕掛けを入れてあります。

| 場所 | できること |
|---|---|
| 戦闘画面 | **オート** … 各キャラが自動で行動を選ぶ（回復優先 → バフ → 最も削れる攻撃）<br>**高速** … 1行動あたりの待ち時間を 260ms → 60ms に短縮 |
| 戦闘結果 | **もう一度** … 報酬を受け取って、同じフィールド・同じ連戦数へそのまま再出撃 |
| 出撃タブ | **同じ場所へ再出撃** … 直前の出撃内容をワンクリックで繰り返す |
| 鑑定タブ | **すべて開封** … 所持している宝箱を種類をまたいで一括開封し、レアリティ内訳を表示 |
| 装備タブ | **自動装備**（このキャラ／パーティ全員）<br>**並べ替え**（強い順／新着順／レアリティ順／部位順）<br>**絞り込み**（部位・系統タグ・レアリティ・未装備のみ）<br>**ロック**（🔒 で一括売却から保護。自動装備でも外れない）<br>**表示中をまとめて売却**（装備中とロック中は必ず除外） |
| 装備／ビルドタブ | **キャラクターの並べ替え** … 編成中を先頭に固定（既定ON・左端の線と順番の数字で表示）＋レベル／レア度／属性／名前／取得順<br>**属性で絞り込み**、**名前で検索**（設定はセーブに保存される） |

キャラクターが増えると「今使っている4人」を探すのが一番多い操作になるので、
編成中を先頭に固めるのを既定にしてあります。検索欄は入力のたびにリストだけを描き直し、
入力欄そのものは作り直さないのでフォーカスが飛びません。

### 自動装備の選び方

汎用スコアではなく、**候補を実際に着せたユニットを組み立てて §3 のダメージ計算で評価**します。

- キャラの技の `scaling_stat` を見ているわけではなく、期待火力そのものを測るので、
  魔力参照のキャラには自然と魔術装備が乗る
- 回復役は攻撃力が低いので、回復量も火力として評価に含める
- §3.2 の「異なる系統タグは乗算」も評価に入る（分散したほうがスコアが伸びる）
- 火力だけでなく実効HP（防御と被ダメージ軽減込み）も控えめに加味する

各スロットの上位候補を絞ってから1箇所ずつ入れ替え、改善が止まるまで繰り返します。
**ロック中の装備は外しません。** パーティ全員でやる場合は先頭のキャラから順に取っていくので、
同じ装備が2人に付くことはありません。

オートの行動選択は `src/core/autoplay.js` に分離してあり、期待ダメージの見積もりには §3 の
ダメージ計算をそのまま使います（乱数とクリティカルを固定して呼ぶので戦闘状態は変化しません）。

### 自動売却の安全装置 (§7.4)

鑑定タブの「自動売却ルール」で、**レアリティ**（複数選択）と**スコア下限**を条件にできます。
どちらかに当てはまれば売却対象です。`鑑定時に自動で売る` を入れると、開封した瞬間に
その回の分だけへ適用されます（手持ちの装備を巻き込みません）。

誤爆させないための3段構えを入れてあります。

1. **ロック中と装備中は常に対象外** — 判定側でも `RPG.state.sellMany` 側でも二重に弾く
2. **更新候補は残す**（既定ON）— パーティの誰かのその部位の装備を1つでも上回るスコアなら、
   条件に合っても売りません。誰かの部位に空きがあれば、その部位は丸ごと保護されます
3. **実行前に必ず件数と金額を出す** — 手動実行では確認ダイアログも挟みます

2 のおかげで、序盤に装備が空のうちは何も売られません。「掃除したいのに0個」と表示されたら、
先に自動装備を掛けてから使ってください。

### プレイして分かった問題への対応

実際に遊んで見つかった詰まりどころを、原因ごとに直しました。

| 症状 | 原因 | 直し方 |
|---|---|---|
| クエスト「格上狩り」が達成不可能になる | 主人公を編成から外せないため、レベル上限の縛りは主人公が育つと詰む | **出撃先を持たない達成条件型**を新設し、「自分より12レベル上の敵に勝つ」に変更。塔でも高難度フィールドでも達成できる |
| クリア済みクエストの追加報酬が受け取れない | 「クリア済み」フラグだけを持っていたため、後から報酬を足しても配れない | **受け取った報酬の種類**を記録する形に変更。起動時に未受取ぶんだけを配る |
| レジェンドが手に入る頃にはガチャで揃っている | 獲得クエストが終盤にあった | 推奨Lv10 / Lv25 へ前倒し。難度はレベルではなく敵の強化倍率で作る |
| 行動順を決められない | 主人公が先頭固定だった | **並び順を自由に変更可能**に（主人公は外せないまま）。編成画面にレベルも表示 |
| 属性貫通が全属性適応の下位互換 | 不利の無効化しかせず、適応Lv1と役割が同じだった | **不利属性の相手への特効**を追加。適応が「どこでも腐らない」のに対し、貫通は「苦手を狩り場に変える」 |
| 塔が低層から潜り直しになる | 常に1階からだった | **到達済みの階層帯から再開できる**ように。報酬は最高到達階の更新時のみなので、飛ばした階のぶんは出ない |
| 派遣がしょぼい | 8時間で実効30周。同じ8時間でオート回数は60回復するので 1/3 の価値しかなかった | 1周 12分→**8分**、報酬倍率 0.75→**0.85**。8時間で実効51周 |
| Lv50前後で深淵が作業になる | 強化・セット・コンボが乗って想定より強くなっていた | **高難度フィールドを2つ追加**（下記） |
| クエスト「蒼の誓い」が達成不能 | 属性限定の縛りが、編成から外せない主人公（光属性）にも適用されていた | **選べないキャラは属性判定の対象外**に。格上狩りと同じ種類の詰み |
| 主人公がレジェンドに見劣りする | 限界突破できずボーナスSPも得られない | **攻撃力と魔力を高い方に揃える**／**レベル×0.5%の火力上昇**の固有パッシブを付与 |
| 下位の攻撃スキルが死に技になる | 強技を覚えると選ぶ理由が消える | **小技専用の強化系統**を新設（下記） |

あわせて、バランス検証ツールが**装備の強化を織り込んでいなかった**ため、実プレイより弱い
パーティで測っていた点も直しています（Lv80の深淵で勝率 70% → 94%）。

### 高難度フィールド

装備の強化 (§7.6) とセット効果 (§7.7) が乗ると、Lv80前後で終焉の深淵が作業になります。
その先に2つ追加しました。

| フィールド | 推奨Lv | 敵Lv | 性格 |
|---|---|---|---|
| 灰燼の果て | 110 | 125 | 属性が入り乱れ、単一属性のビルドでは押し切れない |
| 創世の残響 | 150 | 170 | 強化と厳選を詰めていなければ削りきれない |

**ガチャの需要は有限（20体 × 完凸5 = 120回）**なので、これらを「ガチャ何回ぶん稼げるか」で
測っても意味がありません。`postGacha: true` を立てて経済判定の対象を分け、
代わりに「深いほど収入が増える（装備の強化に注ぎ込む先になる）」を確認しています。

塔の階層帯も 101階＝灰燼層 / 141階＝創世層 まで伸ばしました。

### 小技の使い道 (§4.3)

**強い技を1つ覚えると、それ以下の攻撃技は二度と選ばれなくなります。** 技を増やしても
選択肢が増えずノイズになるだけなので、「威力が低いこと自体が条件になる」効果を用意しました。
小技＝**威力100%以下の攻撃技**です。

| 仕組み | 内容 | 出どころ |
|---|---|---|
| 威力の底上げ | 小技の威力 +12%/Lv（強技には乗らない） | ツリー初級・ユニーク装備 |
| 自動発動 | 攻撃後に一定確率で小技が飛ぶ | ツリー中級・ユニーク装備 |
| 全体化 | 小技の単体攻撃が敵全体に当たる | ツリー中級・ユニーク装備 |
| 多重発動 | 小技が1回多く発動する | ツリー上級・ユニーク装備 |
| **全弾解放** | 持っている攻撃技を**すべて**威力60%で同時発動。撃った本数ぶん（最大4）行動不能 | ツリー上級 |

実測で、底上げを積むと威力100の「斬撃」が威力180の「覇王斬」の **89%** まで肉薄します。
上回らせないのが要点で、上回ると今度は強技が死に技になります。

**全弾解放は「技を多く抱えていること」がそのまま威力になる**技です。
これがあると、使わない技を覚えておく理由が生まれます。

### ユニーク装備 (§7.8)

**竜の宝箱**は数値を伸ばす箱です。系統タグ倍率・クリティカル・上限突破が乗り、素直に強くなります。
その上の**星辰の宝箱**から出るユニーク装備は、**系統タグ倍率を一切持たない**代わりに、
ビルドの方向性そのものを変える固有効果を持ちます。

つまり「攻撃力を伸ばしたいなら竜」「戦い方を変えたいなら星辰」という選択になります。
素の数値では竜に負けるので、効果を活かせる構成でなければ着ける意味がありません。

| 装備 | 固有効果 |
|---|---|
| 万手の刃 | 小技 +50% ／ 小技が1回多く発動 |
| 拡散の環 | 小技が敵全体に当たる ／ 小技 +20% |
| 連鎖の触媒 | 攻撃後60%で小技が自動発動 ／ 小技 +25% |
| 反響の外殻 | 被弾の55%を怒りに変え、次の攻撃で解放 |
| 虚ろの王冠 | 倒れた仲間1人につき火力+50% ／ HP40%で復活 |
| 初手の理 | 1ラウンド目 +150%、以降1ラウンドごとに-15% |
| 無縛の核 | 属性不利を受けない ／ 弱点コンボが落ちない |

同じ種類でも個体差があるので、厳選する意味は残ります。
入手先は**創世の残響**と**塔の101階以降**です。

### 装備セット (§7.7)

**「攻撃力+10%」のようなセットは作っていません。** それは既存の副オプションで足りています。
ここに置いたのは **戦い方そのものが変わるもの** だけです。部位は問わず、
同じセットを何個着けているかだけを数えます（スロットは最大6なので、2セットは早期から、
4セットはスキルツリーでスロットを広げてから狙う形になります）。

| セット | 2セット | 4セット |
|---|---|---|
| **残響** | 与えたダメージの25%を記録 | 記録は45%になり、**2ラウンド後にまとめて撃ち込まれる** |
| **憤怒** | 被弾の35%を怒りとして溜める | 怒りは70%になり、**次の攻撃で全て解き放たれる** |
| **千変** | 属性不利を受けない | **弱点コンボが外しても落ちず、上限 +3** |
| **刹那** | 1ラウンド目 +80% | 1ラウンド目 +180%。**以降1ラウンドごとに12%ずつ落ちる**（下限50%） |
| **常世** | HP35%で復活 | **倒れている仲間1人につき火力 +40%** |
| **共鳴** | 自分以外の味方全員 +12% | **自分の火力が半分になる代わりに、味方全員 +45%** |

千変はコンボ (§10.6) と、刹那はラウンド制限のクエスト (§10.3) と、常世は全滅寸前の状況と、
共鳴は編成そのものと噛み合います。数値ではなく**局面**を変えるものにしてあります。

セット装備は宝箱から出ます（銅0% / 銀10% / 金22% / 竜38%）。名前が「残響の長剣」のように
変わるので、並べたときに探せます。**厳選してもセットは外れません**（揃えた意味が消えないように）。

効果の適用先は性質ごとに分けてあります。

| 置き場所 | 扱うもの |
|---|---|
| `units.js` | 組み立て時に決まるもの（属性適応・復活HP・初回ラウンド） |
| `battle.js` | 戦況を見るもの（残響・憤怒・仲間の生死・ラウンド経過・味方への付与） |
| `damage.js` | 受け取った倍率を掛けるだけ（**純関数のまま**） |

### 装備の強化・厳選 (§7.6)

鍛冶タブ。**終盤になるとゴールドの使い道が振り直ししか無く、いくら稼いでも余っていた**
（ガチャの需要は 20体 × 完凸5 = 120回で打ち止めになるため）という課題への答えです。
レベルではなく**装備の等級に比例して伸びる**ゴールドの使い道になっています。

| | 内容 | 費用 |
|---|---|---|
| **強化** | +1〜+10。平坦ステータスが1段につき +6%（+10で ×1.6） | ゴールド＋素材（不要装備） |
| **厳選** | 主ステータスと副オプションを振り直す。部位とレアリティは不変 | ゴールドのみ |

竜の宝箱のレジェンド装備を +10 まで積むと **312,366 G ・素材43個**（実測）。
終焉の深淵で 8,383 G/周なので1個あたり約37周、装備12枠ぶんで約450周の受け皿になります。
序盤の銅の宝箱コモンなら +1 が 90 G なので、序盤から普通に使えます。

**強化で伸びるのは平坦ステータスだけです。** 系統タグ倍率・クリティカル率・上限突破・軽減は
伸ばしていません。§3.2 のダメージ曲線はこれらの値を前提に調整してあり、ここを伸ばすと
「宝箱のグレードで強さが決まる」状態に逆戻りするためです（`gear.js` の `softScale` と同じ理由）。

失敗判定は入れていません。乱数はドロップと厳選だけで足りていて、
払ったぶんが消える体験まで足すと時間の無駄が増えるだけになります。

誤爆を防ぐ仕掛け:

- 素材は**弱いものから自動で選ばれます**（強い装備を誤って食わせないため）
- **装備中・ロック中・強化する本体そのもの**は素材にできません
- 厳選は**強化値・名前・ロック状態を引き継ぎます**。積んだ装備も安心して振り直せます
- クエスト報酬の専用装備は厳選できません（強化はできます）

### 装備プリセット (§7.5)

装備タブに、キャラごとに3枠あります。今の装備を名前をつけて保存し、「適用」で戻せます。

装備は「1つを1人だけ」という原則を崩さないので、保存した装備を他のキャラが着けていた場合は
**そちらから外して持ってきます**。適用後にどこから移動したかを名前つきで報告します。
売却済みの装備は欠番として飛ばし、何点欠けたかを出します。

### エンドレスタワー (§10.7)

上限の無い階層を、どこまで登れるかを競う場所です。**手動でしか深く行けない場所**として作りました。

- **HPが階をまたいで持ち越されます。** 回復は `bossEvery`（5階）ごとのボスを越えたときの
  最大HP35%だけ。それ以外に回復手段はありません
- **倒れたら終了。** そこまでの到達階が記録になります
- 1階ごとに敵レベル +1.7、能力倍率 +0.035。ボス階はさらに ×1.25
- 階層帯は既存フィールドの敵プールを借ります。フィールドを増やせば帯も増やせます

**手動が有利になる理由は速さではなく被害の少なさです。** 1階あたりの消耗を抑えられるほど
深く行けるので、弱点コンボ (§10.6) を繋いで短いラウンドで倒せるかが効きます。
オートAIはコンボを組めないため、同じ編成でも到達階が伸びません。

#### 周回で稼げないようにしてあること

到達報酬は **最高到達階を更新したときにだけ** 出ます（クエストの初回クリア報酬と同じ考え方）。
浅い階を何度登り直しても報酬はゼロで、通常の戦闘報酬しか入りません。
`claimTo()` が「前回どこまで受け取ったか」を持っていて、差分だけを渡します。

節目（10 / 25 / 40 / 50 / 75 / 100階）には専用装備やオート回数の上限アップを置いてあり、
`data/tower.js` の `milestones` に追記するだけで増やせます。

#### 実装の再利用

階ごとの敵の強さは、クエストが持っている `enemyLv` / `enemyScale` の上書き機構を借りています
（同じ仕組みを2つ作らないため）。タワーの設定には `id` を持たせていないので、
`finishBattle` の「クエストの初回クリア報酬」は発火しません。

### オート戦闘の制限 (§10.5)

実測すると **高速オートは1周（5連戦）を約3.6秒**でこなします。派遣が1周12分なので
**200倍**の効率になり、時間で縛ったはずの周回が戦闘画面からまるごと迂回されていました。

| 方式 | 1周あたり |
|---|---|
| 高速オート | 3.6秒 |
| 通常オート | 15.7秒 |
| 派遣 | 720秒 |

**手動側の報酬を上げるだけでは埋まりません。** 差は「1周あたりの報酬」ではなく
「単位時間あたりの周回数」にあるので、周回速度そのものに上限が要ります。

ただし全体スタミナ制はこのゲームに合いません。買い切りで遊ぶ作りなのに、手動で遊びたい人まで
待たされるのは本末転倒です。そこで **手動は無制限のまま、オートだけが回数を消費する** 形にしました。

| | 消費 | 速度の上限 |
|---|---|---|
| 手動 | **なし** | 自分で操作する時間そのもの |
| オート | 1戦闘につき1回 | 回数（8分で1回復・初期上限20） |
| 派遣 | **なし** | 1周12分 |

これで「同じコストなら手動のほうが得（手動ボーナス +50%）」が初めて成立します。
上限は **手動を強いるクエストの報酬**（`autoCharge`）で永続的に伸びるので、
手動で頑張るほどオートが楽になるという循環になっています。

消費は1戦闘につき1回だけです。途中で手動に戻して再開しても二重には取りません。
回復は実時間なので、タブを閉じていても進みます（端数の時間は次の回復に持ち越し）。

### 弱点コンボ (§10.6)

属性有利、または弱体中（毒・防御崩壊など）の敵を狙うとコンボが1段積まれ、
**パーティ全体の火力が1段につき +8%、最大5段で +40%** 上がります。
弱点を外すと1段だけ落ちます（0には戻しません。1手のミスで台無しにしないため）。

**オートAIはこれを考慮しません。** `RPG.autoplay` は「今いちばん削れる技」しか選ばず、
属性有利を維持したりデバフを入れてから殴ったりという段取りは組みません。
つまりこの仕組みは、手動で考えて戦う人だけが取り切れる火力です（テストで縛っています）。

計算そのものは `damage.js` の `options.comboPower` を受け取るだけで、
積み上げの管理は `battle.js` が持ちます。ダメージ計算は純関数のままです。

### 派遣 (§10.4)

出撃タブでフィールドを選ぶと「派遣」が出ます。放置して、**実時間の経過ぶんだけ**報酬を受け取ります。

#### なぜ作り直したか

以前は「まとめ周回」として、ボタン1つで10周ぶんの戦闘を即座に計算していました。
10周が実測 5ms で終わるので、**実質「押すと数値が増えるボタン」**になっており、
周回というゲーム要素そのものが消えていました。作った本人の設計ミスです。

いまは周回のコストを **実時間** に置き換えています。

- **1周につき 12 分**。30分＝2周 / 4時間＝20周 / 8時間＝40周
- **早送りする手段はありません。** 時間前に受け取ろうとすると残り時間を出して断ります
- **同時に出せるのは1隊だけ。** 並べて回すことはできません
- **受け取り時に本物の戦闘エンジンを回します。** 勝てない場所へ送れば持ち帰れません
  （深淵へ格下のパーティを送った実測: 40戦0勝、報酬0）
- 報酬は手動で戦った場合の **75%**。見ていない時間ぶんは効率を落としてあります

編成は縛りません。派遣は「触らない時間を報酬に変える装置」であって、手動の上位互換では
ないという位置づけです。手動戦闘には別途 **+50% の手動ボーナス** があります。

セーブに持つのは開始時刻と条件だけなので、**リロードしてもタブを閉じても進みます**
（実測: 8時間派遣を75%地点でリロード → 進捗と残り時間を維持）。
端末の時計を巻き戻されても進捗が負にならないようにしてあります。

## 図鑑 (§13)

### 図鑑そのもののデータは持たない

図鑑用のカタログを別ファイルに作ると、キャラや敵を1体足すたびに2箇所を直すことになります。
ここでは**項目を必ず `RPG.data.*` から導出**し、セーブには「どこまで見たか」だけを持ちます。

```
codex.enemies[敵ID] = { seen: 遭遇回数, killed: 撃破数 }
codex.fields[場ID]  = { visits: 出撃回数 }
```

キャラクターは「所持しているか」がそのまま解放条件なので、記録を別に持ちません。
この結果、`data/characters.js` や `data/enemies.js` に1体足すだけで、
図鑑の分母・一覧・出現場所の逆引きがすべて自動で追従します（テストで検証しています）。

同じ理由で、表示側もデータ構造に追従するように書いてあります。

| 表示 | 導出元 | データを足したときの挙動 |
|---|---|---|
| ステータス | `RPG.units.STAT_LABEL` を引く | ステータスを増やしても表示側は変更不要 |
| キャラの技 | 組み立て済みの `unit.skills` | `unique_skills` / `common_skills` / ツリー習得のどれでも拾う |
| 敵の出現場所 | `data/fields.js` を走査 | フィールドを足せば自動で逆引きに載る |
| 固有効果 | `passives` / `situational` のキー | 知らないキーはキー名のまま出るので落ちない |

### 発見の記録

戦闘エンジンは `battle.encountered` / `battle.defeatedEnemies` に数を数えるだけで、
セーブには触りません。書き込みは戦闘終了後に `RPG.codex.record(battle)` が行います。
まとめ周回でも同じ関数を通すので、画面を出さなくても図鑑には残ります。

フィールドの解放は**実際に出撃したか**で判定します。出現する敵から逆算すると、
同じ敵を使い回している別のフィールド（廃坑のゴーレムは灼獄竜の巣にも出る）まで
解放されてしまうためです。

## キャラクターアートについて

### UIアイコン

タブ・通貨・属性・系統タグ・ステータス・装備スロットなどのアイコンは
[Free Game UI Assets](https://freegameui.net/)（**CC0 1.0**・帰属表示不要・商用可）の素材です。
34点を `assets/ui/` に置いています。対応表は [assets/ui/README.md](assets/ui/README.md)。

**元のSVGは一切改変していません。** すべて単色（`fill="white"`）の 128×128 SVG なので、
CSSの `mask-image` で切り抜いて `currentColor` で塗る方式にしました。

```js
W.icon('elem-fire')                       // 現在の文字色で塗られる
W.icon('coin', { size: '15px', color: 'var(--gold)' })
```

こうすると属性ごとの色分けやレアリティ別の着色が既存の配色変数だけで完結し、
素材ファイルに手を入れずに済みます。差し替えたいときは同名のファイルを置くだけです。

絵文字（⚔🎁🪙 など）を置き換えたのは、**OSごとに絵柄が変わってしまう**ためです。

### 敵の立ち絵の置き場所

**`assets/enemies/` に `敵ID.png` を置くだけです。** データ編集は不要です。
ファイル名の一覧は [assets/enemies/README.md](assets/enemies/README.md) にあります。

味方と違い、**敵は顔の切り抜きを一切しません。** 生成した画像をそのままの構図で戦闘画面に表示します。
NovelAI などで出力した 832×1216 の画像を、加工せずそのまま置いてください。

- 推奨サイズ **832 × 1216**（味方の立ち絵と同じ。表示枠もこの比率）
- 背景は透過推奨だが、透過していなくてもそのまま表示できる
- 未配置の敵は紋様タイルで表示されるので、少しずつ差し替えていける

### 立ち絵の置き場所

**`assets/characters/` に `キャラクターID.png` を置くだけで反映されます。** データ編集は不要です。
ファイル名の一覧と詳しい手順は [assets/characters/README.md](assets/characters/README.md) にあります。

- 推奨サイズ **832 × 1216**（表示枠もこの比率に合わせてあります）
- 背景は**透過PNG推奨**（顔の自動検出の精度が上がります）
- **顔アイコンは立ち絵から自動で切り抜かれる**ので、別途用意する必要はありません
- 自分で用意した顔アイコンを使いたい場合のみ `assets/characters/icons/` に同名で置きます

`test/art.html` が調整ツールです。立ち絵と切り抜き結果を並べて確認でき、スライダーで微調整すると
`data/characters.js` に貼れる形の `face: { x, y, size }` が表示されます。
切り抜いた顔を 512×512 のPNGとして書き出すこともできます。

### 画像の取り込み

生成した画像を手でリネームして `assets/` へ置く作業をなくすための道具が2つあります。
**どちらも取り込み先の一覧を `data/characters.js` / `data/enemies.js` から読み、
保存先と拡張子を `data/art.js` から読みます。** キャラや敵を1体足せば、道具の側にも
自動で枠が増えます（道具のコードに個別のIDは書かれていません）。

#### 1. ブラウザのツール — `tools/import.html`

```bash
python hakusura-rpg/tools/devserver.py 8124
```

を起動して <http://localhost:8124/tools/import.html> を開きます。

- 画像をまとめてドロップすると、**ファイル名にIDか名前が含まれていれば自動で割り当て**ます
  （`em_golem.png` も `廃坑のゴーレム_v2.png` も `… s-2282933820 em_golem.png` も通ります）
- 判断できなかったものは一時置き場に並び、プルダウンで割り当てられます
- 1体ずつ「画像を選ぶ」でファイルダイアログから選ぶこともできます
- **「保存先フォルダを選ぶ」で `hakusura-rpg`（または `assets`）を一度選べば、
  正しい名前で直接書き込みます。** Chrome / Edge が必要です
- それ以外のブラウザでは、正しい名前を付けたファイルのダウンロードになります
- 既に画像があるものは「設定済み」、サイズが 832×1216 と違うものは注意書きが出ます

#### 2. ミニツール — `tools/import_images.py`

ブラウザを使わない場合はこちら。Python の標準機能だけで動きます。

```bash
python hakusura-rpg/tools/import_images.py
```

引数なしで起動すると一覧が出て、行を選んで**エクスプローラーのダイアログ**から
画像を選べます。「フォルダからまとめて」でフォルダ内を一括で振り分けることもできます。

```bash
python hakusura-rpg/tools/import_images.py <フォルダ>
```

フォルダを渡すと、その中の画像をファイル名から自動で振り分けてコピーします。
`--dry-run` を付けると結果だけを表示し、`--list` でまだ画像が無いものを一覧できます。

同じIDで拡張子違いのファイルが残ると、探索順しだいで古い方が読まれてしまうため、
取り込み時に古い方を取り除きます。Pillow が入っていればサイズも確認します。

### 画像の生成 — `tools/novelai_gen.py`

NovelAI の API を直接叩いて立ち絵を作ります。**APIキーは環境変数からしか読みません。**
ソースにも設定ファイルにも書きません。

#### APIキーの設定

キーは NovelAI のサイトで発行します（アカウント設定 → **Persistent API Token**。`pst-` で始まる文字列）。

**ダブルクリックで使うなら、環境変数を「ずっと残す」形で設定してください。**
`.bat` は新しいプロセスとして起動するので、下の「この窓だけ」の設定では読めません。

```powershell
setx NOVELAI_API_TOKEN "pst-xxxxxxxx"
```

実行したら**窓を開き直してください**（`setx` は今開いている窓には反映されません）。
Windows の「システム環境変数の編集」→「環境変数」→ ユーザー環境変数に追加しても同じです。

その窓の中だけで一時的に使う場合:

```powershell
$env:NOVELAI_API_TOKEN = "pst-xxxxxxxx"    # PowerShell（窓を閉じると消える）
```
```bash
export NOVELAI_API_TOKEN=pst-xxxxxxxx      # bash
```

読めているかの確認:

```bash
python tools/novelai_gen.py --check
```

キーの中身は表示せず、長さと先頭4文字だけを出します。`pst-` で始まっていない、
前後に空白が入っている、といった取り違えもここで分かります。
そのうえで契約情報を1回だけ取りに行き、トークンが実際に通るかまで確かめます
（画像は作らないので **Anlas は減りません**）。
一覧画面（引数なしで起動）の上部にも同じ状態が出ます。

#### エラーが出たときの読み方

| HTTP | 意味 | 対処 |
|---|---|---|
| 401 | トークンが無効 | `--check` で先頭が `pst-` か確認。作り直したら古いものは失効します |
| 402 | 支払い・残高 | サブスクリプションと Anlas の状態を確認 |
| 403 + `error code: 1010` | **Cloudflare に弾かれている** | 下記参照 |
| 429 / 5xx | 混雑・一時的な不調 | 自動で待って4回まで試し直します |

403 は再試行しても結果が変わらないので、待たずに理由を出して止まります。

> **`error code: 1010` について**
> urllib の既定 User-Agent（`Python-urllib/3.x`）は NovelAI の前段にいる Cloudflare に
> 弾かれ、APIへ届く前に 403 になります。実測で確認済みです。
>
> | User-Agent | 結果 |
> |---|---|
> | 既定 | `403` / `error code: 1010`（Cloudflare が返す） |
> | ブラウザ風 | `401` / `{"statusCode":401,…}`（APIに届いた上での認証エラー） |
>
> このため `novelai_gen.py` はブラウザと同じ形の `User-Agent` / `Origin` / `Referer` を
> 付けて送ります。**この指定を消すと必ず 403 になります。**
> 同じ症状は `assets/ui/` の素材を取得したときにも起きました。

**引数なしで起動すると一覧画面が開きます。** `tools/画像を生成.bat` をダブルクリックしても同じです。
行を選んで「候補を選ぶ／生成」を押すと、その対象の画面へ進みます。

```bash
python tools/novelai_gen.py                        一覧画面（引数なし）
python tools/novelai_gen.py em_slime --count 4     候補を4枚
python tools/novelai_gen.py --missing enemy        画像が無い敵をまとめて
python tools/novelai_gen.py --pick em_slime        候補から選ぶ画面へ直行
python tools/novelai_gen.py --list-prompts         使われるプロンプトを全部表示
python tools/novelai_gen.py --check                APIキーが読めているか確認
python tools/novelai_gen.py em_slime --dry-run     送信せず内容だけ確認
```

> **`.py` を直接ダブルクリックすると、エラーが出たときに窓が一瞬で閉じて内容が読めません。**
> 付属の `.bat` から開いてください。失敗したときだけコンソールが残ります。

#### 提供元に負荷をかけないための作り

- **同時接続は常に 1。** 必ず1件ずつ順番に投げます
- 既定で **10 秒あけて**次へ進みます。`--delay` で変えられますが **3 秒未満にはできません**
- 429 / 5xx が返ったら待ち時間を倍にして最大4回まで待って試し直します（`Retry-After` があればそれに従う）
- **1回の実行で 40 枚を超える指定は拒否します。** 事故で大量送信しないための歯止めです

#### プロンプトの決まりかた

```
enemies_image/prompt_overrides.json（手で調整したもの）
  → data/artprompts.js の個別指定
    → 属性・ボス判定・髪型からの自動合成
```

最後の自動合成があるので、**`data/enemies.js` に1体足すだけで生成できる状態**になります。
水属性のボスを足せば「pale ice blue theme … boss, imposing」が自動で組まれます。
出来が気に入らないときだけ個別指定を書けば済みます。

主語（`1girl` / `1boy` / `monster girl`）は、個別プロンプトが自分で名乗っていないときだけ
補われます。土台の側に主語を書かないのは、主人公だけ男性という前提 (§8.1) と
矛盾したタグが出るのを防ぐためです（テストで縛っています）。

#### 撮り直しと調整

生成した画像は `assets/` へ直行せず、いったん `enemies_image/generated/<ID>/` に貯まります。
使ったプロンプトとシード値が同じ名前の `.json` に残るので、あとから再現・微調整ができます。

```bash
python tools/novelai_gen.py --pick em_slime
```

で候補を並べた画面が開きます。ここで

- 候補をクリックすると、その画像を出したプロンプトが下の欄に入る
- 欄を書き換えて「この内容で生成」を押すと、**その場で撮り直せる**
- 気に入ったら「選んだ1枚を採用」で `assets/enemies/em_slime.png` へ
- 「プロンプトを保存」で `prompt_overrides.json` に残り、次回から既定になる

コマンドから調整する場合は `--add "cute, smiling"` でタグを足す、`--prompt "…"` で丸ごと
差し替える、`--seed` で同じ絵柄を固定する、といった方法があります。
`--save` を付けると、そのとき使ったプロンプトが上書きとして保存されます。

### 顔の自動切り抜きの仕組み

canvasで別画像を作るのではなく、**正方形の枠の中で `<img>` を拡大・移動させるCSS方式**です。
`file://` で直接開いても確実に動き、元画像の解像度がそのまま活きます。

顔の位置は次の優先順位で決まります。

1. `art.face`（手動指定）
2. ピクセル解析による自動検出 — 透過部分または四隅の色から被写体の外接矩形を求め、
   その上端から一定割合の帯を頭部とみなし、帯の中の重心を中心に正方形を切り出す
   （`http://` で開いている場合のみ。検出結果はブラウザに保存されます）
3. `data/art.js` の `defaultFace`（全身の立ち絵で頭部がだいたい収まる既定値）

### 画像が無い場合のフォールバック

立ち絵を置いていないキャラクターは、`art` パラメータから組み立てた**アニメ調SVG**で表示されます。
キャラを追加するときは `data/characters.js` に `art` を書くだけで、`src/ui/art.js` を触る必要はありません。

```js
art: {
  gender: 'female',                 // 主人公のみ 'male'
  hair: 'twin',                     // long / twin / bob / ponytail / hime / wavy / crop
  accessory: 'ribbon',              // ribbon / halo / horn / visor / hairpin / circlet / none
  expression: 'smug',               // calm / gentle / fierce / cool / smug
  hairColor: '#f0503f', hairLight: '#ff8a72', hairDark: '#8c2018',
  eye: '#ffb648', eyeLight: '#ffe6a8',
  outfit: '#3a1218', outfitLight: '#5e2028', outfitTrim: '#ffb648',
  accentColor: '#ffb648',
}
```

規約どおりのファイル名を使わず、任意のパスを指定したい場合は `art` に直接書けます。

```js
art: { image: 'any/path/icon.png', standeeImage: 'any/path/full.png', /* 以下は従来どおり */ }
```

なお、この生成SVGは『崩壊：スターレイル』『ゼンレスゾーンゼロ』級の描き込みには**達していません**。
実際のイラストを `assets/characters/` に置くまでの繋ぎとして用意したものです。

## 設計書との相違点（要判断）

**§11 テストケース1 の期待値**

設計書は防御定数を `C = 被攻撃側レベル × 100 + 500` と定義しており、Lv1 なら **C = 600** です。
しかし同じテストケースの計算過程は `軽減率 = 50/550` すなわち **C = 500** で算術されており、
その結果として期待値が「≈45」になっています。両者は同時には成立しません。

本実装は**明記された式（C = 600）を正**とし、最終ダメージ **46** を返します。
テストページには参考として C=500 の場合の 45 も併記してあります。
式のほうを直したい場合は `src/core/damage.js` の `DEF_CONST_PER_LEVEL` / `DEF_CONST_BASE` を
変更すれば済みます（他に散らばっていません）。

**§3.2 と §4 の関係**

§3.2 は系統タグ倍率を `(1+物理) × (1+魔術) × (1+遺物)` と定義し、テストケース2 でも
物理技に対して3系統すべての補正が乗っています。一方 §4 は damage_type を
「どの系統タグの補正が乗るか」と説明しており、フィルタとして読めます。
テストケース2 が数値で確定している以上、**補正は原則すべて乗る**方を採用しました。
そのうえで、アフィックスに `match_type` を持たせ、
「[物理]系統(物理技限定)」のようにダメージタイプ一致時だけ乗る補正も表現できるようにしています。
§4 のあべこべビルド（ATK参照×[魔術]系統など）はこの仕組みで成立します。

**§10.1 の「最終ウェーブ＝ボス」と単発戦闘**

設計書は連戦を 5戦 / 10戦 としており、最終ウェーブがボスになります。この規則をそのまま
1戦モードに当てはめると、単発で出撃した瞬間にボス戦になってしまい、序盤の腕試しができません。
そこで `data/fields.js` の `waveModes` に `bossFinale` を持たせ、1戦モードだけボスを出さない
通常戦闘としています。5戦・10戦は設計書どおりボスで締めます。

**§5.4 「全属性適応」の中間レベル**

設計書は Lv1（不利を等倍に無効化）と LvMax（全攻撃を有利1.5倍化）だけを定義しています。
中間段階の指定がないため、最大レベルを2として Lv1/Lv2 がそのまま両者に対応するようにしました。
