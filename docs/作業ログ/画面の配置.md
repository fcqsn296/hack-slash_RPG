# 画面の配置を作り直す（PC 3ペイン／スマホの横パネル）

ブランチ `work/画面の配置を作り直す`。A→B→C→D の順で入れた。**全部済み。**

## 発端

依頼側の提案——「PCは3ペインにすればスッキリする」「スマホはスワイプで
横からパネルを引き出す形が操作しやすい」。工数を見積もるために実測したら、
**提案が効く場所と、ペインでは直らない場所**が分かれた。

測定は実データのセーブ（所持装備 2,205個）を localhost に読み込んで行った。

## 測る前に分かっていなかったこと

3画面（ビルド・装備・鍛冶）は既に `pane-split` で2カラムになっていた。
ただし**カラムがペインになっていなかった**——1つの文書を2列に流しているだけで、
独立してスクロールしない。左のキャラ一覧がそのまま文書の高さを決めていた。

| 画面 | PC(1512幅) | スマホ(375幅) |
|---|---:|---:|
| ビルド | 4,930px | 2,901px |
| 装備 | **14,024px** | **39,546px（48.7画面）** |
| 鍛冶 | 1,237px | — |

`#app` が `max-width: 1180px` で頭打ちのため、1512px 幅では 332px（22%）が余っていた。

## A: 列を独立してスクロールさせる

列に `max-height` と `overflow-y` を与え、`position: sticky` で貼り付けた。
sticky にしたのは、860px 以下（1列に落ちる幅）で**この指定ごと無効化**したいため。

高さは「画面 − 上部バー − タブバー」。どちらも中身と端末で変わるので
実測値を CSS 変数で受け取る。`--topbar-h` は既にあったので `--rail-h` を足した。

- ビルド 4,930px → **950px**（＝画面ちょうど）
- 装備 14,024px → **950px**

タブバーぶんの余白が `#app`(60px) と `.base-body`(76px) の**二重**にあり、
そのままだと 69px の無意味なスクロールが残ったので分割画面だけ解除した。

## B: 所持装備の一覧にページ送りと行表示

**一覧が飾りになっていた。** 「上位120個」で打ち切っていて、
121個目以降には到達できない。2,205個持っていても絞り込みでしか届かない。

ページ送りに変えた（1ページ60個・37ページ。最終ページ 2161〜2205 まで確認）。

ただし**ページ分割だけでは縦は減らない**。カードは中身（ステータスと
副オプション）で高さが決まり、1枚が約290pxある。行に落とせるようにした。
行は名前・部位・スコア・所有者だけ。中身はカードへ戻せば見られる。
既定は画面幅で決める（860px未満なら行から）。

| 装備タブの縦 | 前 | 後 |
|---|---:|---:|
| PC・右列の中身 | 10,832px | 6,421px（カード）/ 6,001px（行） |
| スマホ | 39,546px | **11,813px**（行）/ 22,175px（カード） |
| DOM要素数 | 9,253 | 6,926（カード）/ **3,638**（行） |

## C: 3ペイン

左＝誰を、中＝操作するもの、右＝見ながら確かめるもの。

| | 中 | 右 |
|---|---|---|
| ビルド | クラス・技順・スキルツリー | 頭・レベル上げ・固有・残りSP・要約・ダメージ内訳 |
| 装備 | 所持装備（見出し・絞り込み・一覧） | キャラ詳細・プリセット・装備枠・自動売却 |

所持装備を中央（広い側）に置いたのは、カード表示が横に並ぶ幅を要るため。
着ている側は行の集まりなので狭い列でも読める。

**幅で3段階に畳む。**

| 幅 | 形 |
|---|---|
| 1200px以上 | 3ペイン（`.col-main` の子がそれぞれスクロール） |
| 861〜1199 | 2ペイン（中と右が `.col-main` の中に積まれ、器がスクロール） |
| 860px以下 | 1列（従来どおり文書がスクロール） |

1200px を境にしたのは、1100px で3列にすると中央が 300px を割り、
装備カード（最小240px）が1列になって分けた意味が無くなるため。実測で決めた。

狭い画面では `order: -1` で中と右の順番を入れ替える。3ペインのために中央へ
移したものは、もともと画面の下のほうにあったから。これを入れないと
スマホで「いきなり所持装備2205個の一覧から始まる」。

ビルドは中身が中702px列に 1,014px、右420px列に 925px。**ほぼ1画面に収まり、
ツリーを触りながら要約を見るのに画面の上まで戻る必要がなくなった。**

## D: スマホの横パネルと左端スワイプ

これまでは畳んだ中身をその場で開いていた（`display` の切り替え）。
開いた瞬間に下の内容が 1,000px 以上押し下がるので、
「選ぶ → 閉じる → さっき見ていた場所を探し直す」になっていた。

板（`position: fixed` で左から滑り込む）にすると下の内容が動かない。
**開く前も開いた後もページ全長 2,937px のまま。**

`installEdgeSwipe()` を document に1度だけ付ける。860px以下で、
キャラ一覧を持つ画面のときだけ働く。

**縦スクロールを邪魔しないことが要点。** 12px 動くまで向きを決めず、
縦のほうが大きければその指は捨てる。合成タッチで4通り確認した:

| 操作 | 結果 |
|---|---|
| 端(x=8)から右へ払う | 開く |
| 開いた状態で左へ払う | 閉じる |
| 端から縦に払う | 開かない |
| 画面中央から右へ払う | 開かない |

PC(1512px)では同じ操作で開かず、一覧は `position: static` のまま常に見えている。

端の判定は 28px（広げると一覧の中で横に払う操作まで拾う）。
途中経過は追わず、しきい値(60px)を越えた時点で開閉する。
板の動きは CSS の transition が受け持つ（`prefers-reduced-motion` では切る）。

## 残っていること

- **鍛冶は2ペインのまま。** 3つ目に置くものが無い。A の独立スクロールは効いている
- **スマホの行は 125px ある。** 560px以下で装備/ロック/売却の3ボタンが別行へ
  折り返すため（44pxの押しやすさを確保しているぶん）。
  行を叩いて選んだものにだけ操作を出す形にすれば半分になるが、
  操作の作法を変えることになるので手を付けていない
- **検証テストに既知の不合格が1〜3件**（「闘技場: 虹を喰らう獣 が決着する」）。
  今回の作業とは無関係で、`stat_cost` 移行前のコミット b2267bf でも同じように
  落ちることを確認済み。有利属性を回復として吸収するボスに対し、オートが
  有利属性で殴り続けて膠着する。別途対応
