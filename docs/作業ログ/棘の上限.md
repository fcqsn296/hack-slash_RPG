# 棘の上限を 30 → 300 へ

## 何が起きていたか

棘は「相手の最大HP × 率」で、相手のHPが伸びるほど自動で強くなる作りだった。
頭は `THORNS_CAP_RATIO`（自分の最大HPの何倍まで）で押さえてあったが、
**その倍率が小さすぎて、桁違いの相手ではまったく機能していなかった。**

闘技場の主（ハード・HP 2億）での実測。

| | |
|---|---:|
| 素の棘（2億 × 0.29） | 58,000,000/発 |
| 上限 30（26,533 × 30） | 795,990/発 |
| **削られていた倍率** | **185倍** |

4人パーティで 1.8M/ラウンド、200Mを削るのに **111ラウンド**。暴走は18ラウンド。
つまり棘という軸は、闘技場では存在しないのと同じだった。

## なぜ 300 か

**狙われやすさを限界まで積んだ4人編成**で測った値。単騎で測ると3倍ずれる。

| 上限 | 毎ラウンド | 200Mに必要 |
|---:|---:|---:|
| 30（旧） | 1.8M | 111R |
| **300** | **22.2M** | **9R** |
| 1000 | 74M | 3R |

中技型・小技多段型（どちらも 22.2M / 9R）と**ちょうど同値**になる位置。
大技型(28.6M / 7R)には及ばず、状態異常特化(100M / 2R)には遠い。
「殴られ役が片手間に出す火力」としてその位置に置いた。

1000 にしなかったのは、前回の提案が**単騎・狙われやすさ無し**の数字だったため。
狙われやすさを積むと2.78倍になるので、1000だと状態異常に迫ってしまう。

## 通常フィールドには影響しない

通常の敵はHP 14万程度なので、素の棘は 140,000 × 0.29 = 40,600/発。
旧上限（30倍 ≒ 60万）にも届いていなかったので、**上限を緩めても1も動かない**。
効くのは桁違いの相手のときだけ、という設計はそのまま。

## 覚えておくべき噛み合わせ

- **狙われやすさは THREAT_MAX = 4 で頭打ち。** 4人編成でボスの攻撃の
  4/(4+1+1+1) = 57% までしか集められない。実測 2.78発/ラウンド（ボスは5回動く）。
  **上限を決めるときは必ずこの倍率込みで測ること**
- **軽減を積みすぎると棘が死ぬ。** 棘は「ダメージを受けたとき」に出るので、
  軽減100%だと**1発も出ない**（実測で発動0回）。耐久と火力が正面から食い合う軸。
  最適点はおそらく50〜70%
- **「庇う」では棘が出ない。** 肩代わりは `guard.hp` を直接引く実装で、
  棘・反射・障壁・軽減のどれも通らない。前に出る手段は狙われやすさだけ
- **棘と反射は取り巻きの守り(guardedByAdds)を貫通する。** あの判定は
  `applyDamage` にしか無く、棘・反射は `hurt()` を直接呼ぶため。
  実測で、取り巻きを一度も倒さずにボスを削り切れた

## 反射は触っていない

`REFLECT_LEVEL_RATE` は正しく適用されていた（Lv255 で ×26.5）。
効いていない原因は `REFLECT_CAP_RATIO = 40`（主人公で 417,240/発、2.09M/ラウンド）で、
コメントに「緩和前をそのまま返すと1発13.8Mになり、反射だけで闘技場が終わる」と
理由が書かれている。**意図して厳しく置かれているので据え置いた。**
