# 棘に上限を設ける

**ブランチ**: `work/thorns-cap`
**日付**: 2026-08-25

## きっかけ: 闘技場のHP見積もりを9倍間違えていた

反射の調査中、闘技場ボスのHPを 4,760,600 と見積もっていたが、**実際は 39,981,600**。
利用者から実機の画面を示されて発覚した。

掛け忘れが2つあった。

```
正しい式: statsAtLevel(def, 255) × (scale × HARD_SCALE) × bossStatMultiplier
                                          ~~~~~~~~~~~~     ~~~~~~~~~~~~~~~~~~
                                          =6 を忘れた       =1.5 を忘れた
```

| ボス | ハードHP |
|---|---|
| 無貌の簒奪者 | 42,845,400 |
| 三重の守護者 | 42,574,032 |
| 終刻の審判者 | **39,981,600** |
| 闘技場の主 | 15,552,000 |
| 千葬の守り手 | 13,264,290 |

味方HP 35,724 に対して **370〜1,200倍**。「20〜133倍」と報告したのは誤りだった。

## 正しい数字で測ると、問題は反射ではなく棘だった

棘は `attacker.maxHp × 率` の割合ダメージで、**上限が無かった**。

```
39,981,600 × 0.29 = 11,594,664   ← 棘1発
3.5回被弾するだけでボスを削り切る。しかも13SP。
```

闘技場ハードでの実測（修正前）:

| 構成 | 勝率 | 貢献 | ボスHP比 |
|---|---|---|---|
| **棘** | **50%** | 40,581,324 | **101.5%** |
| 反射(×0.1) | 0% | 820,437 | 2.1% |
| 同SPを火力へ | 0% | — | — |

## ただし「棘でしか勝てない」ではなかった

利用者の実セーブで確認したところ、**主人公＋破鎧撃持ちの2人で完走できる**。

| 構成 | 勝率 | 最大で削れた量 |
|---|---|---|
| 実主人公＋ゼロ（破鎧撃）2人 | 11% | 39,981,600（完走） |
| 実セーブのパーティ4人 | 67% | 39,981,600 |
| 検証台の2人 | 0% | 1,210,267 |

検証台の自動生成キャラは実物の 1/33 しか出せない。
「アタッカーは勝率0%」と報告したのは**測る相手が弱すぎた**だけだった。

正しくは「**棘を積めば弱いキャラでも勝てる**」。13SPで被弾3.5回という対価の軽さが問題。

## 入れたもの

率は割合のまま（インフレ耐性を残す）で、**1発の頭だけを自分のスケールで押さえる**。

```js
const THORNS_CAP_RATIO = 30;   // 自分の最大HPの30倍まで
const cap = defender.maxHp * THORNS_CAP_RATIO;
const back = Math.min(attacker.maxHp * thorns, cap);
```

### 効き

| | 修正前 | 修正後(×30) |
|---|---|---|
| 闘技場 棘1発 | 11,594,664 | 860,640 |
| 闘技場 ボスHP比 | 101.5% | **8.0%** |

**通常フィールドには一切当たっていない。**

| 場 | 棘合計 | 敵HP比 | 上限に当たった回数 |
|---|---|---|---|
| fl_origin | 136,100 | 7.1% | **0** |
| fl_endless | 318,047 | 11.7% | **0** |

数値は修正前と完全に同じ。効くのは桁違いの相手のときだけ。

### 倍率の選定

| 倍率 | 闘技場での棘 |
|---|---|
| ×20 | 5.3% |
| **×30（採用）** | **8.0%** |
| ×40 | 約11% |

通常フィールドの棘が 7〜11% なので、×30 でほぼ同水準に揃う。
「割合ダメージは強い相手ほど効く」性質もわずかに残る。

検証テスト 1210/1210。

## 反射も闘技場水準へ (§5.19)

棘に上限を入れた時点で、闘技場での貢献は 棘 8.0% 対 反射 2.3% だった。
反射側も引き上げる。

### 原因は「緩和後」を返していたこと

闘技場には `maxHitRatio`（1発が自分の最大HPの何割まで）という
**プレイヤーを一撃死から守る緩和**がある。反射はその**削られた後**を返していた。

```
ボスの一撃(緩和前)  675,932
緩和後              12,192   ← タンクHP 28,688 × 0.425
                    55.4倍削られている
```

さらにタンクは3回殴られただけで倒れる（1発が最大HPの42.5%なので2.4発で死ぬ）。
回数も量も足りない状態だった。

### 入れたもの

`maxHitRatio` で削る前の値を `result.preMercyDamage` に控え、反射はそちらを使う。
そのままだと1発13.8Mになるので、棘と同じ考え方で自分のHPスケールで頭を押さえる。

```js
const REFLECT_CAP_RATIO = 40;   // 棘は 30
const weight = result.preMercyDamage || result.damage;
const back = Math.min(weight * reflect * scale, defender.maxHp * REFLECT_CAP_RATIO);
```

**棘(×30)より高くしてあるのは、反射の性格を闘技場でも残すため。**
同じ倍率にすると両方とも上限に張り付いて**まったく同じ数字**になり、
「重い一撃に強い」という差が消える（実際に×30で試して同値になった）。

### 効き

| | 闘技場ハード | fl_origin | fl_endless |
|---|---|---|---|
| 反射 | **10.6%**（修正前 2.3%） | 2.3% | 29.4% |
| 棘 | 8.0% | 7.1% | 11.7% |

**通常フィールドの反射は1ダメージも変わっていない。**
`maxHitRatio` は闘技場だけの仕組みなので、通常戦闘では `preMercyDamage` が発生しない。

性格の違いも残った。反射は重い一撃の相手（fl_endless 29.4% / 闘技場 10.6%）に強く、
棘は回数と敵HPで安定して効く（7〜12%）。

検証テスト 1208/1208。
