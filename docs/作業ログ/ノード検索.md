# ビルド画面のノード検索

## 不具合: スマートフォンで検索が打てない

**原因は絞り込みの実装。** キーを叩くたびに `.tree-browser` を丸ごと作り直し、
そのあと `input.focus()` でフォーカスを当て直していた。

```js
// 直す前
oninput: (e) => {
  treeQuery = e.target.value;
  const next = treeBrowser(root, charSave);
  host.parentNode.replaceChild(next, host);   // ← 入力中の要素が消える
  input.focus();                               // ← 当て直しても間に合わない
}
```

PCでは辛うじて動く。スマートフォンでは、入力中の要素が消えるたびに

- IME の**変換中の文字が失われる**（日本語だと一文字も確定できない）
- ソフトキーボードが閉じる

ため、実質まったく打てない。

**検索欄そのものには触らず、結果の枝だけを差し替える形に変えた。**
入れ物（`.tree-results` / `.tree-cats`）を先に作っておき、`replace()` で中身だけ入れ替える。
`input` 要素は一度も作り直されないので、当て直しも要らない。

同じ罠は `charSelector` の検索欄では既に避けてあり
（「検索欄だけは作り直さない」というコメントが残っている）、
ツリー側だけが取りこぼしていた。他に同じ形の入力欄は無い。

## 軸で探せるようにする

「クリティカル率で完成するツリーを見たい」ができなかった。

- ノードの説明文は「会心するたび」「会心の追撃」としか書いていない
- 効果種別 `crit` / `crit_damage` には登録簿の `label` が**無い**（`route` が `unit`）
- ティアを跨いで見る手段が無く、軸の端から端までが一度に見られない

### terms（言い換え語）

`data/nodeCategories` に `terms` を足した。分類に属するノードは、
名前や説明文にその語が無くても、この語で引ける。

ノード側には**何も書かせない**。分類は効果種別から自動で決まるので、
ノードを足せば言い換え語も自動でつく。既存の設計（分類をノードに書かせない）と同じ考え方。

`RPG.tree.searchText(node)` が「名前 + 説明 + 分類名 + 言い換え語 + 効果種別の表示名」を
繋げた文字列を返す。検索はこれ1本にかける。

### 軸のチップ

- 分類を**件数つきのチップ**で並べ、押すとその軸だけに絞る
- ノードの札にも分類を出し、**押すとその軸に絞る**
  （「これと同じ系統を全部見たい」が、名前を思い出さなくてもできる）
- ティアに「すべて」を足した。会心なら初級〜上級の15枚が1画面に並ぶ
- 絞り込んでいるあいだは分類を畳まない（畳んだままだと結果が見えない）

札が増えるので、**属性戦略・生存の札は外した**。分類チップと同じことを言っており、
狭い画面では同じ意味の札が2枚並ぶと本文が押し出される。装備枠とアクティブ技は残した
（分類では言えない情報のため）。
