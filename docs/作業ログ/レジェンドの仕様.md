# レジェンドの仕様を「両方持つ」に固める

## 見つかったこと

セレナとカグラに固有パッシブが無い、という指摘を受けて点検した。
**パッシブは実装されていた。** 無かったのは `desc` のほうだった。

  セレナ  situational: { weakGuard: 0.35 }
  カグラ  passives: { statusOnHitKind: { burn: 0.30 } }

固有能力は**ビルド画面の「固有」欄に `desc` を出すことでしか伝わらない**。
書き忘れると、正しく実装されていてもプレイヤーからは「無い」のと同じになる。
**その状態で公開していた。**

全レジェンド37体を機械的に点検したところ、`desc` が無いのはこの2体だけで、
固有パッシブと固有技はすべて揃っていた。

## 直したこと

2体に `desc` を足した。

  セレナ 【特殊】弱点を突かれたときの被ダメージ-35%。纏った風が不利属性の
        一撃を受け流す。味方全体の被ダメージ軽減と合わせて、崩れない前線を作る。
  カグラ 【特殊】攻撃するたびに30%で火傷を付与する。舞うほど相手が焼ける。
        火傷中の敵への火力を持つルーナと組ませると噛み合う。

## 仕様にした

検査を **「どちらか一方」から「両方 + desc」** へ変えた。

| | 何を書くか |
|---|---|
| 固有パッシブ | `passives` / `situational` / `elementMods` のどれか |
| 固有技 | `unique_skills` に1本以上 |
| `desc` | 固有能力を1〜2文で |

以前の「どちらか一方」だと、固有技しか持たないレジェンドが生まれても
素通りし、**他のレジェンドと同じ枠に並ぶのに常時効く能力だけが無い**
という状態が作れてしまう。実際そうなりかけた。

併せて「固有技のIDが実在する」検査も足した。IDを書き間違えても
上の検査だけは通ってしまうため。

`docs/拡張コンテンツの作り方.md` にも節を足した。
他のエージェントはあの文書だけを読んで作業する前提なので、
検査だけ厳しくして文書に書かないと「書いたのに弾かれる」ことになる。

検証テスト 1238/1238。37体すべてが3つとも揃っている。
