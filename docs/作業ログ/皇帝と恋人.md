## 皇帝 IV

> 利: 自分の手番を、味方1人の即時行動に置き換える
> 害: 命令できる味方がいる間、自分の技は使えない
> 解放: 座して統べる（主人公を一度も行動させずに5ウェーブ）

### 実装の芯 — `commandSkill` を3つに割った

1つの関数が9つの仕事を抱えていた。皇帝は**実行と手番の終わりを別人で回す**ので、そこを割った。

```
command(battle, cmd, opts)
  ├ skill  → performAction(本人)   → finishTurn(本人)
  └ decree → performAction(受け手) → finishTurn(皇帝)
```

| 仕事 | 持ち主 |
|---|---|
| `skillReady` / `startCooldown` / `executeSkill` / 魔術師の配り / 死の刻み | **受け手** |
| 麻痺の判定・制圧の判定・再行動の連鎖・順番送り | **皇帝** |

`commandSkill` は入口として残したので、既存の呼び出し8か所は無改修。
**割っただけの段階で既存テスト1599件が全部通ることを確認してから**機能を足した
（挙動を変えていない証明）。

@知見: 手番の持ち主と技を使う者が別になる札は、まず実行と手番終了を割ってから作る

### 順番を保つこと

`startCooldown` が麻痺判定より**前**にあるのは意図的な作り (§5.8)。
麻痺で飛んでもクールダウンは進むので、大技を抱えた相手ほど損が大きい。
割るときにここを入れ替えてはいけない。

### 命令状態はセーブにもUI状態にもしない

`battle.decree` が生きているのは `command()` の中の**同期実行の一瞬だけ**。
手動の選択（命令先 → 技 → 対象）はUI側が溜め込み、揃ってから `commandDecree` を1回呼ぶ。
だから `skipDeadActors` も敵フェーズも描画もこれを跨がない。

### 手番が戻る輪を作らない — 止め所は3つだった

**生んでから取り消すのではなく、生む前に止める。**
取り消す形にすると、受け手の残り回数や取得済みの権利を巻き戻すことになる。

| 場所 | 何 | 対応 |
|---|---|---|
| `battle.js` 撃破の再行動 | 連鎖する死 | `battle.decree` があるとき発火させない |
| `battle.js` コンボの再行動 | 段の出口 | 同上 |
| `skillReady` | 号令・前借り・蘇生+行動 | **技ごと選ばせない**（`grantsTurn`） |

手番を生む技は `plugin` で見分ける（`mass_extra` / `borrow_turn` / `mass_revive` の `actNow`）。
データ側に旗を足す形にしなかったのは、新しい技を書く人が忘れた瞬間に輪が開くから。

@知見: 禁止は `skillReady` に入れる。オートは `skillReady` で候補を絞るので自動的に従う

逆に言えば、`skillReady` の外に禁止を書くとオートだけ素通りする。

確かめ方: 受け手に `killExtraAction = 1`（倒したら必ず再行動）と
`extraActionRate = 1`（手番の終わりに必ず再行動）を持たせ、命令で3体倒させた。
`extraActions` も `pendingExtra` も `grantedExtra` も動かなかった。

### 初回測定（終わりなき回廊 HP×300・20試行）

並び順は 主人公・アストラ・ルーメン・ミレーヌ。

| | 勝率 | 勝ったときR | 勅命 | 渡した先 |
|---|---|---|---|---|
| 皇帝なし | 100% | **5.1** | — | — |
| 皇帝＝主人公（担ぎ手） | 100% | **19.4** | 37.4回 | アストラ 748 |
| 皇帝＝ミレーヌ（支援） | 100% | 5.2 | 3.3回 | eretoto 66 |
| 皇帝＝ルーメン | 100% | 5.0 | 2.1回 | eretoto 43 |

**担ぎ手に着けると壊滅する**（5.1R → 19.4R）。本人が一切殴らなくなるので当然で、
**この札は支援役が着けるもの**だとはっきり出ている。

闘技場ハードでは 皇帝なし 100%/4.1R に対し 皇帝＝ミレーヌ 95%/4.8R。

### まだ利が出ていない

仕様書の採否条件「主力へ渡す利益が高難度で現れる」は**まだ確認できていない**。
HP×1000 / ×3000 でも 皇帝なし 5.3R / 6.6R に対し 皇帝＝ミレーヌ 5.8R / 7.0R で、
わずかに遅い。理由は**1ウェーブ1ラウンドの床**——手番を誰に渡しても、
ウェーブが1ラウンドで終わるなら結果が変わらない。

床から離れる土俵（闘技場ハードで敵を倒せなくする等）での測定が要る。
数値の採否はそこで決める。

### オートは編成の並び順で選ぶ

誰に渡すのが得かを考える仕組みは入れていない（オートの判断を増やすと、
どの札のせいで結果が変わったのか読めなくなる）。
渡す相手だけ中核が決め、**撃つ技は受け手の既存の判断**に任せる。

その結果、**皇帝が先頭にいると次席に渡し、後ろにいると担ぎ手に渡す**という
並び順への強い依存が出ている。上の表の差はほぼこれで説明できる。

### 皇帝は複数いてよい

他の皇帝へは命令できないので、皇帝どうしで回し合う形は生まれない。
3人が1人へ集中する編成は組めるが、**渡す側は柔軟な行動を丸ごと失う**
——バフ・デバフ・回復・蘇生・固有の再行動技が全部使えなくなる。

## 恋人 VI

> 利: 同じ札を持つ味方1人につき、火力が大きく上がる（+45%）
> 害: 受けた被害を、同じ札を持つ味方と分け合う（30%）
> 解放: 二人の誓い（二人だけで、どちらも倒れずに5ウェーブ）

### 編成そのものを賭ける軸

既存の札は全部「1人の中で完結する」取引だった。これは**編成を賭ける**。
1人で持っても何も起きない。

| 恋人の人数 | `setPower` |
|---|---|
| 1人 | ×1.00（何も起きない） |
| 2人 | ×1.45 |
| 3人 | ×1.90 |
| 4人 | ×2.35 |

### なぜ「倒れたら自分も倒れる」にしなかったか

味方が倒れる頻度は実測で **周回 0.00人／相つき 0.25人／闘技場 3.00人**。
連鎖死にすると「まったく効かない」か「全滅」かの二択になり、中間が無い。
これは死の設計で捨てた「殴られると弱い＝高難度と相性が悪い」と同じ形。

**分配なら目盛りが連続になる。** 総量は変わらず散るので、
「誰かを守る」戦術が効かなくなる代わり、集中砲火では落ちにくくなる。

### 戦車とは噛み合わない

分配は `ward_null` で無効になる。戦車は痛みを分け合えない——
**守りを捨てた者は、他人の痛みも引き受けられない**、という形で規則が揃っている。
既存の `damage_share`（守護者が 0.35 で持つ）と同じ場所・同じ作りにしてあるため、
この性質は自動的に揃った。

### 実装で要ったもの

`unit.arcanaId` をユニットに持たせた。**効果の合流だけでは札そのものを見分けられない**
（同じ効果種を別の札が持ちうる）ので、IDを別に持つ必要がある。

## 実装で踏んだ罠

- **`setPower` の `p` は途中で宣言される。** 前半（`fx` の区画）に `p.bondPower` を
  書いて `Cannot access 'p' before initialization` で落ちた。`p.` を使う区画へ置くこと
- **`RPG.rng` に `random` は無い。** API は `next / float / int / chance / pick / weighted` で、
  `float` は範囲を取る（引数なしは NaN）。両方で一度ずつ落ちた
- **検査で `mk()` を2回呼ぶと別の戦闘が2つできる。** 片方の味方をもう片方の絆として
  数えてしまい、「1人では何も起きない」が 1.45 になった。1つの戦闘から取ること
- **オートが返す行動の形が変わる。** 皇帝は `{ decreeTo, skillId, targets }` を返すので、
  `commandSkill` を直に叩いている呼び出し側は命令が素通りする。
  共通の実行口 `RPG.battle.perform(battle, action, opts)` を用意して、
  UI・dispatch・sim・balance・builds・tests の**計25か所**をそこへ繋いだ

@知見: オートの返り値の形を増やしたら、直呼びしている箇所を全部共通の実行口へ繋ぎ直す
