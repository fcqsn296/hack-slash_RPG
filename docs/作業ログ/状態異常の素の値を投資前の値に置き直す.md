# 状態異常の素の値を「投資前の値」に置き直す

## 何が壊れていたか

`STATUS_CAP` を常用域まで下げたのが誤りだった。上限 0.06 に対して
疫病の坩堝の素が 0.10 で、**0SP + クラス点4 で上限に当たっていた**。

実測（闘技場の主ハード / 200M / 耐久を切り離す）:

| 構成 | 消費SP | クラス点 | 決着 |
|---|---:|---:|---:|
| 火傷・最小（坩堝を取るだけ） | 0 | 4 | 5R |
| 全部盛り | 134 | 48 | 5R |
| 主人公の攻撃ツリー | 241 | — | 7R |

投資が1点も結果に出ず、**耐久に全振りして毒と火傷を撒くのが最適解**になっていた。

## どう直したか

上限で押さえるのをやめ、**素の値を「何も振っていないときの値」に取り直した。**
全部振ったところ（statusPower 3.7 → ×4.7）が狙いの強さになる。

```
毒   素0.015 → 全振り0.070（上限0.10）  1回/ラウンド → 7%/R
火傷 素0.005 → 全振り0.024（上限0.035） 闘技場3回/R  → 7%/R
                                        合計 14%/R
```

上限はそのさらに上、実際の構成では当たらない位置に置いた。**安全弁であって
調整つまみではない。**

### 一度外した：片方だけ見て倍にした

最初 毒0.03 / 火傷0.01 で置いたら 4〜5R になった。毒と火傷は**足し合わさる**ので、
毒だけ見て 14%/R に合わせると合計28%/R になる。半分にして合った。

### 火傷はスキルの params だけでは動かない

素の値を縮めても火傷が 0.047 のまま動かず、原因を探ったら
`STATUS_ON_HIT_RATIO.burn`（パッシブ `statusOnHitKind` の既定値）から来ていた。
**削る異常の値は skills.js と battle.js の両方にある。**

### ratio が削る異常と制御の異常を兼ねていた

`ratio` の意味は種類ごとに違う。毒・火傷は「最大HPの何割」だが、
呪詛は「回復を何割塞ぐか」、麻痺は「何割の確率で動けなくなるか」。

呪縛の福音は回復封じ60%が欲しくて `ratio: 0.60` を置いていたが、
**同時に撒く毒まで60%**になっていた（上限で隠れていた）。
`status` プラグインに `ratios: { poison: 0.015 }` の上書き表を足して分けた。

## 実測（闘技場の主ハード / 200M / 耐久を切り離す・中央値）

| 構成 | 決着 |
|---|---:|
| 状態異常 専業（134SP+48点） | **7R** |
| 攻撃型のみ（241SP） | **8R** |
| 攻撃型＋毒牙をつまみ食い | **9R** |
| ルーナ無投資（技だけ4点） | 13R |

**つまみ食いは損になった。** 撒くのに1手番使うぶん、攻撃だけ続けるより遅い。

## HPを変えたとき

| ボスHP | 状態異常 | 攻撃型 |
|---:|---:|---:|
| 10M | 4R | 3R |
| 50M | 7R | 3R |
| 200M | 7R | 7R |
| 400M | 7R | 15R |

状態異常は割合なので**ラウンド数がHPに依らない**。低HP帯では攻撃型が速く、
200Mで並び、その上では状態異常が答えになる。役割が分かれた形で落ち着いた。

ボスHPの上限は 500M までに保つこと（そこで攻撃型が20ラウンド弱）。
