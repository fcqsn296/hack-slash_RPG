# レベルを決め直せるようにする（検証・縛りプレイ用）

## なぜ

闘技場の突破を「証明」しようとしても、**主人公だけ255で仲間が70**では
何を確かめたことになるのか分からない。編成のレベルを揃えられないと、
実測そのものが成立しない。縛りプレイの入口にもなる。

（実際、以前このセーブで闘技場ノーマルの突破を確認したときも、
主人公255／仲間70という編成だった）

## 設計: 到達点までは無料で行き来できる

`c.peak` に**今までに到達した最高レベル**を記録し、その範囲では無料で上下する。

- **無制限にすると**、ゴールドで買う仕組みが意味を失う
- **一方通行にすると**、検証のたびに買い直すことになる

一度自分で登った高さの中でだけ自由、という線に置いた。
到達点より上へは、これまでどおり経験値かゴールドが要る。

`peak` は `addExp` と `buyLevels` の両方で伸ばす。
旧セーブには無いので、`migrate` で「今のレベル＝到達点」とみなす。
新規作成の初期形にも `peak: 1` を置いた（移行だけで補うと、
作った形と読んだ形がずれる — §7）。

## 下げるときに起きること

### 消費SPが配られるSPを追い越す

Lv120で15SP消費している状態からLv15へ下げると、配られるSPは14しかない。
**黙って壊れた状態にしない。** 呼び出し側へ `needsReset` を返して確認させ、
了承されたときだけツリーとクラスツリーを戻す。

### 装備枠が減る

装備枠をレベルで配る形にしたとき、「レベルは下がらないので枠も減らない」
と書いた。**その前提がここで崩れる。** `afterTreeShrink` を通して、
はみ出した装備を外している。

実測: Lv120（武器2枠・2本装備）→ Lv8（武器1枠）で、装備が1本に戻った。

### 解禁が閉じる

塔・鍛冶・闘技場は主人公のレベルで見ているので、下げれば閉じる。
縛りプレイでは望ましい挙動なので、そのままにしてある。
クラスは就任済みなら締め出さない（`canTakeClass` が先に true を返す）。

## 画面

ビルド画面のレベル欄に、買う側とは点線で区切って置いた。

  -10 / -1 / Lv1 / 到達点 Lv◯◯

今のレベルと同じになるボタンは出さない。Lv120（到達点120）なら
「到達点」ボタンは消え、下げると現れる。
