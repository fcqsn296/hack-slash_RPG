# 手動戦闘の演出を足す

## 何が足りていなかったか

演出の土台は既にあった（浮かぶ数字・カードの明滅・ウェーブのバナー、
高速モードで間隔を詰める仕組みまで）。足りなかったのは3つ。

| | 前 | 後 |
|---|---|---|
| 何で殴ったか | **弱点のときだけ数字の色が変わる**。炎でも闇でも同じ見た目 | 属性色で爆ぜる |
| 何を撃ったか | ログに1行出るだけ。目はカードを見ているので届かない | 技名を短く提示 |
| どれだけ重いか | 数字を読むまで分からない | 重い一撃だけ画面が揺れる |

## オートと高速では出さない

判断は `src/ui/battle.js` の `rich()` が持つ。`!auto && !fast` のときだけ濃くする。

演出は「1回の戦闘を見せる」ためのもので、周回では邪魔にしかならない。
**ストーリーと闘技場は手動で1戦ずつ戦う場所**なので、そこだけ濃くする。
新しい設定は増やしていない。既にある2つに相乗りさせた。

実測（同じ一撃を3条件で）。

| | 爆ぜ | 技名 | 揺れ | 浮かぶ数字 |
|---|---:|---:|---:|---:|
| 手動・通常速度 | 1 | 1 | 8 | 3 |
| 手動・高速 | 0 | 0 | 0 | 3 |
| オート | 0 | 0 | 0 | 19 |

## 属性は「倍率」しか届いていなかった

`damage` イベントの `element` は**相性の倍率**（0.5 / 1 / 1.5）で、
炎か闇かは入っていない。だから画面側は弱点かどうかしか描けなかった。

イベントに3つ足した。

- `elem` … 技の属性名。色に使う
- `kind` … `phys` / `magi` / `reli`。形に使う
- `weight` … 相手の最大HPに対する割合。揺れの強さに使う

**生の数値ではなく割合にしてある。** 数値で決めると桁が変わる終盤しか揺れない。

## 見た目の作り

系統で形を分けた。属性ごとのクラスは並べていない——属性が増えるたびに
CSSとJSの二重管理になるので、色は `--fx` にJS側から差し込む
（`src/ui/widgets.js` の `ELEMENT_COLOR` を再利用）。

| 系統 | 形 |
|---|---|
| 物理 | 縦に裂ける（`border-radius: 46% 54% 50% 50% / 8% 8% 92% 92%`） |
| 魔術 | 丸く広がる |
| 理 | 背景を持たず、光の輪で締める |

揺れは**重い一撃だけ**。毎回揺らすと重さの差が伝わらなくなる。
会心か、相手の最大HPの12%以上を持っていったときだけ。

`prefers-reduced-motion` では**揺れだけ完全に止める**（他は0.01msに短縮）。
酔いに直結するので、短くするのでは足りない。

## 測った値

- 検証テスト 1355 / 1355
- 追加した検査4件: イベントに `elem` / `kind` / `weight` が乗ること、
  行動イベントに技名と属性が乗ること
- 見た目は実機で確認（4属性×3系統で色・形・アニメが解決されることを計算値で確認）

## 次に触るときに

**イベントに乗せた項目は、消えても静かに無視されるだけ**で誰も気付かない。
検査で固定してあるので、落ちたら「テストが厳しい」ではなく
**画面から演出が消えた**と読むこと。
