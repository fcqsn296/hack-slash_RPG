# スマホの戦闘配置（コマンドが下すぎて演出が見えない）

**ブランチ**: `work/スマホの戦闘配置`
**開始**: 2026-09-12

## 報告

> スマホ版の配置だとコマンドを選ぶ場所が下過ぎて、演出が表示される場所が見えません
> （演出自体はコマンドを選んで急いでスクロールすれば見える）

## 測って分かったこと（375×640）

| 要素 | 高さ |
|---|---|
| 上部バー | 134 |
| 戦闘の見出し | **157** |
| コンボ | 30 |
| 敵の行 | 251 |
| ログ | **190** |
| 味方の行 | 124 |
| コマンド | **816**（技8本 × 82px） |

**コマンドを全部出すには 750px スクロールが必要で、そのとき敵の行は -583〜-332。**
画面の外どころか、583px 上にある。報告のとおり。

### 同時には入らない

```
640 − 見出し119 − コンボ30 − 敵251 − 味方124 = 116px
```

**敵を見せたまま技の一覧を出す余地は116pxしかない**（技1.5本ぶん）。
配置を工夫して収める問題ではなかった。

## 直した4つ

### 1. 見出しが縦に潰れていた（157 → 119px）

`.battle-top` は `nowrap` の flex 一行で子が5つ（場所・ウェーブ・ラウンド・トグル・撤退）。
375px では取り分が足りず、**「始まりの草原」が幅15px・高さ144pxになって
1文字ずつ縦に折り返していた。** 見出しが157pxだった正体がこれ。

折り返しを許して2段にした。実測 `battle-field` は 15×144 → **309×22**。

**これは配置の問題ではなく、ただの不具合だった。**

### 2. ログを最後へ回した

DOM の並びは 見出し → 敵 → **ログ** → 味方 → コマンド で、
敵とコマンドのあいだにログが190px挟まっていた。`order` で最後へ回し、高さも124pxへ。

並べ替えは `order` でやる。DOM を触るとログの追従スクロールや読み上げ順まで巻き込む。

### 3. 技の一覧に上限と内部スクロール（816 → 355px）

**2列は試して捨てた。** 幅が半分になるぶん技名と札が折り返してボタンが
82→128pxに伸び、816→690pxしか縮まない。しかも段の高さが揃わない（実測 163×128 と 108×128）。

代わりに `max-height: 42vh` で切って中を送らせた。**技が何本あってもページの丈が伸びない。**
切っただけだと最後の技に気付けないので、下端にぼかしを掛けて「まだ下にある」ことを示す。

### 4. 選んだら敵へ戻す（`keepEnemiesInView`）

同時に収める方法が無いので、**手でやっていたスクロールを機械にやらせる。**
`act()`（すべてのコマンドが通る一点）で、演出の前に敵の行を画面中央へ戻す。

**既に8割がた見えているときは動かさない。** 毎回スクロールすると、
指で見たい所を出しているときに横取りになる。

## 直後の実測

| | 前 | 後 |
|---|---|---|
| ページの丈 | 1587 | **1252** |
| コマンドを全部出すスクロール | 750 | **415** |
| 一覧の先頭を出すスクロール | — | **210**（そのとき敵は 83〜334＝見える） |
| 技を選んだあと | 手で戻す | **自動**（540 → 98、敵の行が top 195） |

検証テスト 1459/1459。変更は `@media (max-width: 680px)` の中と、
`innerWidth > 680` で抜ける JS だけなので、PC版には影響しない。

## 追加: 味方を2人ずつ並べる（提案を受けて）

> キャラのアイコンを一回り小さく表示して、体力バーを半分程に切ってアイコンの下に
> 配置すれば1列に2人表示して縦の長さを半分にできませんか？

**4人編成で測ると、そのとおりだった。**

| | 前 | 後 |
|---|---|---|
| カード | 309×90 | **151×66** |
| 味方の行（4人） | **396px** | **174px** |
| ページの丈 | 1558 | **1302** |
| 一覧の先頭を出すスクロール | — | 260（そのとき敵は 33〜284 で見える） |

顔を 68 → 48px に落とし、名前は溢れたら省略。HPバーは幅を追うので、
カードが半分になれば自然に半分になる（提案どおり「半分に切る」指定は要らなかった）。

### 札（バフ・状態異常）は横へ流す

狭いと何段にも折り返して**カードだけが伸びる**。1段に抑えて、溢れたぶんは
横スクロールにした。何が付いているかは指で送れば読める。

### HPの表記は折り返させない

幅75pxに対して実測68px（この保存で最大のテオドラ 21,386 で
「21,386 / 21,386」）。いまは収まるが、桁が増えると折り返して
**バーが2段になりカードが崩れる**。`nowrap` + `overflow: hidden` で切る。
数字が読めなくなるより、形が崩れないほうを採った。

## 追加: 戦闘中は上部バーを畳む（提案を受けて）

> 上部の常時表示の横に所持金とスタミナ量、宝箱の数、データを
> 二段に分けて配置すればまだ詰められませんか？

**測ってから、別の手を採った。**

### 提案どおり2×2にすると17px

`#topbar` は 103px で、内訳は 上余白14 + ロゴ26 + すき間8 + 右の行44 + 下余白10。

- ロゴ101px + 右323px = 424 > 335 なので折り返している
- **右の行が44pxなのは「データ」ボタンだけが44px**（通貨の札は28px）

ロゴの横へ2段に置くと `max(ロゴ26, 28+6+28=62) + 余白24` = **約86px**。
17px は稼げるが、データボタンを28pxへ縮める前提になる。
**44pxは指で押す最小の寸法**なので、そこを削るのは別の代償を払うことになる。

### 戦闘中は103px まるごと空けられる

**戦闘中に上部バーの中身が何も要らない。**

- 所持金と宝箱は戦闘では動かない（払い出しは結果画面に出る）
- **オートの残量は戦闘側のトグルが「オート (20)」として出している**
- データ画面は戦闘中には開かない

`showOnly()`（画面切り替えの一点）で `body.in-battle` を付け、
狭い画面のときだけ `#topbar` を畳む。拠点へ戻れば復活する。

| | 前 | 後 |
|---|---|---|
| ページの丈 | 1302 | **1181** |
| 一覧の先頭を出すスクロール | 260 | **139**（そのとき敵は 33〜284 で見える） |
| 戦闘の中身が始まる位置 | y=134 | **y=13** |

**139px 送れば、敵と技の一覧が同時に見える。**

## 残っていること

- 上部バーの2×2（提案そのもの）は入れていない。戦闘では畳むので効かず、
  拠点など他の画面で17px稼ぐだけになる。やるなら「データ」の寸法と引き換え
- 味方の行124px も削れる余地はあるが、HPバーは戦闘中いちばん見る場所
- **見た目は実機で確認が要る。** ブラウザ枠の描画が縮尺されていて、
  こちらのスクリーンショットでは見た目を判断できなかった（数値と操作は確認済み）
