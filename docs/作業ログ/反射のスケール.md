# 反射を敵スケールへ揃える

**ブランチ**: `work/reflect-scale`
**日付**: 2026-08-25

## 診断（利用者の指摘が正しかった）

> 敵の体力が闘技場で膨らむのにこちらのHPは数万程度、
> さらにそのHPで耐えられる攻撃を反射するから起こっている

数字で確認した。

| | 値 |
|---|---|
| 闘技場ボスのHP | 736,710 〜 4,760,600 |
| 味方のHP | 35,724 |
| **開き** | **20〜133倍** |

反射は `result.damage × reflect` ——**受けきれる量しか返せない**ので、
味方のHPスケールに縛られる。率を何倍にしても敵のHPスケールには届かない。

## 棘は同じ問題を持っていなかった

```js
反射:  result.damage * reflect     ← 味方が受けた量（味方スケール）
棘:    attacker.maxHp * thorns     ← 相手の最大HP（敵スケール）
```

実測（Lv255・破壊者・上限投資）:

| 場 | 棘 | 反射(修正前) |
|---|---|---|
| fl_endless | 301,676（敵HPの11.3%） | 37,803（1.4%） |
| fl_origin | 134,846（7.1%） | 1,947（0.1%） |

**棘は反射の8〜70倍。** しかも棘は13SP、反射は27SP。
「殴られてから効く」一族が全部だめなのではなく、**反射だけが基準を間違えていた。**

## 入れたもの

反射の最終ダメージに **相手のレベル倍率** を掛ける。

```js
const REFLECT_LEVEL_RATE = 0.1;
const scale = lv > 0 ? 1 + lv * REFLECT_LEVEL_RATE : 1;   // Lv270 で ×28
```

`1 +` にしてあるのは序盤で1を下回らせないため。
レベルを持たない相手には掛けない。

### 係数の選定 — 一度 0.05 にして、0.1 へ戻した

最初、棘との釣り合いを見て 0.05 を採った（0.1 だと棘の2.9倍になるため）。
**これは基準の取り方が間違っていた。**

利用者の設計意図はこうだった:

> 棘に関しては継続ダメージと同じで、今後敵だけがインフレし続けた場合に
> 割合ダメージなのが効く（或いは低ダメージの連続攻撃型の敵）と思っているので、
> 反射とダメージ差が開いていても良い

**棘は敵インフレへの備えとして意図的に割合基準にしてある。**
揃える対象ではないので、揃えようとすると反射を不必要に削ることになる。

正しい基準は「**同じSPを火力に回した場合に勝てるか**」。それで測り直した。

| 場 | 構成 | SP | 勝率 | R | 反射 |
|---|---|---|---|---|---|
| fl_endless | 同SPを火力へ | 229 | 67% | 3.88 | — |
| fl_endless | **反射(×0.1)** | 234 | **71%** | **2.71** | 876,677（敵HPの32.5%） |
| fl_origin | 同SPを火力へ | 229 | 100% | 2.17 | — |
| fl_origin | 反射(×0.1) | 234 | 100% | **2.04** | 40,971（2.2%） |

fl_endless で火力に回すより明確に良く、fl_origin でも僅かに良い。
**反射1発の最大は 1,076,663** で、闘技場ボス（736,710〜4,760,600）を
一撃で消す水準ではない。提案どおり 0.1 で確定。

**修正前は「反射を捨てたほうが勝率が上がる」状態だった（63% → 88%）。**
いまは逆に、反射を取ったほうが勝率もラウンドも良い。


### 場による差は残す

| | fl_endless | fl_origin |
|---|---|---|
| 反射 | 32.5% | 2.2% |
| 棘 | 11.3% | 7.1% |

反射は**強く殴ってくる相手ほど効く**、棘は**回数で安定して効く**。
`damage.js` のコメントにある「棘と違い、殴られた重さがそのまま返るので大技ほど痛い」
という元の設計意図が、敵スケールのまま実現できた形。

## ついでに直した説明の誤り

- `tr_thorns_hi`（鉄条の鎧）「相手に**自分の**最大HPの5%」→ 実装は `attacker.maxHp`。
  闘技場ボス相手だと 1,786 と 238,030 の違いになる
- `damage.js:264` の `C = 被攻撃側レベル × 100 + 500` → 定数は `DEF_CONST_PER_LEVEL = 40`。
  以前から報告していたもの

なお `tr_thorns` の「硬い相手ほど効く」は**正しい説明**だった（一度誤りと判断したが撤回）。
