# 反射を敵スケールへ揃える

**ブランチ**: `work/reflect-scale`
**日付**: 2026-08-25

## 診断（利用者の指摘が正しかった）

> 敵の体力が闘技場で膨らむのにこちらのHPは数万程度、
> さらにそのHPで耐えられる攻撃を反射するから起こっている

数字で確認した。

| | 値 |
|---|---|
| 闘技場ボスのHP | 736,710 〜 4,760,600 |
| 味方のHP | 35,724 |
| **開き** | **20〜133倍** |

反射は `result.damage × reflect` ——**受けきれる量しか返せない**ので、
味方のHPスケールに縛られる。率を何倍にしても敵のHPスケールには届かない。

## 棘は同じ問題を持っていなかった

```js
反射:  result.damage * reflect     ← 味方が受けた量（味方スケール）
棘:    attacker.maxHp * thorns     ← 相手の最大HP（敵スケール）
```

実測（Lv255・破壊者・上限投資）:

| 場 | 棘 | 反射(修正前) |
|---|---|---|
| fl_endless | 301,676（敵HPの11.3%） | 37,803（1.4%） |
| fl_origin | 134,846（7.1%） | 1,947（0.1%） |

**棘は反射の8〜70倍。** しかも棘は13SP、反射は27SP。
「殴られてから効く」一族が全部だめなのではなく、**反射だけが基準を間違えていた。**

## 入れたもの

反射の最終ダメージに **相手のレベル倍率** を掛ける。

```js
const REFLECT_LEVEL_RATE = 0.05;
const scale = lv > 0 ? 1 + lv * REFLECT_LEVEL_RATE : 1;   // Lv270 で ×14.5
```

`1 +` にしてあるのは序盤で1を下回らせないため。
レベルを持たない相手には掛けない。

### 係数の選定

| 係数 | Lv270で | fl_endless の敵HP比 | 棘との比 |
|---|---|---|---|
| 0.1（提案値） | ×28 | 32.5% | 2.9倍 |
| **0.05（採用）** | ×14.5 | **17.5%** | 1.5倍 |

0.1 は棘の3倍近くになり強すぎた。0.05 なら、反射のほうがSPが倍（27対13）なので
1.5倍は妥当な範囲に収まる。

### 効き（fl_endless / 3種×8戦）

| 構成 | 勝率 | R | 貢献 |
|---|---|---|---|
| 素（反射も棘も無し） | 67% | 3.88 | 0 |
| **反射(×0.05)** | 67% | **2.56** | 443,994 |
| 棘 | 67% | 2.75 | 301,676 |

**修正前は「反射を捨てたほうが勝率が上がる」状態だった（63% → 88%）。**
いまはラウンドが 3.88 → 2.56 と縮み、罠ではなくなった。

### 場による差は残す

| | fl_endless | fl_origin |
|---|---|---|
| 反射 | 17.5% | 0.9% |
| 棘 | 11.3% | 7.1% |

反射は**強く殴ってくる相手ほど効く**、棘は**回数で安定して効く**。
`damage.js` のコメントにある「棘と違い、殴られた重さがそのまま返るので大技ほど痛い」
という元の設計意図が、敵スケールのまま実現できた形。

## ついでに直した説明の誤り

- `tr_thorns_hi`（鉄条の鎧）「相手に**自分の**最大HPの5%」→ 実装は `attacker.maxHp`。
  闘技場ボス相手だと 1,786 と 238,030 の違いになる
- `damage.js:264` の `C = 被攻撃側レベル × 100 + 500` → 定数は `DEF_CONST_PER_LEVEL = 40`。
  以前から報告していたもの

なお `tr_thorns` の「硬い相手ほど効く」は**正しい説明**だった（一度誤りと判断したが撤回）。
