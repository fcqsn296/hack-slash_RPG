# 節制 XIV — 実装と初回測定

実装済み・公開済み。検証テスト 1638/1638 合格（節制10件）。
**「溜めるための手番を使わない」形（案A）で採用。**

仕様は `docs/節制の実装案.md`。

## 実装したもの

> 利: 自分の回復技であふれた回復を蓄え、次の攻撃1行動を強化する
> 害: 溜まるのは回復技のあふれた分だけ。吸収や再生では溜まらず、次の攻撃で使い切る

- 効果種 `temperance`（係数 0.25）を1つ追加
- 蓄積は `ctx.heal` の**既にある `spill`（過剰分）を共有**する。
  自前で計算し直すと、呪詛や分別の補正を二重に掛けたり掛け忘れたりする
- `plugin === 'heal'` の技だけを数える。**吸収 (lifesteal_hit) も蘇生 (mass_revive) も
  同じ `ctx.heal` を通る**ので、技で絞らないと「強化攻撃の吸収が次の強化を用意する輪」ができる
- 攻撃1行動の開始時に蓄えを移し、終わりに必ず捨てる。多段の全段に乗り、次の行動へ漏れない
- 上限 `TEMPER_CAP = 1.0`（暫定）

### 上限は「足す」のではなく「倍にする」

@知見: 上限を伸ばす一時強化は cap_break に足さず、(1 + capBreak) を倍にする

ダメージ上限は `500,000 × (1 + capBreak)`。同じ数値を `cap_break` に**足す**と、
既に上限突破を積んだビルドほど効きが薄まる。
`(1 + capBreak) × (1 + 蓄え) - 1` にすれば、上限の下でも上でも実効がちょうど倍率どおりになる。

検査で確かめてある（上限突破0でも5でも ×2.00 ちょうど）。

## 交換式は表のとおり

| 条件 | 蓄え |
|---|---|
| 1人へ最大HP100%分の過剰回復 | +25% |
| 4人へそれぞれ100%分 | +100% |

吸収技のあとは +0%（正しい）。攻撃1行動で使い切り、次の行動には残らない。

## 仕様書が予期していた問題がそのまま出た

> 現行のオートが満タン時に回復技を選ばない場合、蓄積が一度も起きない可能性がある

**そのとおりだった。** 手を入れる前は 蓄積0回／周回・HP×300・HP×1000 のすべて。

そこで一度、オートに「蓄えるために回復する」判断を足して測った。
緊急回復の判断より後ろに置き、この1回で上限近くまで届く見込みがあるときだけ撃つ形。

## その判断は採用条件を満たさなかった

終わりなき回廊5ウェーブ・20試行:

| | HP×300 | HP×1000 |
|---|---|---|
| 素 | **5.1R** | **5.3R** |
| 節制（上限+100%） | 7.3R | 10.5R |
| 節制（上限+200%） | 7.3R | 11.2R |

**上限を倍にしてもラウンドが1つも改善しない。** 上限+300%にすると、
見込みが上限に届かなくなって一度も蓄えず、素と同じになる（＝札が不活性）。

### 原因

主人公の行動を並べると、**回復と強化攻撃を交互に撃っている**。

```
聖癒の光（蓄え0%）    → 削った 0
黄昏  （蓄え100%）    → 削った 47,440,072
聖癒の光（蓄え0%）    → 削った 0
黄昏  （蓄え100%）    → 削った 20,706,498   ← 敵の残りHPで頭打ち
聖癒の光（蓄え0%）    → 削った 0
黄昏  （蓄え100%）    → 削った 145,878,530
```

2手（回復＋強化攻撃）で ×2 の一撃が1回。**通常攻撃2回と火力上は並ぶだけ**で、
そのうえ回復の1手ぶん敵に余計な行動を与える。

さらに、**強化ぶんが過剰殺傷で捨てられる回が混ざる**（20.7M の行は敵の残りHPで
頭打ちになっている）。倒し切れる相手に ×2 を撃っても得は無い。
だから上限を倍にしても改善しなかった。

@知見: 「1手を溜めて次の一撃を倍にする」は、過剰殺傷で捨てられるぶん構造的に損になる

## 採った形 — 案A「溜めるための手番を使わない」

オートの「蓄えるために回復を撃つ」判断を**外した**。
必要で撃った回復のあふれだけが溜まる。溜めるための手番を使わないので害が無く、
そのぶん利も控えめ——**回復役を連れる編成が、ついでに少し火力を得る**という位置づけ。

### 外したあとの実測（24試行）

| | 素 | 節制 | 解放 |
|---|---|---|---|
| 周回（相なし） | 5.00R | **5.00R** | 0.0回 |
| HP×300 | 5.08R | **5.08R** | 0.0回 |
| HP×1000 | 5.21R | **5.21R** | 0.0回 |
| 相つき（先制＋あまねく） | 5.00R / 勝率96% | 5.00R / 勝率96% | 0.2回 |

**害がゼロ。** 周回では素と小数点以下まで同一で、味方が実際に削られる場面でだけ発火する。

### 採らなかった案

- **B. 蓄えを1行動で使い切らせない** … 仕様書の「次の攻撃で全て消費する」の変更になる
- **C. 強化の中身を火力以外へ変える** … 札の像（注ぎ分ける）からは離れる

## 実装で踏んだ罠

- **`TEMPER_CAP` を外から書き換えても内部の定数は変わらない。** 探針で
  `R.battle.TEMPER_CAP = 2.0` としたら、オートだけ上限を勘違いして
  「溜まったつもりが溜まっていない → また回復」を繰り返し、5.1ラウンドが27ラウンドになった。
  上限を振って測るときは**ソースの定数そのものを書き換える**こと。
  （案Aで判断ごと外したので、この暴走の口は塞がっている）
- **蓄積のログを対象ごとに出さない。** 全体回復だと4行並んで、
  「何回蓄えたか」を数えるときに人数ぶん水増しされる（実際に読み違えた）
