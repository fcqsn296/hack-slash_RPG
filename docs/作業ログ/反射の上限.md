# 反射の上限を 40 → 400 へ

## レベル倍率は最初から効いていた

`REFLECT_LEVEL_RATE = 0.1`（Lv255 で ×26.5）は正しく適用されていた。
`preMercyDamage`（闘技場の緩和を戻した重さ）も使われていた。

効いていなかったのは **`REFLECT_CAP_RATIO = 40`** のほう。
闘技場の主（ハード）で実測すると、返り値が**毎回きっちり 1,061,320**
（26,533 × 40）だった。

```
闘技場の主（ハード） に 1,061,320 が跳ね返った
闘技場の主（ハード） に 1,061,320 が跳ね返った
闘技場の主（ハード） に 1,061,320 が跳ね返った
```

**一撃の重さもレベル倍率も、何ひとつ結果に出ていない。** 上限がそのまま火力だった。
「重い一撃ほど痛い」という反射の性格が消えていた。

## なぜ 400 か

狙われやすさを限界まで積んだ4人編成での実測。

| 上限 | 1発 | 毎ラウンド | 200Mに必要 |
|---:|---|---:|---:|
| 40（旧） | 1,061,320（毎回同じ） | 2.9M | 69R |
| **400** | **490万〜840万（毎回違う）** | **20.0M** | **10R** |

400 では**上限が当たらなくなり、素の値が出る**。天井は安全弁として残るだけになり、
「1発が極端に重い相手」にだけ効くという本来の役目に戻った。

棘（300 → 22.2M / 9R）のすぐ後ろに並ぶ位置。多段で殴ってくる相手では棘が上、
一撃が重い相手では反射が上、という差が数字にも出る形にしてある。

## 通常フィールドには影響しない

通常フィールドの素の返りは40万程度で、旧上限（約106万）にも届いていなかった。
上限を緩めても1も動かない。棘と同じ理屈。

バランス計測の想定ビルド（`test/balance.js` の `PRIORITY`）にも
`tr_reflect` は入っていないので、フィールドの再測定は不要。

## 測っているときに踏んだ罠

検証テストが 1349 → 1338 に落ちて「虹を喰らう獣が決着しない」が出た。
**原因は反射の変更ではなく、計測用に読み込んだセーブが `localStorage` に
残っていたこと。** 主人公のツリーを反射型に差し替えたまま検証テストを回したので、
パーティが倒しきれず膠着していた。

反射を40に戻しても同じ落ち方をしたので、そこで初めて環境を疑った。
**数値を戻して直らなかったら、次に疑うのは環境。**

## 測った値

- 検証テスト 1351 / 1351
- 追加した検査:「重い一撃ほど返りが大きい（上限に張り付いていない）」
  「反射の上限は棘より高い（性格の差を残す）」
