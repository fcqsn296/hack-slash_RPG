# 自動売却を装備画面からも使えるようにする

## 何が足りなかったか

自動売却の設定と実行は**鑑定画面にしか無かった**。
装備画面には「表示中をまとめて売却」があるが、あれは性格が違う。

| | 何をするか | 安全装置 |
|---|---|---|
| 表示中をまとめて売却 | 絞り込みの結果を**無条件に**売る | ロック・装備中のみ |
| ルールで売却 | レアリティ・スコアの条件で選ぶ | ＋**更新候補は残す** |

掃除の判断が要るのは鑑定した直後だけではないので、
ルールで売る側も装備画面から使えるようにした。

## 実装

コア (`src/core/autosell.js`) は最初から在庫全体を対象にできる
（`run()` に何も渡さなければ `s.inventory` を見る）。**UIの配置だけ**で済んだ。

`autoSellPanel(root)` をそのまま流用し、折りたたみの枠 `autoSellSection` で包んで
所持装備の一覧の直前に置いた。中身は鑑定画面とまったく同じで、
設定はセーブ側で1つなので**どちらで変えても揃う**。

**既定で畳んである。** 装備画面は所持装備の一覧が主役で、設定を常時開くと
一覧がそのぶん下へ押し出される。見出しには対象の件数を出したままにしたので、
畳んでいても「いま31個 / 1,833 G」と状況は分かる。

CSSは枠が二重にならないよう、入れ子側のパネルの枠・背景・見出しを外している。

## 実機で確かめたこと

- 畳んだ見出しに件数と金額が出る（31個 / 1,833 G）
- 開くと鑑定画面と同じ3行（売却対象・スコア・安全装置）が並ぶ
- 売却して 40個 → 9個、+1,833 G。**装備中は残った**
- 装備画面でスコアを250に変えると、鑑定画面でも「250 未満」が選ばれている

なお `protectUpgrades` が効いていると、**誰も何も装備していない状態では
全部が「更新候補」になって対象0件になる**。基準が0なので当然だが、
最初に見たときは驚いた。自動装備を通してから測り直している。

検証テスト 1270/1270。
