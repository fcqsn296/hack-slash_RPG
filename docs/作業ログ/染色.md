# 染色（敵の属性を塗り替える）

保留中のアイデアから着手。2026-08-20 に保留、2026-09-18 に実装。

## なぜ空いていたのか

攻撃側の属性操作は**ツリーが埋め尽くしている**。

| 既存のツリー効果 | 何をするか |
|---|---|
| `element_convert` | 自分の全攻撃を1属性に固定する |
| `dual_element` | 2属性で判定して良い方を取る |
| `element_adapt` | 不利を等倍まで引き上げる |
| `element_mastery` | 特定属性の有利倍率を伸ばす |
| `element_pierce` | 不利属性の目減りを減らす |

一方で、**受け側の属性に触る手段は1つも無かった**。ここが構造的に空いている。
属性特化ビルドは「刺さらないフィールド」で腐るという弱点を抱えているが、
染色があればその弱点を連れて行く仲間で補える。

## 保留の理由を、どう解いたか

保留時に挙げていた3つの懸念と、その始末。

### ① 全体化すると属性特化がそのまま万能になる

単体・短ターン（2ターン）にした。「どの1体をいつ染めるか」が残る。
実測でも**ボスに使うと得、雑魚に使うと損**という形に収まっている。

### ② 敵の属性は被ダメージ側の相性も決めている

**塗るのは「受ける側の属性」だけにした。** `toDefender` が返す属性だけを
差し替え、敵の攻撃は塗る前の属性のまま飛んでくる。
闘技場の `elementNull` が相性を一方向にだけ均しているのと同じ立ち位置。

両方向にすると有利不利が二重に動き、1手の価値が場面によって跳ね上がる。
実測: 与ダメ 1.50倍 / 被ダメ 1.00倍。

### ③ バランス検証を属性別に見直す必要がある

見直す必要が無かった。周回シミュレーションはオートで回るが、
**autoplay は染色を読まない**（コンボと同じ扱い）。
手動で遊ぶ軸なので、周回の数字は動かない。実際に全項目 ✔ のまま。

## 踏んだ罠

**既定の染め色を「撃った本人の属性」にしていた。** 火のパーティが相手を火に
染める形になり、有利どころか何も起きない。実測でボス戦が
14.25R → 15.20R と、**染めたほうが遅くなっていた**。

正しくは「自分の属性が食う色」。火なら風へ。`STRONG_AGAINST` を引けば
一意に決まるので、技ごとに書かせる必要もない。直したら 10.85R になった。

もう一つ。手順書の検査は「plugin に書けるもの」から「バフは3つ」までを
1つの表として読む。その範囲に別の表を割り込ませると、
**その行が plugin 名として拾われて落ちる**。節は範囲の外へ置くこと。

## 実測（Lv200・火に固定した4人・20戦）

| 条件 | 染めない | ボスを染める |
|---|---|---|
| 闇のボス単体（火は不利） | 14.25R | **10.85R**（−24%） |
| 闇の5戦通し | 38.35R | **34.70R**（−10%） |

持続を伸ばしても大差ない（2T 10.85R / 3T 10.55R / 4T 10.30R）ので、
いちばん短い2ターンで据え置いた。保留時の方針どおり。

## 染めた色を盤面に出す

ログだけでは染まりが読めなかったので、敵の札に **「元の色 → いまの色 → 残りT」**
を出す形にした（`闇 → 風 2T`）。元の色を残すのは、落ちたあと何に戻るかが
分からないと次の一手を決められないため。染色は2ターンで落ちる。

### 相性チップが嘘をついていた

**画面と計算で属性を別々に決めていた。** 相性チップは技の `element` を
そのまま読んでいたので、2つの場面でずれていた。

- 属性変換（`element_convert`）を積んだ人 … 実際は火で飛ぶのに技の色で判定
- 染まっている相手 … 素の色で判定

前者は染色より前からあった不具合で、染色を入れたことで表に出た。
`damage.attackElementOf` / `damage.matchup` を作って**計算と同じ口**を通すようにした。
双極（`dual_element`）も matchup が見るので、「不利と書いてあるのに有利で通った」
という形も同時に消えている。

実画面での確認（火に固定・闇の蛇2体、片方を風へ染めた）:

| 相手 | 札 | 相性チップ |
|---|---|---|
| 染めた蛇 | 闇 → 風 2T | 有利 ×1.5 |
| 素の蛇 | 闇 | 等倍 |

直す前は、変換を無視して技の色（光）で判定するので**両方とも有利 ×1.5**と
出ていた。375px でも札96pxに印74pxが収まり、横スクロールは出ない。

## オートに読ませた

染色そのものは1ダメージも増やさない。増えるのは**そのあと味方がその相手を
殴るときの通り**。技の威力だけで測ると威力90の弱い攻撃にしか見えず、
永久に選ばれない（障壁で踏んだのとまったく同じ形）。

相性の倍率は `damage.matchup` が知っているので、塗る前と塗った後を引けば
そのまま「増える割合」になる。それを味方の一番よく通る一撃に掛けて足す。

**1人ぶんしか数えないと、実際の値打ちの1/4にしかならない。**
最初そうしていて、20戦で 0.2回しか染めなかった（手で染めれば 14.25R → 10.85R
なのに）。生きている味方1ラウンドぶんを合計し、その相手の残りHPで頭打ちにした
——倒しきれる相手を染めても増えるのは過剰殺傷だけで、1手を捨てることになる。

| 条件 | 技なし | 技あり | 染めた回数 |
|---|---|---|---|
| 火に固定 / 闇のボス | 14.25R | **11.25R** | 4.0回 |
| 火に固定 / 闇の5戦 | 38.35R | **32.60R** | 16.6回 |
| 変換なし（染めても得しない） | 13.05R | 13.05R | **0回** |

手で染めた 10.85R にほぼ並んでいる。得にならない編成では一度も染めない。

## 敵も染めてくる

味方側とまったく同じ仕組みで動く。**片方だけの道具にしない。**

| 敵 | 属性 | 筋 |
|---|---|---|
| 無を織る者 | 闇 | 織る者が色を奪う |
| 燼獄の女王 | 火 | 燼をまとわせて火の色にする |

敵は「自分が食う色」に染めるので、そのあとの一撃が有利で通る。
実測: 被ダメ 10,976 → 16,464（1.50倍）。

**味方の札にも同じ印を出した。** 出さないと「なぜ急に痛いのか」が読めない
画面になる。敵と味方で読み方を揃えるため、印は1つの関数にまとめてある。

## 次に決めること

- 染めてくる敵をもっと増やすか（いまは2体。属性の偏りも見たい）
- 異相に「属性を問う相」を足すか（敵全体が染色を持つ、など）
