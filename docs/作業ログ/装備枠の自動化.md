# 装備枠をツリーから外し、レベルで配る

## なぜ

装備枠の枝は **全員が必ず取る** ものだった。取捨選択が起きない枝をツリーに置くと、
「13SPを払う手続き」でしかなくなる。選ばせるつもりの場所に、
選びようのないものが3つ混ざっていた。

  装飾の心得  初級 3SP
  重装の心得  中級 4SP
  二刀の極致  上級 6SP   計 13SP

## レベルで配る（ティア解放ではなく）

最初はティア解放に紐づけようとしたが、**ティアは基礎ノードを払い戻すと閉じ直す**。
枠が消えて装備がはみ出す崖が新しく生まれてしまう。

レベルは下がらないので、枠も減らない。**「枠が減ったときの後始末」という
問題そのものが消える。**

| | レベル | 以前の実質的な取得時期 |
|---|---|---|
| アクセサリー | Lv5 | 3SP ≒ Lv5 |
| 防具 | Lv10 | 中級解放 + 4SP ≒ Lv10 |
| 武器 | Lv20 | 上級解放 + 6SP ≒ Lv17〜20 |

**Lv1 の 1/1/1 は変えていない。** 始めた瞬間から枠が違うと、
既存の説明も初期の手触りも変わってしまう。

## 撤去したもの

ノード3つを消したので、`slot` という効果種別が誰にも使われなくなった。
登録簿に残すと「分類表に使われていない種別が無い」検査に引っかかるので、
一式まとめて外した。

  data/skilltree.js      ノード3つ
  data/effectkinds.js    slot の行
  data/nodecategories.js 分類表の 'slot'
  src/core/tree.js       KNOWN_EFFECT_KINDS / case 'slot' / slots の集計
  src/ui/base.js         ノードの「装備枠」チップ
  styles.css             .chip-slot
  test/tests.js          §5 の検査一覧

## 既存セーブ

`spentSp` も `effects` も **実在するノードしか見ない** ので、
消した時点で 13SP は自動的に戻る。実機で確認した（59SP中 54 が残り、
消費は tr_atk の 5 のみ）。

ツリーに残った `tr_slot_*` は `migrate` で消している。効果は無いが、
将来同じIDのノードを足したときに「勝手に振ってある」状態になるため。

## 伝え方が消えた問題

枠が枝だったころは、ツリーに「二刀の極致」が並んでいるだけで
**2つ目の武器枠の存在が伝わっていた**。自動化するとその手掛かりが消える。

装備画面の見出しに、次に枠が開くレベルを1行出すようにした。

  Lv1  → 「Lv5 でアクセサリー枠が1つ増えます」
  Lv7  → 「Lv10 で防具枠が1つ増えます」
  Lv15 → 「Lv20 で武器枠が1つ増えます」
  Lv30 → （全部開いているので出さない）

検証テスト 1245/1245。
