# 終わりなき回廊を一覧の最後へ／庇うの分担／貫通を仕様に

## 1. 庇う役が2人いても1人しか働かなかった

`battle.party.find(...)` で**先頭の1人だけ**を拾っていた。2人目を庇う型にしても
何も起きず、しかも誰が働くかが**パーティの並び順**で決まっていた。

直したが、「各自が0.8ずつ肩代わり」にはしていない。それだと2人で160%が動き、
**庇うほど総ダメージが増える**という逆転になる。

**総量は0.8のまま、持ち分で割る。** 2人目の意味は「総量が増えること」ではなく
「1人あたりの負担が減ること」。

## 2. 棘・反射が取り巻きを貫通するのは仕様として残す

`guardedByAdds` の判定は「こちらから殴る」経路（`applyDamage` の入口）にしかなく、
棘・反射は `hurt()` を直接呼ぶので衛士が生きていても本体へ通る。

**殴ってきた相手にそのまま返す**という性質のものなので、
「衛士の後ろにいるから殴り返されない」ほうが理屈に合わない。
うっかり塞がれないよう、コードのコメントと検査の両方に残した。

## 3. 終わりなき回廊を一覧の最後へ

並び順は推奨レベルで決まる（`src/ui/base.js`）。臨界の際(225)と還らぬ位相(250)を
足したとき、**常に追随する狩場が手前に来てしまっていた**。
「置いていくことができない」場所が途中にあるのは順序として噛み合わない。

`rec_level` 200 → **255**（レベル上限そのもの）。敵はここから +15 されて Lv270 になるが、
格上補正が乗らない範囲（+20以内）に収まっている。

### 最後に置くなら、最高収入である必要がある

並び替えただけでバランス検証が3件落ちた。**推奨レベル順で収入が単調に増える**
という判定なので、最後尾は最高でなければならない。

| | 移動前 | 移動後（倍率を上げる前） | 最終 |
|---|---:|---:|---:|
| 1ラウンドの総収入 | 6,510 | 6,213 | **11,767** |
| 1周の直接G | — | 12,485 | **17,025** |

`gold_mult` 0.32 → **0.75**、`box_mult` 1.68 → **2.80**。

倍率が大きく見えるが、この狩場の性格には合っている。**常にパーティ+15レベル**で、
実測の勝率は **67%**（臨界96% / 位相100%）。3回に1回負ける代わりにいちばん稼げる、
という位置づけになった。もともと「常に格上な代わりに実入りが濃い」と書いてあった
方向を、数字の側でやっと満たした形。

### 移動で分かったこと

推奨レベルを上げると**戦闘の中身まで変わる**。Lv200のパーティがLv215と戦う形から、
Lv255がLv270と戦う形になり、レベル差は同じ+15なのに勝率が 88% → 67% に落ちた。
**「並び順を変えるだけ」は成立しない。** 必ず測り直すこと。

## 測った値

- 検証テスト 1357 / 1357
- バランス検証 4節すべて合格
- 最終の並び: 灰燼4,959 → 封絶区画5,258 → 創世5,722 → 臨界7,068 → 位相9,678 → **回廊11,767**

## 残していること

回廊の経験値は据え置き（`exp_mult: 0.52`）。1レベルに6.6周で、位相の3.1周より遅い。
検査（14周以内）は通っているが、**最後の狩場なのに経験値だけは最下位**という状態。
レベル上限に張り付いてから通う場所なので実害は小さいと判断した。
