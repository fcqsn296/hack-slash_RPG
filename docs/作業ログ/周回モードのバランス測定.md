# 周回モードのバランス測定

担当: バランス測定のみ。**修正はしていない。** 数字はすべて `test/balance.html` の道具
（`RPG.balance.*`）を実際に戦闘エンジン・ツリー判定に通して測ったもの。

条件は `CLAUDE.md` §3 と `docs/強いビルドの組み方.md` §9 に合わせた
（上乗せでなく置き換え・1回に1つだけ変える・複数シード平均・`localStorage` 退避）。
既存の作業ログから引いた数字には出典を添えている。

---

## 結論を先に（重い順）

1. **既存の「想定ビルド」が 259SP のうち 124SP（48%）を使い切らずに測っている。**
   `test/balance.html`・`docs/強いビルドの組み方.md` の Lv1〜255 の全ダメージ曲線が、
   この半分しか使っていないビルドを基準にしている。§1 参照。
2. **クラスポイント51点は、どのクラス・どの派生を選んでも「核＋派生1つのフル取得」に届かない。**
   常に34点前後（4割）足りない。§2.2 参照。
3. **軸ごとのツリー専用ノードの厚みが最大30倍以上違う。** 状態異常(381SP)・支援回復(445SP)は
   259SPを全部注いでも足りないのに対し、棘(13SP)・反射(27SP)は極端に薄い。§2.1 参照。
4. **還らぬ位相(Lv250)が終わりなき回廊(Lv255)を実戦効率で上回る。** 回廊は「常に格上」の代償を
   払っているのに、勝率込みの実収益では緩い還らぬ位相に負けている。§3.3 参照。
5. **Lv150→160でダメージの伸びがほぼ止まる（+1%）。** ただしこれは①の測定ツールの
   想定ビルドがLv135前後で投資先を使い切ることが原因の疑いが強く、実プレイヤーの伸びを
   正確に反映していない可能性がある。§4.1 参照（未解決のまま記載）。

## 1. 想定ビルドが259SPを使い切っていない（測定ツールの問題）

### 測った数字

`test/balance.js` の `PRIORITY`（Lv1〜255の全ダメージ曲線・全フィールド経済シミュレーションが
これに乗って動く「プレイヤーがだいたいこう振るだろう」というリスト）を、Lv255・凸5（259SP）で
最後まで振り切ってみた。

```
RPG.balance.investTree({level:255, limitBreak:5, tree:{}})
→ 消費SP 135 / 259（124SP が丸ごと未使用）
```

### なぜ

`PRIORITY` に `tr_slot_acc` `tr_slot_armor` `tr_slot_weapon` が入っているが、
これらは作業ログ「装備枠の自動化」で削除済みのノードID（装備枠がレベル解放に変わった際に
撤去された）。`RPG.tree.canInvest` は存在しないノードIDに `{ok:false, reason:'不明なノード'}`
を返すだけなので、**エラーも出さずに3項目が黙って何もしない。** ここで説明が付くのは13SPぶんだけ。

残り111SPは、単純に `PRIORITY` の対象が狭いことが原因。威力帯ノード
（`tr_high_boost` `tr_mid_boost` `tr_low_boost` 系列）・属性の極意・弱点ダメージ増幅・
【極】ノードなど、木の大部分がリストに入っていない。

### 実際に259SP使い切ったらどうなるか

攻撃系ノードを網羅したリストを作り、Lv255・凸5・基準敵で覇王斬のダメージを比較（8シード平均）。

| | 消費SP | 平均ダメージ比 |
|---|---:|---:|
| 既存の想定ビルド（135SP） | 135 | 基準 |
| 259SP使い切った版 | 259 | **×0.95〜×1.08**（8シード平均でほぼ横ばい） |

**124SP追加してもダメージはほぼ変わらない。** SP自体は無駄になっていない
（§2.1 で見るように状態異常・支援回復側には行き先が潤沢にある）が、
**「攻撃に全振りする」という一番素直な使い方をした場合、Lv255ではSPの使い道が
135前後で頭打ちになる** ということでもある。

### これが困る理由

- `damageCurve()` を使うすべての測定（`強いビルドの組み方.md` の §4.1 上限到達表、§2.3 序盤SP表、
  このファイルの §4 も含む）が、**Lv135相当のSPしか使っていないキャラを「そのレベル帯の想定ビルド」
  として扱っている。** Lv150以降の数字は、実際に259SPまで振り切ったプレイヤーの強さを
  正確に表していない疑いがある
- `economyTable()`（フィールド経済・勝率）も同じ `investTree()` を経由するので、
  **高レベル帯フィールドの勝率も同じバイアスを受けている**（§3.1 参照）
- 修正すべきは `PRIORITY` 配列そのもの（死んだ3項目の削除と、威力帯・状態異常等の追加）。
  **今回は測定のみなので直していない。**

## 2. SP収支

### 2.1 ツリー：軸ごとの専用ノード予算

各軸に属する効果種別（`data/nodecategories.js` の `kinds`）を持つツリーノードだけを集め、
**その軸の専用ノードを全部Lv上限まで取ったら何SP要るか**を出した
（`RPG.data.skillTree` を実測ではなく列挙して積算。ティア解放の順序は§2.1末尾で別途確認）。

| 軸 | 専用ノードの合計SP | 259SPに対する比率 | ノード数 |
|---|---:|---:|---:|
| 状態異常 | **381** | 147%（**足りない**） | 40 |
| 支援・回復 | **445** | 172%（**足りない**） | 40 |
| 耐久（HP/DEF系＋障壁・復活・軽減） | 287 | 111%（ほぼぴったり） | 29 |
| 小技多段 | 118 | 46% | 12 |
| 中技 | 92 | 36% | 8 |
| 大技 | 85 | 33% | 7 |
| 反射 | **27** | 10% | 2 |
| 棘 | **13** | 5% | 2 |

**軸によって最大30倍以上の厚みの差がある。** 状態異常・支援回復は259SPを全部注いでも
専用ノードを取り切れず、逆に棘・反射は専用ノードだけなら13〜27SPで打ち止めになる
（残りは全部、他の軸と共通の系統タグ・会心・スロットなどの「一般枠」に流れる）。

`強いビルドの組み方.md` §7 が棘・反射を「衆目セット／守護者・修羅／HPを積む」で
噛み合わせる型として説明しているとおり、**この2軸はツリーではなく装備・クラス側で
強さを作る設計になっている**らしいことは、この数字とも整合する。ただし、
「ツリーの専用ノードが13SPしかない」こと自体は今回はじめて数えたもので、
その薄さが意図どおりかは未検証。

### 実際に軸だけへ投資したときの挙動（ティア解放込みの実測）

`RPG.tree.canInvest` を通した実投資で、各軸の専用ノードだけを優先度リストにして
Lv255・凸5（259SP）まで振ってみた（届いた後は一般枠フィラーで埋めている）。

| 軸 | 軸専用ノードだけで使った額 | フィラーまで含めた消費 | 259に対する余り |
|---|---:|---:|---:|
| 状態異常 | 259（使い切り） | 259 | 0 |
| 支援・回復 | 259（使い切り） | 259 | 0 |
| 耐久 | 257 | 259 | 0 |
| 中技 | 92 | 187 | 72 |
| 小技多段 | 98 | 193 | 66 |
| 棘 | 4 | 99 | 160 |
| 反射 | **0** | 95 | 164 |
| 大技 | 8 | 103 | 156 |

**反射軸は、専用ノードだけを狙って振ろうとすると1SPも入らない。** `tr_reflect`（反射の入口）が
中級ノードで、**反射軸には初級ノードが存在しない**ため。中級解放には初級ノードへの
5レベル投資が要るので、他の軸（tag/statなど）へ最低5SPを回り道しないと反射そのものに
着手できない。同じ理由で **大技軸も、専用の初級ノード（`tr_high_boost`・最大4レベル）だけでは
中級解放の5レベルに1レベル届かない**（実測: `canInvest('tr_high_boost_mid')` が
「初級に あと1レベル 投資が必要」を返す）。棘軸も同様に中級ノードが無く、
上級ノード解放（初級＋中級で計10レベル）に単独では届かない。

程度は小さい（反射は5SP、大技は1SP）が、**「この軸だけに絞って育てる」という
プレイヤーの意図どおりには育たない**という構造上の癖として記録しておく。

### 2.2 クラスポイント（51点）

各クラスの「核（派生に属さないノード）」と「派生1本」を、`data/classes.js` を
列挙してフルレベルまで積算した（実投資ではなく定義の積算）。

| クラス | 核 | 派生（3本） | 核＋最小の派生 | 核＋最大の派生 |
|---|---:|---|---:|---:|
| 守護者 | 51 | 34 / 34 / 34 | 85 | 85 |
| 癒し手 | 50 | 35 / 35 / 36 | 85 | 86 |
| 破壊者 | 51 | 34 / 36 / 32 | 83 | 87 |
| 呪術師 | 52 | 35 / 35 / 33 | 85 | 87 |
| 戦術家 | 50 | 38 / 35 / 35 | 85 | 88 |
| 暗殺者 | 51 | 34 / 37 / 34 | 85 | 88 |

**どのクラス・どの派生を選んでも、核＋派生1本のフル取得には83〜88点が要る。**
Lv255で配られるクラスポイントは `floor(255/5) = 51点`。**常に32〜37点（約4割）足りない。**

派生は3本のうち1本しか選べない排他式（§12）なので、余った2本ぶんの点は最初から
選択肢に入らない。それを差し引いても、**核を完全に取ると派生にはほぼ何も残らない**
（51 − 核50〜52 ＝ −1〜1点）計算になる。実際のプレイでは核を全部取り切ることは
少ないと思われるが、「核と派生をバランスよく」という前提のクラス設計に対して、
51点という配布数がそもそも85点級の器を満たせない量になっている。

これがツリーの状態異常・支援回復と同じ「余らない・足りない」型なのか、
それとも意図的な「取捨選択を強制する」設計（`docs/作業ログ/極ノード.md` と同じ思想）
なのかは、今回の測定だけでは判定できない。**未測定**：核と派生それぞれの
「効果1点あたりの重さ」を比較して、51点でどこまで戦力になるかの実戦検証。

### 2.3 まとめ

| 問い | 答え |
|---|---|
| 259SPを使い切れるか | 状態異常・支援回復・耐久の専業なら使い切れる（余らない） |
| 余ったSPの行き先はあるか | 大技・中技・小技・棘・反射の専業では**余る**（最大164SP）。行き先は
  系統タグ・会心・限界超越などの一般枠で、軸そのものの選択肢ではない |
| 全然足りない軸はあるか | 状態異常(381)・支援回復(445)は259を超える。**クラスポイントも
  常に32〜37点足りない**（どのクラスでも） |

### 3.2 勝率が低いフィールドの「勝ち試行だけの平均」に対する注意

`economyTable()` の値は**勝った試行だけ**の平均。終わりなき回廊は勝率67%なので、
負けた33%ぶん（時間を使って何も得ない）を無視した数字になっている。
勝率込みの実効効率を別に測った（§3.3）。

### 3.3 突出：還らぬ位相が終わりなき回廊を食っている

勝率込みの「本当の1ラウンドあたり収益」（勝敗問わず全試行の合計G ÷ 全試行の合計ラウンド数）
を、100戦・種を変えて測定。

| フィールド | 推奨Lv | 勝率 | 勝率込みG/ラウンド |
|---|---:|---:|---:|
| 灰燼の果て | 110 | 100% | 4,646 |
| 封絶区画 | 130 | 100% | 4,700 |
| 創世の残響 | 150 | 87% | 4,408 |
| 臨界の際 | 225 | 83% | 5,538 |
| **終わりなき回廊** | **255** | **77%** | **9,062** |
| **還らぬ位相** | **250** | **100%** | **9,748** |

（40戦・別シードでも同じ順位: 回廊8,609 対 還らぬ位相9,241。2回とも還らぬ位相が上回った。）

回廊・還らぬ位相の2つだけが突出して高く（灰燼〜臨界の1.6〜2.2倍）、これは
作業ログ「宝箱収入の底上げ」の設計意図（"常に格上な代わりに実入りが濃い"）どおり。

**ただし還らぬ位相（常に+5格上・勝率100%）が、回廊（常に+15格上・勝率77%）を
上回ってしまっている。** 回廊のほうが厳しい相手と戦っているのに、実入りは還らぬ位相のほうが良い。
Lv250以降のプレイヤーから見ると、**回廊へ行く実利的な理由が無い**
（見た目のバリエーション — 敵が31通りに化ける — という演出面の価値はある。
そちらは今回測っていない）。

原因は数値ではなく釣り合いの問題: 回廊の `box_mult 2.80` は「格上+15・勝率88%」だった
旧仕様（作業ログ「宝箱収入の底上げ」時点、雑魚差し替え前）を基準に決めた値で、
その後 `borrowShapes` 導入時の雑魚差し替えで勝率がさらに67〜78%まで落ちている
（この文書の§3.1・§3.3の勝率がその後の値）。**勝率が落ちたぶんを倍率が追いきれていない。**

## 4. 育成の詰まり

### 4.1 ダメージ曲線（レベル節目、複数シード平均）

`RPG.balance.makeUnit`（想定ビルド＝§1で触れた135SP版）で基準敵に対する
最良攻撃技の平均ダメージを、レベル節目ごとに15シード平均で測定
（1シードだと装備抽選のブレでレベル間の順位が入れ替わるほど揺れるため、
単発測定は使わず複数シード平均に統一した）。

| Lv | 平均ダメージ | 直前の節目からの伸び |
|---:|---:|---:|
| 45 | 7,965 | — |
| 50 | 16,739 | **+110%**（Lv46から装備が銀→金へ切り替わる節目） |
| 55 | 17,943 | +7% |
| 60 | 21,216 | +18%（凸3の適用込み。§4.2参照） |
| 65 | 21,987 | +4% |
| 145 | 142,166 | — |
| 150 | 155,097 | +9% |
| **160** | **156,748** | **+1%（ほぼ停止）** |
| 170 | 177,247 | +13% |
| 190 | 197,105 | (170から+11%) |
| 200 | 219,383 | +11% |
| 220 | 243,024 | (200から+11%) |
| 225 | 228,638 | −6%（振れ幅の範囲） |
| 240 | 239,952 | (225から+5%) |
| 255 | 248,759 | (240から+4%) |

**Lv150〜255の伸びは合計でも+60%程度**（105レベルぶん）で、Lv45→50の1段だけで
起きる+110%より緩い。特にLv150→160はほぼ横ばい。

**ただしこれは §1 の問題と地続きの疑いが強い。** この測定に使った想定ビルドは
Lv136相当（135SP）で投資先を使い切り、それ以降のレベルはSPを何にも使わずに
レベルアップしている。Lv150以降の伸びの鈍さが「ゲームの設計」なのか
「測定ツールがSPを使い切れていないアーティファクト」なのかは、
**今回の測定だけでは切り分けられない。** §1で259SP使い切り版を試したときは
Lv255で+0〜8%程度の差しか出なかった（§1参照）ので、伸びの鈍さの相当部分は
本物である可能性もある。**要再検証**：使い切り版のPRIORITYでLv150〜255の
曲線を測り直すこと。

### 4.2 レベルの節目との整合

装備枠・鍛冶・クラス・闘技場などの解禁レベル（Lv5/10/20/30/40/50/60、
出典: `docs/作業ログ/レベルの節目.md`）と、上のダメージ曲線を突き合わせると:

- **Lv50（鍛冶解禁）は強さの伸びとも一致している。** 装備箱が銀→金に切り替わる
  タイミングと重なり、+110%の最大の伸びがここに出た
- **Lv60（闘技場解禁）は、今回の測定条件では伸びの節目になっていない**
  （+18%はほぼ限界突破3凸の効果で、レベルそのものの伸びは緩い。§4.1参照）。
  ただし闘技場は「そこで測る」場所であって「そこで強くなる」場所ではないので、
  一致しなくても設計上は不自然ではない
- Lv30（クラス解禁）・Lv40（塔解禁）はダメージ曲線に直接现れない
  （クラス点はLv30時点でfloor(30/5)=6点しかなく、火力への寄与はまだ小さい）

### 4.3 限界突破（凸）の価値

**未測定。** `docs/強いビルドの組み方.md` §4.3 に「限界超越+96%が24SPで、上限に
当たっていないと1ダメージも変わらない」という実測があり、上限に当たり始める条件も
同ドキュメントに記載済み（固有バフを重ねる・大技を撃つ等）。凸そのもの
（`limitBreak` の値がSP total にどう効くか）を、レベル帯ごとに分けて測り直すことはしていない。
