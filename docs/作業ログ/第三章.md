**ブランチ**: `work/story-ch3`

## 何を作るか

第二章はシキの加入で終わっている。シキは主人公を **「管理者」** と呼び、
「ここに何人納めたか」を覚えていると言う。第三章はその中身を明かす章。

**筋**:
1. シキが「継承の座にはもう一段下がある」と言う（納められた側だから知っている）
2. 下層へ降りる。ここは機械しかいない
3. 索引の亡霊が納めた者の名を唱えている。読めない項目が一つある——**管理者本人**
4. 二番機ドゥオが道を塞ぐ。倒す
5. その奥に**零式の遺構兵装アストラ**。初代管理機ウーヌスが「渡す相手」を待って抱えていたもの
6. ウーヌスはさらに下にいる。今は届かない。アストラが加わって章が終わる

## なぜこの筋か

| シキ「ここに何人納めたか」を覚えている | 下層の存在を知っている理由 |

### アストラに入手経路が無かった

`ch_astra`（零式の遺構兵装、LEGEND、無属性）は
**ガチャにも他のどこにも載っていない孤立キャラ**だった。
第二章のシキと同じ「筋書加入」にすれば、経路が付いたうえに設定とも噛み合う。

### ウーヌスを倒させない理由

`bs_first_warden` は `fl_sealed`（敵150）のボス。ストーリーは Lv1 から始まる
別プロファイルなので、第三章の想定は Lv20〜30 前後。**同じ個体を二つの強さで出せない**。
下層の入口で引き返す形にすれば、終盤に `fl_sealed` へ行く動機がそのまま物語の続きになる。

## 途中で捕まえた不具合

**小部屋を壁で囲んでいた。** 最初のマップは

```
'#.####.......####..#'
'#.#..#.......#..#..#'   ← この行の小部屋に入口が無い
'#.####.......####..#'
```

の形で、`(3,3)` と `(16,9)` の小部屋が四方を壁に囲まれていた。
さらに `(16,3)` と `(16,9)` は**壁のマスの上にイベントを置いていた**。

検証テストの到達性検査が3件とも捕まえた。前回 `mp_vault` で

`#....#` の形に変えて左から入れるようにし、BFSで7イベント全部が届くことを確認した。

検証テストのブラウザ実行が `プロンプト: 全ての敵に個別の指定がある` で落ち続けたが、
**コードは正しく、原因は2段重ねのキャッシュだった。**

1. `localhost:8124` で動いているのは `python -m http.server`（`SimpleHTTP/0.6`）。
   `.claude/launch.json` に「キャッシュ無効化ヘッダを返さないため、直したJSが反映されない」と
   **警告が書いてあるそのもの**。素のURLは古い15391バイトを返し、
   `?cb=` を付けると新しい18199バイトが返る
2. `RPG.tests.runAsync()` は**結果を再計算しない**。
   `em_slime` を消しても結果が変わらないことで確認した。
   つまり画面に出ていたのは、ページ読み込み時点の古いデータで走った結果

node で同じ条件式を回すと `敵36 / プロンプト36 / 欠け0` で通る。

## 立ち絵

1体につき3枚生成して選んだ（計12枚）。取り込み→透過→メタデータ除去→WebP の順。
WebP化で 3.8MB → 0.3MB（92%減）。`publish_check` 問題なし。

透過は暗い衣装・白い衣装が食われやすいので、
黒漆の記録機と白地に銀の二番機を目視確認した。どちらも欠けなし。

### 分かったこと: `glowing eyes` が機械の指定と競合する

`base` の `subject` に **`glowing eyes`（複数形）** が入っている。
これが「単眼」「no eyes」「blank faceplate」といった機械向けの指定と正面から衝突する。

灯し番は3枚中**2枚が人間的な二つ目**になり、
`blank faceplate with a single soft amber lamp` が通ったのは1枚だけだった。
その1枚は指定どおりだが、頭部が潜水兜のようになって絵としては使いにくく、
結局「二つ目だが琥珀色に光る」枚を採用している。

二番機ドゥオの `no eyes` は通った（面頬に縦の継ぎ目のみ）。
指定の位置と強さ次第で通ったり通らなかったりする、という程度の競合。

**機械を足すときは、単眼にしたいなら `--negative-add "glowing eyes"` を検討すること。**
