# 画面の幅にまつわる3件 — 鍛冶の一覧・ビルドの残りSP・戦闘のHPバー

いまの状態: **3件とも直して検証済み。**

共通しているのは、**器の幅や高さを決めていないせいで、中身が勝手に場所を
決めてしまう**こと。1と2は狭い画面で「見るものと触るものが画面の外に離れる」
形で出た。3は逆にPCだけで出て、**札の数がHPバーの長さを決めてしまっていた**。

どれも目で見ると「少し広い」「少し下」に見えるだけなので、
**座標を数字で並べるまで原因にたどり着けない**。測り方は末尾にまとめてある。

## 1. 鍛冶 — 選んでも画面が変わらない

`.pane-split`（左に一覧・右にパネル）は 860px 以下で1列に落ちる。
すると一覧が上、鍛冶のパネルが下に積まれる。

実測（375px・**装備40個しかない状態**）:

| | 位置 |
|---|---|
| 画面の高さ | 812px |
| 一覧 | 121〜1076px |
| 鍛冶のパネル | **1100px から** |

つまり行を叩いてもパネルは画面の下 288px の外にあり、
**押した本人には何も起きていないように見える**。装備は数千個まで増えるので、
一覧が伸びるほどパネルは遠くなる。

### 直し方 — キャラ一覧と同じ「横から出る板」にした

パネルを常に画面の頭に置き、一覧は上に重なって開き、選べば閉じる。
下の内容は動かないので「選ぶ → 閉じる → さっき見ていた場所を探し直す」が起きない。

直したあと（同じ条件）: 選ぶボタン 121px ／ パネル **204px** ／ 文書全長 812px。
1件選んでもパネルは 300px で、**画面内に収まる**。

**スワイプの入口も揃えた。** キャラ一覧は左端スワイプで開けるのに
鍛冶だけ開けないと、画面ごとに操作が変わる。`installEdgeSwipe` を
「いま出ている板」を見て切り替える形にしてある。同時に2つ出る画面は無い。

板のCSSはキャラ一覧と共有している（`.char-body` / `.pick-body` を並記）。
**片方だけ直すと、もう片方が静かに取り残される**ので、
新しい板を足すときはセレクタを並記すること。

## 2. ビルド — 残りSPがツリーに入った瞬間に消える

`position: sticky` は**親の箱の中でしか効かない**。
残りSPは右の列 (`.col-far`) に置いてあったが、1199px 以下では
その列が先に積まれ、ツリー (`.col-mid`) は後ろに来る。

実測（375px・Lv1）:

| | 範囲 |
|---|---|
| `.col-far`（残りSPが居た列） | 269〜1315px |
| `.col-mid`（ツリー） | 1339〜3675px |
| 文書全長 | 3811px |

**文書の最初の3分の1しか追随せず、ツリーの 2,336px のあいだは丸ごと消えていた。**
いちばん残りSPを見たい場面——ノードを押しているあいだ——で見えない。

### 直し方 — 測る対象と同じ箱に入れた

`spBar()` として切り出し、`.col-mid` の先頭に置いた。
貼り付く位置は幅の帯ごとに変わるので、3帯すべてで確かめてある。

| 幅 | スクロールの器 | `top` | 実測 |
|---|---|---|---|
| ≤860px | 文書 | `--topbar-h` | y=1200 以降、文末まで上端 103px で固定 |
| 861〜1199px | `.col-main` | 0 | 送り900 以降、器の上端 86px で固定 |
| ≥1200px | `.col-mid` | 0 | 列を最下部まで送っても 86px のまま |

**列ごとにCSSを書き足すこと。** 書き漏らした帯では、貼り付く位置だけが
100px ほどずれる（上部バーの高さぶん浮く）という形で出る。

## 3. 戦闘 — バフが増えるとHPバーが伸びる（PC）

**HPバーの長さが、HP以外の理由で変わっていた。**

`.party-card` は `.party-row`（flex・折り返しあり）の子で、幅を決めていなかった。
札の行 (`.chips`) は `flex-wrap: wrap` だが、**折り返す先の幅が決まっていない**と
max-content ＝「全部の札が1行に並んだ幅」がそのままカードの幅になる。
つまり札が増えるほどカードが横へ伸び、中のHPバーも一緒に伸びる。
HPの数値は変わらないので、**減っていないのにバーだけ育つ**という形で出る。

実測（1400px・札を積んだとき）:

| 札の数 | カード幅 | HPバー幅 | 札の行数 |
|---|---|---|---|
| 0 | 210px | 106px | — |
| 6 | 337px | 233px | **1** |
| 12 | 577px | **473px** | **1** |

札の行数がずっと 1 のままなのが、折り返す先が無いことの証拠。

### 上限 (max-width) では足りない

最初 `max-width: 264px` を置いたが、**上限に達するまでは中身なり**なので、
札が2〜4個の範囲でバーが 106 → 160px と伸び続けた。同じ嘘が小さくなるだけ。
`width: 248px` で固定して、札は素直に段を増やす形にした。

直したあと（札 0〜14個）: カード幅 248px・**HPバー幅 144px で不動**。
高さだけが 90 → 180px に伸びる。4人並べても全員同じ幅で、
札の数がばらばら（2/4/6/8個）でもバーは揃う。

**敵カードは元から `width: 158px` で固定されていた。** 味方だけ抜けていた。
狭い画面側も `width: calc(50% - 4px)` ＋ 札を1段横送りで既に解決済みで、
**PCだけが穴だった**（151px・バー77px のまま変化なし）。

## 測るときの注意

- **`localStorage` には書かずに測った。** メモリ上の `RPG.state.get()` に
  装備を足して描画するだけなら、実データを壊さない。
  `RPG.gear.forge(spec, uid)` は乱数を使わないので条件を揃えやすい
  （`spec.base` は `RPG.data.equipBases` のキー。`roll` という関数は無い）
- **見た目ではなく座標で判定すること。** 「パネルが下にある」は目で見ても
  分かりにくい。`getBoundingClientRect().top + scrollY` と `innerHeight` を
  並べれば、画面の外に何px出ているかがそのまま出る
- **幅の不具合は、札の数を振って表にすること。** 1点だけ見ると「少し広いかな」で
  終わるが、0→12個と振れば線形に伸びているのがすぐ出る。
  折り返しの有無は `chips` の子の `top` を集合にすれば行数として数えられる
- テストページは `1566 / 1566`。**途中で読むと部分集計が出る**ので、
  非同期の検査が終わるまで待つこと（一度 1514 と読み違えた）
