# 支援・回復の【極】

**ブランチ**: `work/support-extremes`
**開始**: 2026-08-25

## 何を作るか

攻撃側に入れた【極】(§5.13) の支援版。**下位ロールごとに1つずつ**置く。

1枚にまとめると、必ずどれかの下位ロールが割を食う。
このゲームは既に 純ヒーラー / 神官戦士 / 反転 / 万軍 / 孤影 を作り分けてあるので、
それぞれに専用の終端を置けば全員に居場所ができ、
選択は「どの下位ロールに振り切るか」になる。

## 「与ダメージ上限を削る」を採らなかった理由

役としては噛み合うが、代償として機能しない。

- 上限は 500,000。ツリーのコメント自身が「Lv1〜100 の与ダメージは最大89,000で
  上限には遠く届かない」と書いている。**純ヒーラーは一生この線に触れない**ので、
  削っても支払っていることにならない（攻撃側の一閃で踏んだ「素直な上積み」と同じ失敗）
- 効かせようと `cap_break` を -0.8 まで下げると、今度は**神官戦士と反転が締め出される**
- 中間の設定が無い。削っている対象が純ヒーラーの通貨ではないため

なお `applyCap` は `cap = 500000 * (1 + capBreak)` なので、
`cap_break` に -1 以下を入れると上限が負になって壊れる。この道を採るなら防御が要る。

## 負値では組めなかった（2つ調べて両方だめ）

新しい仕組みを足さずに済ませたかったが、既存の値を負にする手は両方とも塞がっていた。

### 回復側: `heal_power` を下げると神官戦士の火力まで消える

`healPower` は `ctx.heal` にしか掛からず**リジェネには掛からない**ので、
一見「他人を癒せないが自分は保つ」を作れそうに見える。
しかし `heal_to_power` が `mult *= 1 + healToPower * healPower` の形なので、
`healPower` を下げると**神官戦士の火力そのものが消える**。二重の罰になる。

### バフ側: 負値は打ち消しではなく「上乗せ無し」にしかならない

`buffAmount` の最後が `return power > 0 ? value * (1 + power) : value;`。
`self_buff_power` に -1.0 を入れても **素の値のまま残る**。0にはならない。

## 足す仕組み（3つ）

`soloBuff`（孤影セットの代償側）と同じ形の遮断フラグ。
既存の `soloBuff` は `effectKeysSetOnly` にあり**装備セット専用**でツリーから使えないので、
battle.js が passives 側も読むようにしたうえで、ツリー用の種別を足す。

| 種別 | 何を遮断するか | 使うロール |
|---|---|---|
| `solo_buff` | 味方へのバフが通らない | 孤影 |
| `self_buff_lock` | 自分へのバフが通らない | 万軍 |
| `ally_heal_lock` | 味方を回復できない（自分は可） | 神官戦士・反転 |

## 最大の発見: オートが遮断された行動を無限に撃ち続けていた

**同じ構造の不具合が2つあった。** 遮断された効果は対象の状態を変えないので、
オートの判定が「まだ必要」を返し続け、**同じ手を毎ターン撃って手番を全部溶かす**。

| 場所 | 症状 |
|---|---|
| `autoplay.js` バフ選択 | 旗手を着けた支援が闘気集中を**10回**撃つ（土台は2回）。勝率 97% → 89% |
| `autoplay.js` 回復選択 | 「傷ついた味方がいる→回復→治らない」を繰り返す。神官戦士の勝率 99% → 88% |

これは【極】に限らない。**遮断系の効果を足すたびに同じ罠を踏む**ので、
今後この種の効果を作るときは必ずオート側も直すこと。

### 判別に `targetKind` を使って一度外した

最初 `targetKind(def) !== 'none'` で自分専用バフを判別しようとしたが、
`unique_buff` / `tag_buff` / `def_buff` は **どれも常に `'none'` を返す**ので
一度も引っかからなかった。実際の対象は `buffs.js` の
`resolveTargets`（`params.party ? allies() : [actor]`）が決めている。
**`params.party` を見るのが正しい。**

## `BUFF_POWER_CAP` が見返りを丸ごと潰していた

旗手の `ally_buff_power +140%` が **1ミリも効いていなかった**。
`buffAmount` の `Math.min(BUFF_POWER_CAP, ...)` に既に張り付いていたため。

上限は「全部足せば全部乗る」を止めるために置いてある。
【極】は代償を払って**その天井を破る**場所なので、`buff_cap` を足して
ここでだけ上限を動かせるようにした（号令側の上限も同じ値を見る）。

## 測り方を3回間違えた

数値そのものより、**測る相手を間違えていた**ことのほうが問題だった。

1. パーティ4人全員を支援にした → 誰も倒せず全構成 0%
2. 味方バフ型を測るのに、**全体バフ技を1つも持たないビルド**を使った
   → 味方バフ強化が乗る先が無く、旗手が負けて見えた
3. 神官戦士を測るのに、パーティに他の回復役がいない状態で
   「味方を回復できない」を着けた → 単に唯一の回復源を切っていただけ

## 最終的な効き（fl_sealed / 3種×24戦）

| ノード | 想定ビルド | 結果 |
|---|---|---|
| 献身 | 純ヒーラー | 勝率 97% → **100%**、R 3.09 → 2.93 |
| 旗手 | 万軍（全体バフ技あり） | R 2.32 → **1.71**（-26%） |
| 独尊 | 孤影（自己バフ） | R 3.09 → **2.51**（-19%） |
| 独行 | 神官戦士 | R 2.62 → **2.43**、勝率 99% → 94% |
| 灼身 | 反転 | R 2.62 → 2.60、勝率 99% → 97% |

**旗手と独尊は互いの逆になっている。** 味方バフ型に独尊を着けると
R 2.32 → 2.67 と悪化し、自己バフ型に旗手を着けても伸びない。
仕組みで縛らずに排他が成立している。

独行は勝率が5pt落ちてラウンドが縮む。パーティの回復役を失う代わりに
早く終わらせる、という取引になっている。

灼身はほぼ横ばい。見返り（`smite 0.9`）が弱い可能性があるが、
測るたびに前提を間違えてきた経緯があるので、**ここは断定せずに残す**。

## 追加した効果（4種・5ファイル8箇所）

| 種別 | 内容 |
|---|---|
| `solo_buff` | 味方へかけたバフが通らない（`uniq: null`。同名キーが装備セット専用側に既にあるため） |
| `self_buff_lock` | 自分へかけたバフが自分に乗らない |
| `ally_heal_lock` | 味方を回復できない（自分は可） |
| `buff_cap` | バフ効果量の上限を押し上げる |

遮断されたバフは**積まない・数えない**ようにしてある。
値0のまま積むとログに「+0%」が並ぶうえ、`countSupport()` が回って
「通らないバフを撒いて自分のバフだけ積む」抜け道になる（独尊は `support_stack` を持つ）。
