# 宝箱収入の底上げ（Lv130〜225 の谷）

## 何を直したか

推奨レベルで回したときの**1ラウンドあたりの総収入**が、封絶区画(130) から
創世の残響(150)・終わりなき回廊(200) にかけて下がっていた。
進むほど装備を仕上げるのが遅くなる、という逆転が起きていた。

| | 前 | 後 |
|---|---:|---:|
| 灰燼の果て 110 | 4,959 | 4,959 |
| 封絶区画 130 | 5,258 | 5,258 |
| 創世の残響 150 | **5,216** | 5,515 |
| 終わりなき回廊 200 | **4,375** | 6,474 |
| 臨界の際 225 | 5,739 | 6,931 |
| 還らぬ位相 250 | 9,678 | 9,678 |

## なぜ gold_mult ではないのか

逆算すると創世 0.42 ／ 回廊 0.68 ／ 臨界 0.63 が要り、直接ドロップが総収入の
49% ／ 62% ／ 61% を占める。**「主収入は宝箱の鑑定と売却」という判定と衝突する。**
足りないのは宝箱側なので、そちらを厚くした（結果、直接の比率はむしろ下がった）。

## なぜ敵の drops ではなくフィールド側なのか

**創世の残響と終わりなき回廊は、敵4体をそのまま共有している。**
敵を触ると必ず両方が動くので、片方だけ厚くする調整が書けない。
`box_mult` をフィールド側の調整つまみとして足した（`gold_mult` の宝箱版、既定 1.0）。

`battle.js` の抽選は、1回ぶんを超えたところを確定として数え、端数だけを抽選に回す。
**抽選の回数は倍率によらず drops の数と一致する**ので、乱数の並びは崩れない。

## 谷の正体

1周の総収入は前から単調に増えていた（11,392 → 16,452 → 16,825 → 23,414 → 29,841）。
増えていなかったのは**時間あたり**。創世(3.5ラウンド)・回廊(3.8) は封絶区画(2.3) より
1周が長く、勝率も 88% とこの2つだけ低い。**1周が重いぶんを収入が埋めていなかった。**

回廊だけ倍率が突出して要る（1.49）のは、常にパーティ+15レベルという設定の代償を
収入が払っていなかったため。いまは「常に格上な代わりに実入りが濃い」形になっている。

## 判定の測り方を直した

「3. 収益効率」にあった単調性の判定は**直接ドロップしか見ていなかった**。
それは総収入の 32〜56% でしかなく、宝箱側を厚くしても 1G も動かない。
つまり**正しく直しても落ちたままになる測り方**だった。

判定は「4. 経済バランス」へ移した（宝箱の期待額が手元にあるのはこちら）。
3 のほうには、直接ドロップだけで見ても絶対額が逆転していないかの確認を残した。

**落ちたから消したのではなく、測っている対象が実態とずれていたので直した。**
`totalPerRound` を `economy()` の返り値に足し、表にも「合計G/R」として出している。

## 測った値

- 検証テスト 1315 / 1315
- バランス検証 §3 §4 とも全項目 ✔
- 宝箱/周: 創世 17.3 → 23.0、回廊 17.0 → 25.5、臨界 22.3 → 26.4
- 直接の比率: 創世 39% → 34%、回廊 43% → 32%、臨界 46% → 41%

## 次に触るときの注意

- 上位フィールドの余裕は薄い。創世は手前を **4.9%** 上回っているだけ。
  戦闘の長さを変える調整（敵のHP・size・scaling）を入れたら必ず測り直すこと
- シミュレーションは種を固定しているので、同じ条件なら毎回同じ値が出る。
  数字が動いたら乱数の揺れではなく、実際に何かが変わっている
