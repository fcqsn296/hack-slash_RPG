# 装備の再抽選（星霜の欠片の使い道）

## なぜ作ったか

レベル上限を真の上限まで伸ばしきると、星霜の欠片の使い道が消える。
闘技場を強化して歯ごたえが出たぶん、周回の先に置くものが要る。

限界突破（レベル上限をさらに伸ばす）案は却下。
「ポイントが余りがちの軸」と「足りない軸」の差が開くため。

## 決めたこと

強化値は**必ず引き継ぐ**。引き継がないと「育ててから祈る」になり、
素体を選んでから育てるという順番が成立しない。

引き直し方は3つ。狙いを絞るほど欠片が安い。

| 操作 | 範囲 | 種類 | 欠片 | ゴールド |
|---|---|---|---|---|
| 厳選（既存） | 全部 | 引き直す | 0 | 等倍 |
| 選んだ枠を引き直す | 1つ | 引き直す | 2 | 半額 |
| 選んだ枠の値だけ | 1つ | 据え置き | 1 | 半額 |
| 全部の値だけ | 全部 | 据え置き | 2 | 等倍 |

**「宝箱を大量に開けて素体（副オプションの種類）を選んでから引き直すと欠片が節約できる」**
という向きに効かせている。種類を引き当てる仕事は宝箱に任せるほど安い。

「全部 × 種類ごと」は受け付けない。それは厳選（ゴールドのみ）の担当で、
両方に置くと欠片を払う意味が無くなる。

## 実装で必要になった作り替え

装備は**どの枠が何を引いたか**を持っていなかった。
`stats` / `tagBonuses` / `critRate` / `capBreak` / `reduction` / `affixLines` に
混ぜ込まれた**結果**しか残っておらず、1枠だけ差し替えられない。

`gear.js` に記録を足した。

- `item.mainStats` … 部位で決まる主ステータス（副オプションと強化を除いた素）
- `item.affixRolls` … `[{id, v}]`。引いた副オプションそのもの
- `applyAffixRolls(item, rolls)` … 上の2つから派生する値を**全部作り直す**

生成も再抽選もこの1つの関数を通る。二重に書くと必ずずれるため。

### 乱数の順番は変えていない

`identify()` の中身を組み替えたが、`weighted()` → `float()` の呼ぶ順番は
そのまま。ここがずれるとバランス実測の再現性が壊れる。

### 記録の無い装備

既存のセーブには `affixRolls` を持たない装備が入っている。
`affixRollsOf()` が `affixLines` の**名前**から引き当てる（副オプション名は一意）。

**値は表示文字列から読まない。** 割合系は小数1桁に丸めてあるので、
戻すと目減りする。装備側に残っている正確な値
（`tagBonuses[].value` / `critRate` / `capBreak` / `reduction`）から取り戻す。
平坦ステータスだけは floor 済みの整数なので表示から読んで差し支えない。

検証テストで「復元しても性能が変わらない」ことを確かめている。

## 途中で見つけた別の誤り

先に公開した図鑑の**「装備の理想値」が間違っていた**。

`stat_mult` がいちばん高い宝箱として **星辰の宝箱** を前提にしていたが、
星辰は `uniqueDropChance = 1.0` で **100% ユニーク装備**が出る。
ユニークは系統タグ倍率もクリティカルも上限突破も持たないので、
そこを前提にすると**一生届かない数字を目標として示す**ことになる。

前提を **竜の宝箱** に直し、住み分け（数字を極めるなら竜／戦い方を変えるなら星辰）を
本文に書いた。同じ間違いが再発しないよう、テストで
「前提の宝箱からは副オプション付きの装備が出る」ことを確かめている。
