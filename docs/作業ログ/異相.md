# 異相（フィールドに条件を重ねる）

拡張コンテンツ 提案A。既存フィールドに条件を重ねて、**同じ場所を別の戦いにする**。
新しい場所は作らない。増えるのは「どう組むか」の選択肢だけ。

## なぜこれをやるのか

ロードマップは「新フィールド・仲間の大量追加」を保留していて、再開条件を
**「既存12フィールド・60人を組み替える目的が決まる」** としている。
仲間は60人いるのに、最強の4人を組めばどこでも通るので残りに出番が無い。
異相は「ここではその4人が通らない」を作る装置で、まさにその目的にあたる。

**難度を上げる装置ではない。** 依頼書 §8 が終盤フィールドの高難度化を否定している
——オートで勝てなくすると、周回する人は手前のフィールドへ移るだけ。
だから元のフィールドの周回しやすさは一切変えない（選ばなければ従来どおり）。
ただし**相を選んだときは報酬が上がる**——当初「報酬も変えない」で作っていたが、
§8 の論理をそのまま当てれば、難しくて実入りが同じ選択肢は選ばれないだけ。

## 効かせている場所

| 効果 | どこで効くか |
|---|---|
| `denyElement` | `damage.js`（属性を NEUTRAL に均す）＋ `autoplay.js`（見積もりも同じ判定を読む） |
| `enemyFirst` | `battle.js` の開幕。**`nextWave` の後**に `enemiesAct` を呼ぶ |
| `allHit` | `enemiesAct` の対象を `stillAlive.slice()` にする |
| `targetRule` | `pickByRule` → `pickTarget` |
| `enemyScale` | `battle.enemyScale` の既定値として `aspect.def.enemyScale` を使う |

## 測って分かったこと

物差しは**終わりなき回廊・Lv255・10試行**（`_scratch/save_testbed_lv255.json`）。

### 単体で効くものは一つも無かった

| 試したもの | 結果 |
|---|---|
| 属性の否定だけ | 無風。素の与ダメが敵HPの9倍（413,952 対 44,400）あり、過剰殺傷に吸われる |
| 先制だけ | HP残 96% → 95% |
| 先制＋攻撃×2 | HP残 96% → 92%。勝率は100%のまま |
| 先制＋攻撃×3 | 勝率 70%。ただし**2人編成は攻撃×2 で既に40%** |

原因は **敵の攻撃力がパーティの強さではなく人数に対して効く**こと。
単体攻撃を厚くすると「4人には無風・2人には致命」に割れる。

### 全体攻撃は割れ方を消すが、中身は問わない

全体＋先制＋攻撃×2 で **4人 70% / 3人 70% / 2人 50%**。
人数による割れは消えたが、問うのは「全員が受けきれるか」だけ。

### 狙い方を固定すると、初めて編成の中身が問われる

| 相 | 編成 | 勝率 | HP残 | 倒れ |
|---|---|---|---|---|
| 弱きを選ぶ（先制・×3） | 庇う役なし | 70% | 68% | 1.3人 |
| | 庇う役あり | **100%** | 95% | 0.0人 |
| 硬きを試す（先制・×5） | タンクなし | 50% | 46% | 2.0人 |
| | 軽減+40%を1人 | **90%** | 67% | 1.2人 |

**これが狙っていた形。** 火力を足しても通らないが、連れて行く相手を変えれば通る。

「脆さ」は残HPの割合ではなく **実効耐久**（残HP ÷ 被ダメの通り具合）で見ている。
残HPだけで見ると、軽減を積んだ硬い役が「HPが減っている」だけで狙われ続け、
軽減への投資が裏目に出る。

## 踏んだ罠

- **先制が敵の出現より先に走っていた。** ログで「先を取られた」が「現れた」より
  前に出ていた。`nextWave(battle)` の**後**へ移した
- **戦闘ループを回さずにログを読んで「相が効いていない」と誤判定した。**
  `battle.start` だけ呼んでログを見ても何も起きていない。
  `commandSkill` を回すまで測ったことにならない
- **`RPG.codex.seen` という関数は存在しない**（実体は `fieldSeen`）。
  手前の `if (!RPG.codex.seen) return true` がそれを飲んでしまい、
  **解放条件が常に真**になっていた。無い関数を見たときの既定は
  「通す」でなく「閉じる」にする
- **`fieldSeen` は「出撃したか」で「抜けたか」ではない。** 負けても visits は進む。
  抜けたかはフィールドのボスの `killed` で見る
- `W.icon` の `size` は CSS の文字列。`16` を渡すと `fontSize: 16` で無効になる
- アイコンは CSS のマスクなので、**無い名前を書くと 404 して黙って消える**
  （アルカナで実際に `stat-spd` と書いていた）。テストで実在を固定した

| `as_deny_light` | 光を拒む相 | 光属性が常に等倍 |

| `as_omnipresent` | あまねく相 | 先制＋全体攻撃＋攻撃×2 |
| `as_cull_weak` | 弱きを選ぶ相 | 先制＋最も脆い者を狙い続ける＋攻撃×3 |

解放条件は **そのフィールドのボスを一度倒していること**。
抜ける前に選べると「難しいほうから入って詰まる」入口になる。

## 倍率を上げる案を測った結果、両方とも据え置き

どちらも「上げればもっと問える」と思っていたが、測ると逆だった。

### あまねく相は ×2 で止める

| 倍率 | 4人 | 3人 | 2人 |
|---|---|---|---|
| ×2 | 70% | 70% | 50% |
| ×2.5 | 40% | 30% | 20% |

**この相の価値は「人数で割れない」ことそのもの。**
×2.5 にすると 40/30/20 と再び人数に依存し始め、
2人は 20% で組む意味が消える。上げると作った目的が壊れる。

### 硬きを試す相は ×5 で止める

| 倍率 | タンクなし | 軽減+40%を1人 | 差 |
|---|---|---|---|
| ×5 | 50% / 倒れ2.0人 | 90% / 倒れ1.2人 | **40pt** |
| ×7 | 30% / 倒れ2.9人 | 50% / 倒れ2.5人 | 20pt |
| ×10 | 0% / 1.2R で全滅 | 30% / 倒れ3.4人 | 30pt |

**倍率を上げるほど編成の差が広がると思っていたが逆。**
×7 では両方が同じように破綻し、差が 40pt から 20pt に縮む。

×10 にはもう一つ発見があった。狙いが1人に固定されているのに
**4人全部が倒れる**（1.2R で全滅）。硬い役が死ぬと次に硬い者が
次の狙いになるので、上から順に崩れる。
`q_endless_vigil` のコメントが警告していた一撃死の二択そのもの。

## 報酬の上乗せ（難化の対価）

**当初「報酬は変えない」で作っていたが、これは設計の誤りだった。**
依頼書 §8 の論理をそのまま当てれば、難しくて実入りが同じ選択肢は
選ばれないだけで、置いてあることに意味がなくなる。

採った規則: **要求された組み替えをすれば、1ラウンドあたり素の約1.3倍**。
相ごとの倍率の差は好みでなく実測のラウンド比から出る。
ゴールド・経験値・宝箱すべて同率。

| 相 | 勝ちのR | 比 | rewardMult |
|---|---|---|---|
| 相なし | 6.00 | 1.00 | — |
| 闇/光を拒む | 6.00 | 1.00 | 1.30 |
| 先を取る | 6.07 | 1.01 | 1.30 |
| 弱きを選ぶ（庇う役） | 6.00 | 1.00 | 1.30 |
| あまねく（全員 軽減+25%） | 8.79 | 1.47 | 1.90 |
| 硬きを試す（受け役 +55%） | 9.03 | 1.51 | 1.95 |

### 校正の土台を三度間違えた

**ここは一本道ではなかった。三つの誤りを順に踏んでいる。**

1. **勝率10試行で決めた。** あまねく相を70%、硬きを試す相を90%と読んで
   倍率を決めたが、60試行では 33% と 72%。20〜30ポイント揺れる
2. **勝率で校正した。** 「1ラウンドあたりの期待ゴールド（負けを含む）」は
   もっともらしいが、負け分を報酬で埋める形になる。検証用の土台は
   実セーブより弱いので、その弱さのぶんを払うと実プレイのビルドには
   過大に払う。**上乗せが「弱いほど大きい」向きになり、逆立ちしている。**
   負けはビルドで解く側の問題
3. **平均のラウンド数を使った。** 負けた回は速く全滅するので、平均に混ぜると
   周回のラウンドを過小に見積もる。あまねく相は平均 7.55R だが
   勝った回だけなら 9.30R

正しい土台は **勝った回のラウンド数**。60試行で安定する。

### 宝箱を半分にする案は測って取り下げた

最初は `1 + (m-1)/2` にしていた。理屈は「宝箱は効きが長い」——装備になり、
強さになり、次の周回が速くなるので、ゴールドと同率は均等でないと考えた。

**測ったら持たなかった。** 1ラウンドあたりの宝箱が硬きを試す相で
**0.99倍**（つまり増えていない）、あまねく相で 1.09 倍。
半分にした上乗せが、増えたラウンドと勝率の損に食われて消える。
終盤の実入りの主役は装備の売却益なので、宝箱が増えないと上乗せが薄まる。

### 全体攻撃の相は、敵の倍率では調整できない

あまねく相の勝率を上げようとして敵の倍率を下げても、効率は上がらない。

| 倍率 | 勝率 | R |
|---|---|---|
| ×2 | 33% | 3.6 |
| ×1.8 | 37% | 3.6 |
| ×1.6 | 45% | 4.7 |
| ×1.4 | 50% | 6.1 |

（いずれも先制つきで測った値。軸を分けた後は先制が外れている）

全員が傷むので耐久と回復に手番が食われ、**勝率を上げるとラウンドが伸びる**。
この相の効率の床は構造的なもので、倍率では動かない。
だから調整の手は報酬の側にしかない。

## 相を重ねる

**軸を直交させてある。** 最初はあまねく・弱きを選ぶ・硬きを試すの3つが
`enemyFirst` を内蔵していた。そのまま重ねられると、「先を取る相」を足しても
**何も起きないのに報酬だけ +30% 乗る**。

| 軸 | 中身 | 排他の理由 |
|---|---|---|
| `element` | 闇を拒む / 光を拒む | 1属性しか NEUTRAL にできない |
| `tempo` | 先を取る | — |
| `aim` | あまねく / 弱きを選ぶ / 硬きを試す | 同時に成立しない（全体攻撃は狙いを消す） |

1軸につき1つ。`resolve` が1つの `effects` に畳むので、`battle.js` と
`damage.js` は重なりを知らないままでよい。敵の倍率も**加算**で畳む
（掛け算にすると ×2 と ×5 で ×10 になり、1.2R で全滅する二択になる）。

### 上乗せは基本分を一度だけ払う

素朴に足すと過払いになる。基本の +30% を相ごとに払ってしまうので、
ラウンド対価がゼロの相を足すだけで得をする。

    1 + BASE(0.30) + Σ(mᵢ - 1 - BASE) + STACK(0.05) × (n - 1)

実測した効率（1ラウンドあたりのゴールド、素 = 1.00、狙いは 1.30）:

| 組み合わせ | 素朴な加算 | 基本分を一度だけ | ＋重ね分 |
|---|---|---|---|
| 硬きを試す だけ | 1.30 | 1.30 | 1.30 |
| 闇＋硬きを試す | 1.50 | 1.30 | 1.33 |
| 闇＋先制＋硬きを試す | 1.61 | 1.23 | 1.29 |
| 闇＋先制＋あまねく | — | 1.22 | 1.28 |
| 闇＋先制＋弱きを選ぶ | 1.89 | 1.29 | 1.39 |

重ね分（1つあたり +5%）は風味ではなく、**重なったときに増える手番のぶん**。
安い相は単体ではラウンド対価がほぼゼロだが、高い相に重なると増える——
硬きを試す相単体の 9.03R に対し、闇＋先制を足すと 9.52R。
これを払わないと**重ねると損をする**形になる（効率 1.22〜1.23 まで落ちる）。

### 積みすぎると素を下回る。それが止めどころになる

負けた回まで含めた1ラウンドあたりの実入り（素 = 1.00）:

| 組み合わせ | 勝率 | 実入り |
|---|---|---|
| 闇＋硬きを試す | 100% | **1.33** |
| 闇＋先制＋硬きを試す | 87% | 1.20 |
| 闇＋先制＋弱きを選ぶ | 55% | 1.06 |
| 闇＋先制＋あまねく | 62% | **0.98**（素より悪い） |

上乗せは重ねるほど増えるが、勝てなくなると負けに食われる。
**「オートで回りきれるギリギリまで積む」が遊びとして成立する**のは
この形が作っている。全部乗せの突破もそのまま同じ器で遊べる。

## 事前の見当は出さない（決定済み）

**「この組み合わせで回りきれるか」を出撃前に示す機能は作らない。**

積んで入って確かめるしかない状態は不便に見えるが、これはこのゲームに
数少ないトライアンドエラーの要素で、意図して残している。
見当が出ると、積む行為そのものが計算作業に変わり、
**止めどころを探す遊びが消える**。

出撃前に読めるようにしてあるのは「何が起きるか」（相の効果と上乗せ）だけ。
「勝てるか」は戦って知る。この境目を動かさないこと。
