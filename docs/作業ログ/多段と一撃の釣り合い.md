# 多段と一撃の釣り合い（双撃の理を選択式にできるか）

ブランチ `work/支援の価値`。**まだゲームのファイルは変えていない。測っただけ。**

## 発端

手数（双撃の理＋双月の環×2）が全型に 2.4〜3.1倍 効き、**事実上の必須**になっている。
「双撃の理と排他の、上限突破＋火力上昇のパッシブを置いて選択式にする」案を測った。

## 測り方

ヴァルキュリア（大技型）・Lv255・同じSP（254）・同じ装備の骨格。
HPだけ2億にしたボス（DEFは素）へ当てて決着ラウンド。耐久は切り離し。
オート・6試行の中央値。

基準は **大技＋手数 = 16R**、**大技のみ = 49R**。

## 結果1: 上限突破だけでは全く届かない

| 一撃側に与えたもの | 決着R |
|---|---:|
| 上限突破 +2 / ATK +30% | 43R |
| 上限突破 +8 / ATK +50% | 35R |
| 上限突破 +12 / ATK +100% | 31R |

**上限突破は単独では効かない。** 内訳を見ると `capped = false`——
そもそも上限に一度も当たっていなかった。
`強いビルドの組み方.md` §8.1「上限に当たっていないのに上限突破を積む」を、
測っている側が踏んだ形。

## 結果2: 火力だけでも届かない

| 一撃側に与えたもの | 決着R |
|---|---:|
| 大技の火力 +100% | 42R |
| 大技の火力 +200% | 37R |
| 大技の火力 +300% | 34R |
| 大技の火力 +400% | 30R |

伸びが鈍い。火力を上げると今度は上限に当たり、**超過分は0.1倍に潰される**ため。

## 結果3: 組で振ると釣り合う

| 火力 | 上限突破 | 決着R |
|---:|---:|---:|
| +200% | +4 | 35R |
| +300% | +6 | 28R |
| +400% | +8 | 25R |
| +500% | +10 | 21R |
| +600% | +12 | 22R |
| **+800%** | **+16** | **16R** ← 多段と同じ |

**火力と上限突破は組でしか効かない。** 片方だけでは、上限に当たっていないか、
当たりすぎて潰されるかのどちらかになる。これはご提案どおりの構造だった。

## 分かったこと

多段が強いのは、**上限の下で回数を増やすから**。
1発を大きくする側は上限という壁に当たり、超えたぶんが1割に減らされる。
だから対抗するには「火力」と「壁を押し広げる」を同時に積む必要がある。

釣り合いの点は **火力+800% ／ 上限突破+16**。
双撃の理（8SP・ATK -30%）1本と釣り合わせるには、この数字が要る。

## 追記: 排他の仕組みも、選択そのものも既にあった

**クラスの派生が排他になっている**（`klass.js` の `branchAvailable`）。
実際 `bk_apex` を取ったあとに `bk_swarm` を取ろうとすると
「既に『極撃』を選んでいる」で弾かれる。

しかも破壊者の派生は、まさにこの選択そのものだった:

| 派生 | 説明 | 主な効果 |
|---|---|---|
| 極撃 `br_bk_apex` | 単体を貫く。**上限の壁を殴り抜く**ことに全部を寄せる | 大技の火力+80%、上限突破+60%、最大HP -50% |
| 殲滅 `br_bk_swarm` | 数を薙ぐ | 敵1体につき火力+18%、超過持ち越し50%、DEF -50% |
| 狂奔 `br_bk_frenzy` | 自らを削って撃つ | 瀕死で火力+90%、吸収25%、被ダメ+30% |

**「上限突破＋火力上昇」は極撃としてもう存在している。** 新しく足す必要は無い。

### 穴はここ

実データの主人公は**極撃を選びながら、双月の環×2＋双撃の理で多段3**にしている。
「単体を貫く」派生が、3回殴っている。
**排他はクラスの中でしか働かず、多段はその外側にある。**

実データの主人公・ボスHP2億で測った:

| 条件 | 決着R | 多段 |
|---|---:|---:|
| 極撃＋多段3（いまのまま） | **8R** | 3 |
| 極撃・双月のみ | 12R | 2 |
| 極撃・多段なし | **32R** | 0 |
| 殲滅＋多段3 | 35R | 3 |
| 殲滅・多段なし | 116R | 0 |

**多段は極撃を4倍にしている**（32R → 8R）。
そして**多段を極撃から外すと、極撃32R 対 殲滅＋多段35R でほぼ並ぶ。**
単体のボス相手でこの均衡なら、複数の敵がいる場面では殲滅が勝つ。
つまり「多段は殲滅側のもの」と決めるだけで、2つの派生が釣り合う。

### 影響

実データの主人公は 8R → 32R になる。**4倍の弱体化**。
既に極撃＋多段で組んでいる人には大きい。

## 決まった形: 極撃は双撃の理と排他、そのぶんを極撃に盛る

依頼側の案「双撃の理の1回分を補う程度に極撃を盛る」を実測した。
**装備の多段（双月の環）は残すので、極撃でも複数回は撃てる。**
ツリーの1回分だけを、派生の倍率に置き換える形。

実データの主人公・ボスHP2億:

| | 決着R |
|---|---:|
| いまのまま（極撃＋多段3） | 8R |
| 双撃の理を外す（多段2のまま） | **11R** ← 補う差はここ |
| 極撃 +120%/+90% にして多段2 | **8R** ← 一致 |
| 極撃 +160%/+120% | 8R |
| 極撃 +200%/+150% | 7R |

**現行 +80%/+60% を 1.5倍して +120%/+90% にすると、ちょうど元の強さに戻る。**

インフレも小さい。純粋な一撃型に寄せると 火力+800%／上限突破+16 が要ったのに対し、
装備の多段を残す形なら 1.5倍で足りる。

## 追記: 極撃を盛る案は取り下げ。原因は上限ではなく「代償の当たり先」だった

依頼側の指摘——**双撃の理は全クラスが取れるのに、代償を払うのは極撃だけになる**。
選択を迫られるのが破壊者/極撃の人だけで、他のクラスは無条件に多段を取り続ける。
そのとおりだったので、双撃の理そのものの値付けを測った。

### まず、いったん誤った結論を書いた

「代償をいくら重くしてもラウンドが動かない。ダメージ上限を超えているので
1発の値が変わらないからだ」と書いた。**これは間違い。**
`node` で `units.buildUnit` の中身を直接数えたら、別の原因が出た。

### 本当の原因は `units.js` の適用順

```
① 素のステータス × (1 + statPct)   ← 代償が効くのはここだけ
② ＋ 装備の平坦加算
③ ＋ 変換（DEFの280%をATKと魔力へ）
```

**`stat_pct` は素の値にしか掛からない。** 実データの主人公は
素のATK 2,543 に対して最終ATK 21,070。素は全体の12%しかない。
残りは装備と変換（DEFから30,153相当）で、そこには代償が届かない。

さらに主人公は `mirrorStat`（ATKと魔力を高い方へ揃える）を持つ。
代償は `atk` にしか書かれていないので、**魔力が床になって −30% より下は完全に無効**。

| 双撃の理の代償 | 主人公の最終ATK |
|---|---:|
| なし | 21,833 |
| ATK −30%（現行） | 21,070（−3.5%） |
| ATK −50% | 21,059（−3.5%） |
| ATK −80% | 21,059（−3.5%） |
| **ATK −100%** | **21,059（−3.5%）** |

**ATKを全部消しても3.5%しか減らない。**

### これは双撃の理だけの話ではない

クラス代償の無い骨格で、「−50%」と書いた代償が実際に何割削るかを測った:

| 書いた代償 | 実際（主人公） | 実際（ヴァルキュリア） |
|---|---:|---:|
| HP −50% | −40.5% | −39.9% |
| DEF −50% | −4.7% | −4.1% |
| ATK −50% | −3.5% | −7.5% |
| 魔力 −50% | **−0.0%** | −2.2% |

**HPだけが額面どおり働いている。** HPは装備でほとんど伸びないので素が支配的。
ATK・DEF・魔力は装備と変換で膨らむので、代償が薄まりきる。

ゲーム全体で `stat_pct` の代償は **21箇所**（ツリー6・クラス派生15）。
そのうちHPを削る7箇所だけが本物で、**残り14箇所はほぼ無償**。
【極】と名の付く、いちばん深くて高い節が軒並みこれに当たる。

### 依頼側の指摘は、思っていたより正しかった

- **極撃（HP −50%）は本物の代償を払っている**（実測 −40%）
- **双撃の理（ATK −30%）は実質 −2%**

不公平は既に存在していて、しかも**逆向き**だった。
極撃を盛れば、埋めるはずだった差をさらに広げていた。

### 直し方: 代償を「最終値」に効かせる

変換まで終えた値に代償を掛けるとどうなるかを実験した
（`_scratch/patched/units.js`。リポジトリ本体は触っていない）。

ボスHP2億・実データの主人公・単騎・31試行の中央値。
基準は **双撃の理なし（双月の環だけで多段2）= 12R**。

| 最終値への代償 | ATK | 決着R | 基準比 |
|---|---:|---:|---:|
| なし | 21,833 | 8R | ×1.50 |
| ATK・魔力 −15% | 18,558 | 9R | ×1.33 |
| ATK・魔力 −20% | 17,466 | 11R | ×1.09 |
| **ATK・魔力 −30%（＝いま書いてある値）** | 15,283 | **12R** | **×1.00** |

**書いてある「ATK −30%」が、そのまま正しい数字だった。**
最終値に効かせると平衡点にぴたり乗る。値を決め直す必要すらない。
効かせ先を直すだけで、双撃の理は必須ではなくなる。

しかも**全クラスが同じ代償を払う**ので、極撃だけが損をする形にならない。
同時に極撃側の HP −50% は「−40%」から「ちょうど −50%」になり、
額面どおりに軽くなる。**両方が同時に、書いてある意味に近づく。**

### もう一つのレバー（減衰）は効くが、副作用が広い

2発目以降の威力を減らす実験もした（`_scratch/patched/battle.js`）。

| 減衰 | 双撃なし | 双撃あり | 縮み方 |
|---|---:|---:|---:|
| ×1.00 | 11R | 9R | ×1.22 |
| ×0.85 | 12R | 11R | ×1.09 |
| ×0.60 | 17R | 15R | ×1.13 |

効きはするが、**多段を持つ全員が遅くなる**（終盤全体で1〜2割）。
代償の当たり先を直すほうが、副作用が小さく、しかも文言と実装が一致する。

### 実装した（2026-09-08）

代償専用の効果種 **`stat_cost`** を足し、ゲーム全体の代償21箇所を移した。
`stat_pct` はそのまま（上昇18箇所は素の値に掛かる。移すと変換後の値に +4% が
乗って膨らむため）。

#### 効かせる場所

`units.js` の2か所で使う。ステータスは互いの材料になるため。

```
① 変換は「代償を引いたあとの値」を材料として読む
    hpToAtk / hpToDef / defToAtk / atkToDef のソース
② 表示・計算に使う値は、最後にまとめて額面どおり引く
```

①が無いと「DEF -60%」がATKを一切減らさず、**変換型には無償の節**になる。
①で引いた材料から作られたぶんが②で改めて引かれるが、二重取りではない。
「材料が減ったので生まれる量も減り、その結果もさらに代償を負う」——
どちらもその代償が起こすべきことなので、両方が要る。

#### 移行の結果（実データの主人公の骨格・最終値の減り）

| 節 | 書いた代償 | 移行前 → 移行後 |
|---|---|---|
| 双撃の理 | ATK −20% | ATK −2% → **−20%** |
| 【極】一撃必倒 | HP −50% | HP −40% → **−50%** |
| 【極】不動の城塞 | ATK −50% | ATK −4% → **−50%** |
| 【極】必殺の理 | DEF −60% | ATK −9% → **−51%**（DEFは −60%） |

#### 値を変えた3箇所

- **双撃の理 −30% → −20%。** 額面どおり効かせると −30% はちょうど平衡点で、
  取っても取らなくても変わらない＝取る意味が消えた。−20% で概ね ×1.1
- **【極】一閃 −70% → −25%。** もともと「名目を膨らませて実効 −24% を作る」
  回避策で、desc にも但し書きが付いていた（`stat_pct は素のステータスにしか
  掛からず…` というコメントが残っていた）。薄まりが無くなったので、
  狙っていた実効をそのまま書く
- **【極】献身**の desc から「素の」を削除。同じ理由

#### 副作用として、狙っていた「選択肢」が出た

**【極】必殺の理**（会心+50%・倍率+1.2・DEF −60%）は、
DEFの代償が変換を通してATKにも効くようになった結果:

| | 12ラウンドの与ダメージ |
|---|---:|
| 変換を積んだビルド | **×0.88**（取ると損） |
| 変換を積まないビルド | **×1.15**（取る価値あり） |

**ビルドによって価値が反転する。** DEFの代償を持つ節は
「変換型にはなれない」という機会費用を持つ。
排他の仕組みを足さずに、選択が成立した。

#### 依頼の再調整

終盤ビルドが実際に弱くなったので「三で足りる」が3人で 3/6 しか通らなくなった。
敵倍率 20 → **14**（単騎 0/6・3人 5/6）。18 と 16 は閾値ちょうどで揺れる。

検証テスト **1417/1417**。本体でも双撃の理がちょうど ×0.800 になることを確認した。

#### 測るときの落とし穴（2つ踏んだ）

- **決着ラウンドは分散が大きすぎる。** 72R 帯で ±20R ぶれ、
  火力に関わる値が完全に同一の2条件が 54R と 73R になった。
  倒せないボスへ固定ラウンド殴って**与ダメージ合計**を見るほうが安定する
- **耐久を切り離すなら、HPは「行動を選ぶ前」に戻すこと。**
  後に戻すと、最大HPが低いビルドほどオートが防御的な技を選び、
  「HPの代償が火力を下げた」ように見える

**極撃を盛る案は取り下げる。** 症状のほうを触ることになり、
しかも指摘どおりクラス間の不公平が残る。

## 残っている実装上の判断

### 排他をどう表すか

ツリーのノードとクラスの派生をまたぐ排他になる。
`tree.js` の `canInvest` から `RPG.klass.chosenBranch(charSave)` を見る形が素直
（ノード側に `excludeBranch: 'br_bk_apex'` を持たせる）。

### 既に両方取っている人をどうするか

**ここが未決。** 実データの主人公がまさに極撃＋双撃の理で、
投資済みの効果はセーブに残っているので、投資を禁じるだけでは何も変わらない。

- **返す**: 移行処理で `tr_double` を払い戻す（SPが8戻る）。
  極撃の補強と合わせれば強さは変わらない（8R のまま）
- **据え置く**: 既存だけ両取りのままにする。新規は選択を迫られる。
  同じ構成が組めない不公平が残る

`CLAUDE.md` §7 のとおり、移行処理を書くなら**新規作成の初期形との整合**も要る。


数字は出たが、そのまま置くと**文言が異様**になる
（「大技の火力+800%、上限突破+16」）。取れる道は2つある。

### 案A 一撃側を釣り合う値で置く

提案どおり、双撃の理と排他のノードを新設する。
- 必要な値: 火力+800% ／ 上限突破+16 前後
- 排他の仕組みがツリーに無いので足す必要がある
  （`canInvest` は段位とSPしか見ていない。`excludes` を足す）
- **注意**: 双撃の理だけを排他にしても、双月の環×2 で多段は積める。
  「多段そのものを受け付けない」形にしないと選択にならない
  （支援の【極】が使っている遮断フラグと同じ作り）

### 案B 多段の側を軽くする

上限の下で回数が丸ごと効く、という構造そのものを緩める。
- 双撃の理の代償を重くする（いまは ATK -30%）
- あるいは多段の2発目以降に減衰を入れる
- **既に取っている人の強さが下がる**ので、影響は案Aより広い

## 追記: 測る帯を間違えていた

**ボスHPの上限は 500M** と既に決めてあった
（作業ログ「状態異常の素の値を投資前の値に置き直す」）。
上の測定は 2億で行っているので範囲内だが、
同じ日に別途 20億 でも測っており、**そちらは設計の外**だった。判断には使わない。

さらに、この日「発見」した「状態異常はHPに依らない／攻撃型は上限で頭打ち」は、
**作業ログ「状態異常の上限を起点の頻度で割る」で既に測られていた**。
そこには交差点が約1.5億であること、闘技場ハードの2億は既にそれを超えていること、
そして **「HPで壁を作るほど、この差は開く。ここは別途の判断待ち」** と書いてある。

つまり「終盤をぬるくないようにHPを上げる」は、**既に判断待ちとされた道**だった。
先に作業ログを読むべきだった。

## 訂正: 「排他を足さずに選択が成立した」は、難度の話ではなかった（2026-09-09）

公開後に指摘を受けた——**「双撃の理の排他が働いていない。代償だけだと変わらず単騎で余裕」**。

排他は**実装していない**（取り下げた）。指摘のとおり。
そのうえで「代償だけでは変わらない」も測って確かめた。**そのとおりだった。**

### 排他にしても効かない

実データの主人公・終わらぬ見張り（制限8R）・単騎・12試行:

| 条件 | 突破 | 決着 | 最低HP | ATK |
|---|---:|---:|---:|---:|
| いまのまま | 12/12 | 5R | **100%** | 17,466 |
| 双撃の理を外す（＝排他の効果） | 11/12 | 5R | **100%** | 21,833 |
| 装飾も外す（多段なし） | 10/12 | 5R | **100%** | 21,638 |
| さらに変換も外す | 8/12 | 5R | **100%** | 3,178 |

**ATKを1/7（3,178）まで落としても 8/12 で抜け、どの条件でも一度も削られない。**
排他にしても 12/12 → 11/12。**火力側のどんな代償も効かない。**

### なぜか: 敵が動く前に沈んでいる

敵は弱くない。`累ねの躯`（Lv270）の一番痛い技は主人公の**最大HPの21.6%**を削り、
6発で沈む。**その6発が一度も入らない。**

5ウェーブを5ラウンドで抜ける＝1ウェーブ1ラウンド。
主人公は敵の総HPの30倍近くを1手で出すので、敵に手番が回らない。

**したがって、敵の行動を強くしても効かない。** 実測:

| 敵の行動回数 | 突破 | 最低HP |
|---|---:|---:|
| ×1（いま） | 12/12 | 100% |
| ×2 | 11/12 | **100%** |
| ×3 | 12/12 | **100%** |

**動く前に沈むので、動きの強さは関係が無い。**
「敵の行動を強くするのが良い」という方針は、**敵が生き残る前提が要る**。

### 効くのは敵のHPだけ。境目は約20倍

| 敵のHP | 突破 | 最低HP |
|---|---:|---:|
| ×1・×5 | 11/12 | 100% |
| ×20 | 11/12 | **46%** ← ここで初めて敵が動く |
| ×50 | 0/12 | 32% |

**×20 でようやく手番が回り、×50 で壁になる。窓が狭い。**

### 依頼側で分けられる

終わらぬ見張りに `enemyScale` を入れると、単騎と4人を分けられる
（4人＝主人公・ゼロ・リコリス・エンバーに自動装備で配ったもの）。

| 敵倍率 | 単騎 | 4人 |
|---|---|---|
| ×1（いま） | 11/12・最低HP100% | 12/12・最低HP100% |
| **×10** | **5/12・最低HP0%** | 12/12・最低HP100% |
| ×15 | 2/12 | 12/12・最低HP90% |
| ×20 | 0/12 | 11/12・最低HP90% |
| ×25 | 0/12 | 7/12・最低HP69% |

- **×10** … 単騎は「たまに抜ける難所」になり、4人は余裕。単騎を禁じない
- **×20** … 単騎は不可能。4人は抜けるが削られる

`enemyScale` は **DEFにも掛かる**（`buildEnemyUnit` に渡している）ので、
倍率を上げると火力側の要求も同時に上がる。

### ここから言えること

`stat_cost` は**ビルドの選択**には効いた（節の価値がビルドで反転する）。
だが**難度には効いていない**。この2つを一緒くたに書いていたのが誤り。

終盤の難度は、火力側の代償では動かせない。
`保留中のアイデア.md`「終盤にオート用の張り合いが無い」に、
**余裕の大きさ（約20倍）と、敵の行動強化が効かない理由**が測定として加わった。
