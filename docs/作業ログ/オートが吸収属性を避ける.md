# オートが吸収属性を避ける

## いま何をしたか（完了）

検証テストで断続的に落ちていた「闘技場: 虹を喰らう獣 が決着する（3,800ラウンド）」を直した。
`work/オートが吸収属性を避ける` で作業。検証テスト 1395/1395、5回連続で本数も揺れない。

## 測って分かったこと

停滞の原因は**3つ**重なっていた。1つだと思って直すと直らない。

1. **オートの見積が吸収を知らなかった。**
   `autoplay.estimate` は素のダメージしか見ないので、一番よく喰われる技が
   「一番よく削れる技」に見える。実測: アルトの終焉(闇)が 2,993,184 を回復させ、
   シキが与えた 2,961,854 をそっくり打ち消していた（ボスHPは 2,163,216）。

2. **適応2は「等倍を選ぶ」という答えそのものを奪っていた。**
   `adapt >= 2` は全攻撃を有利化するので、どの属性で殴っても喰われる。
   通常（喰う割合1）では1点も通らない。実測: 全7属性で吸収率1.0。
   味方は maxHitRatio 0.32 で守られているので、**双方決着できない**。

3. **テストの編成が、遊ぶ人のセーブ次第だった。**
   コメントは「最大強化に近い編成」と謳っていたのに、コードは
   `RPG.state.get()` のままレベルだけ100に揃えていた。
   このセーブは4人中3人が適応2だったので停滞し、まっさらなセーブでは
   9ラウンドで負けて終わる。**同じコードが端末ごとに違う判定を出していた**。
   （b2267bf でも同じように再現するのはこのため。stat_cost とは無関係。）

## 直した中身

- `src/core/battle.js`: 吸収の判定を `absorbRatio()` に、属性の否定を
  `elementNulled()` に切り出して公開。オートが**同じ関数**を読む。写すと必ずずれる。
- `src/core/battle.js`: `ADAPT_ABSORB_CAP = 0.8`。適応2**だけ**で有利になっている
  攻撃は全部は喰わない。咎めは残る（有利1.5倍の2割＝実効0.3倍で、等倍1.0倍より損）。
- `src/core/autoplay.js`: `estimate(actor, target, skill, battle)`。吸収を織り込んで
  「相手のHPが実際に減る量」を返す。喰われる技は負の点になる。
  属性の否定も `damage.calc` に渡す。戦闘を渡さない呼び出しは従来どおり素の値。
- `test/tests.js`: 闘技場の編成を Lv255＋ツリー振り切りで**その場で組む**。乱数も止める。
  「勝てる」も判定する（`won` を数えていながら一度も使っていなかった）。
  検査本数をボス1体につき2本に固定（本数が実行ごとに 1,405/1,417 と揺れていた）。

## 残していること（直していない）

**弱すぎる編成は、いまも決着しない。** Lv100・ツリーまばら・装備なしの4人は、
回復役がボスの上限ダメージを上回って回復するので死なず、
ボス 2,163,216 に対して毎ラウンド20前後しか削れない（吸収の修正前は**ちょうど0**だった）。

これは属性吸収ではなく `maxHitRatio` と回復の釣り合いの問題で、闘技場全体の性質。
決着を保証する道具は既に `enrageRound`（data/arena.js）としてあるが、
虹を喰らう獣に付けるとボスの難度そのものが変わるので、指示なしには入れていない。
