# 「庇う」を、庇う役への攻撃として通し直す

## 何が起きていたか

肩代わりが**生のHP引き算**だった。

```js
const taken = Math.floor(result.damage * share);
result.damage -= taken;
guard.hp = Math.max(0, guard.hp - taken);   // ← ここ
```

引かれるのは「**庇われる側の防御で計算し終わったダメージ**」で、それを庇う役の
HPからそのまま引いていた。**庇う役の防御は1つも通らない。**

実測（同じ相手・同じ技）。

| 庇う役の軽減 | 肩代わり量 |
|---:|---:|
| 0% | 56 |
| 44% | 53 |

差は乱数ぶんで、**44%積んでも意味が無かった**。

通らなかったもの: 軽減・DEF・障壁・**棘**・**反射**・不屈・窮鼠・痛みの分配。

つまり「硬い人が前に出る」ではなく「誰でもいいから生で引き受ける」挙動で、
**硬いほど損をする**逆転が起きていた。タンクの鉄板行動が鉄板になっていない。
前に出る手段として実際に機能していたのは**狙われやすさ（taunt）だけ**だった。

`hurt()` は「HPを減らす唯一の口。ここを通さずにHPを書き換えないこと」と
明記してある関数なのに、ここだけがそれを迂回していたのも同じ原因による。

## どう直したか

肩代わりぶんを `powerScale` に share を掛けて `applyDamage` に通し直す。
既にあった仕組みなので、新しい経路は増やしていない。

```js
result.damage -= taken;
applyDamage(battle, attacker, guard, skill, Object.assign({}, opts, {
  guarded: true,
  powerScale: (opts.powerScale == null ? 1 : opts.powerScale) * share,
  crit: result.crit,
}));
```

- `guarded: true` … 庇う役をさらに庇う、の無限再帰を止める
- `crit: result.crit` … **同じ一撃**なので会心の有無を引き継ぐ。
  引き継がないと「初手必中」が庇うだけで2回消費される

## 直った結果（実測）

| 庇う役 | 肩代わり量 | 棘の返り |
|---|---:|---:|
| 軽減なし | 72 | 177 |
| 軽減44% | **42** | 194 |
| 軽減44%＋棘 | **40** | **1,462** |

ログも「イージス が シキ を庇った → イージス に 42 ダメージ（軽減44%）」と、
何が起きたか読める形になった。

## 影響範囲

- **バランス計測のフィールド結果は動かない。** `test/balance.js` の想定ビルド
  (`PRIORITY`) に `tr_guard_ally` が入っていないため。`tr_guard`（軽減）は
  入っているが、そちらは庇うとは別
- 闘技場は、庇うを積んだ編成だけ実質的な耐久が上がる。
  棘・反射との組み合わせは**火力にもなる**ので、そこは今後の測り直しが要る

## 残した既知の問題

**庇う役が2人いても最初の1人しか働かない**（`battle.party.find(...)`）。
1行で直せるが、今回は「一度に1つだけ変える」を守って触っていない。
