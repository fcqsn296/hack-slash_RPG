# ゴールドでレベルを上げる

## なぜ

経験値は**出撃した4人にしか入らない**。キャラクターが増えるほど、
新しく加わった1人を今の水準まで連れて行く周回が積み上がる。

実際に渡されたエンドゲームのセーブを見ると、

| セーブ | 編成 |
|---|---|
| party.json | 主人公 **255** / ゼロ 171 / エンバー 222 / ヴァルキュリア 171 |
| party2.json | 主人公 **255** / ルーナ 71 / エレナ 71 / ブランカ 71 |

主人公だけが上限で、仲間は 80〜180 レベル遅れている。
ここへ支援3・会心3・中技4の**10人を足した**ので、放っておくと悪化する一方だった。

## 相場の決め方

周回を実測すると、**1人が経験値を1得るあいだにパーティへ入るゴールドは約0.22**
（複数のフィールドで 0.220 / 0.237 と安定していた。フィールドの
`gold_mult` と `exp_mult` の比で決まる）。

同額にすると「戦っても買っても同じ」になるので **2倍の 0.44 G/経験値**。
周回のほうが明確に得で、ゴールドは「余ったぶんで遅れを取り戻す」道になる。

| | 必要経験値 | 費用 |
|---|---|---|
| Lv71 → 255 | 18.4M | 8,077,048 G |
| Lv171 → 255 | 12.0M | 5,277,110 G |
| 1レベル（Lv150付近） | — | 37,752 G |

## 買える上限

**レベル上限まで自由に買える。** 到達済みレベルで縛る案も出したが、
上限そのものが星霜の欠片でしか伸びない以上、闘技場を回す往復は
この仕組みでは短絡しない。そのため縛らない形を選んだ。

なお副作用として、**ゴールドが余っている終盤では経験値を稼ぐ理由がほぼ消える**。
これは承知のうえでの選択。

## 作り

  RPG.state.GOLD_PER_EXP   相場（0.44）
  RPG.state.levelUpCost()  見積もり。半端な経験値を差し引く
  RPG.state.buyLevels()    実行

**貯まっている半端な経験値は代金から引く。** 1経験値足りないだけで満額を
払わされると、戦ってから買うのが損になってしまう。引いたぶんは `exp = 0` に
してある（持ち越すと二重取りになる）。

画面はビルドのキャラ見出しの直下。`+1` / `+10` / `上限まで` の3つで、
10レベル以上まとめるときだけ確認を挟む。

## 見張り

「周回のほうが得」は相場が逆転した瞬間に崩れるので、
`GOLD_PER_EXP > 0.22` を検証テストで見張っている。
図鑑の本文に書いた数値も実装の定数と突き合わせている。

検証テスト 1237/1237。
