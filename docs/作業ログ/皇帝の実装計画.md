# 皇帝 IV — 実装計画

`docs/皇帝の実装案.md`（仕様）を、いまのコードに突き合わせた実装手順。
**まだ1行も書いていない。** 着手前に決めることが3つある（末尾）。

## 1. いま `commandSkill` が抱えているもの

1つの関数が9つの仕事をしている。皇帝は「実行」と「手番の終わり」を**別の人物で**回す必要があるので、まずここを割る。

| 順 | 仕事 | 皇帝ではどちらの持ち物か |
|---|---|---|
| 1 | `skillReady` の検査 | **受け手** |
| 2 | 入力の計上（手動ボーナス §10.1） | 1回だけ（命令1つ＝1回） |
| 3 | `startCooldown` | **受け手** |
| 4 | 麻痺の判定 | **皇帝**（失敗したら受け手は動かない） |
| 5 | `executeSkill` | **受け手** |
| 6 | 魔術師の配り（`weaveGifts`） | **受け手** |
| 7 | 死の刻み（`tickFinal`） | **要決定**（下の§6） |
| 8 | 制圧の判定（`checkWaveCleared`） | 共通 |
| 9 | 再行動の連鎖 → `actorIndex` を進める → 敵フェーズ | **皇帝** |

> **順番に理由がある。** いま 3（クールダウン）が 4（麻痺）より前にあるのは
> 「麻痺で飛んでもクールダウンは進む＝大技持ちほど損」という意図的な作り (§5.8)。
> 割るときにここを入れ替えないこと。

## 2. 割り方

関数を3つにする。**通常経路の挙動は1ミリも変えない。**

```
commandSkill(battle, skillId, targets, opts)      ← 既存の入口。そのまま残す
  = command(battle, { kind: 'skill', skillId, targets }, opts)

commandDecree(battle, toKey, skillId, targets, opts)   ← 皇帝の入口
  = command(battle, { kind: 'decree', toKey, skillId, targets }, opts)

command(battle, cmd, opts)
  ├ kind==='skill'  → performAction(actor, …) → finishTurn(actor)
  └ kind==='decree' → 適格性の再検査
                      → 皇帝の麻痺判定
                      → battle.decree = { byKey, toKey }
                      → performAction(受け手, …)
                      → battle.decree = null
                      → finishTurn(皇帝)

performAction(battle, unit, skillId, targets)   … 上の 1・3・5・6・7
finishTurn(battle, unit)                        … 上の 8・9
```

既存の呼び出し口（`src/ui/battle.js` 3か所、`src/core/dispatch.js`、
`test/sim.node.js`、`test/balance.js` 3か所、`test/builds.js`）は
`commandSkill` のまま動く。**互換を壊さないことが、この割り方の唯一の条件。**

## 3. 命令中であることの持ち方

```js
battle.decree = { byKey: '皇帝のkey', toKey: '受け手のkey' } | null
```

### セーブにも、UIの状態にもしない

**命令は `command()` の中で始まって中で終わる。** 手動の選択（命令先 → 技 → 対象）は
UI側が溜め込み、揃ってから `commandDecree` を1回呼ぶ。
だから `battle.decree` が生きているのは**同期実行の一瞬だけ**で、
`skipDeadActors` も `runEnemyPhase` も UI の描画もこれを跨がない。

仕様書 §85 の「`currentActor` は命令中だけ受け手を返す」はこれで満たせる。
`actorIndex` は皇帝を指したまま動かさない。

### `executeSkill` は actor を引数で受ける

`executeSkill(battle, actor, skillId, targets)` なので、受け手をそのまま渡せる。
`currentActor` に依存していないことは確認済み。

## 4. 再行動を発生させない箇所（洗い出し済み）

仕様書は「消してから取り消す方式は使わない」と明記している。
**生む前に止める。** 止める場所は3つ。

| 場所 | 何 | 対応 |
|---|---|---|
| `battle.js:2713` | 連鎖する死（撃破で再行動） | `battle.decree` があるとき発火させない |
| `battle.js:3324` | 段の出口（コンボで再行動） | 同上 |
| `battle.js:3157` | 前借り（`borrowTurn`） | **技の選択ごと禁じる**（下） |

一方、**皇帝の手番終わりに走る3つはそのまま**。`finishTurn(皇帝)` が
`actor` として皇帝を受けるので、書き換え不要。

| 場所 | 何 |
|---|---|
| `battle.js:3544` | 戦車の `turnGift` |
| `battle.js:3556` | 奇襲 |
| `battle.js:3565` | 再行動（`extraActionRate`） |

### 手番を生む技は選ばせない

`plugin` で見分けられる。

| plugin | 技 |
|---|---|
| `mass_extra` | 継ぐ手・鼓舞の一声・総駆けの合図・刻の号令 |
| `borrow_turn` | 影渡り・刻の前借り |
| `mass_revive` | 還りの祈り・再臨の光（`params.actNow` のときだけ） |

判定を1つの述語に集約する（`grantsTurn(skill)`）。
**自動選択と実行時の両方で見る**——片方だけだと、外から `commandDecree` を
直接叩かれた経路で漏れる。

## 5. 適格な命令先

> 自分以外・生存・皇帝ではない・**命令中に使える合法な技と対象の組み合わせが1つ以上ある**

「1つ以上ある」の判定は、既存の `skillReady` と対象探索をそのまま使う。
**候補を調べるだけで乱数も状態も動かしてはいけない**（仕様書 §33）ので、
`skillReady` が乱数を引かないことを先に確かめる。
——現状は引いていない（解禁ラウンド・クールダウン・連打禁止の3つだけ）。
麻痺の確率判定は `commandSkill` 側にあるので、候補判定には混ざらない。

除外しないもの: 再行動上限に達している／主力技がクールダウン中／麻痺を持っている。
除外するもの: 反動（`stunnedRounds`）・手番の負債（`turnDebt`）・
吊るされた男の縛りで動けない番。**これらは `skipDeadActors` が持っている条件**なので、
そこから判定だけを切り出して共有する（二重に書かない）。

## 6. 着手前に決めること

### 決定1: 死（XIII）の終止符を、皇帝の命令は消費するか

仕様書は「実行した技を刻限へ計上」とだけ書いてあり、**皇帝側が不明**。

- **消費する** … 皇帝が死を着けても手番の総量は誤魔化せない。整合的
- **消費しない** … 「技を使っていない」という理屈は通るが、
  **死＋皇帝で代償を踏み倒せる**。死の代償は「行動回数」なので、
  ここを抜くと札そのものが壊れる

実測で、死の代償が効いているのは「回数は装備で埋められない」から。
**消費する側を推す。**

### 決定2: オートの命令先は「編成順の先頭」でよいか

仕様書は「編成順で最初の適格者」。実装は簡単だが、実測で分かっているとおり
**編成の並び順で誰が動くかが大きく変わる**（主人公を先頭にすると行動 5.7回、
3番目だと 3.1回）。先頭が支援役の編成だと、皇帝が延々と支援役に譲ることになる。

- 仕様どおり編成順にする（単純・予測可能）
- または「自分以外で最も与ダメージ期待の高い味方」に渡す（オートの既存の技選択を流用）

**まず仕様どおりに作って測る**のが良いと考える。ここは数字が出てから決めたい。

### 決定3: 皇帝が2人以上いる編成を許すか

仕様書は「他の皇帝へ命令不可」なので、皇帝2人なら互いに命令できず、
**両方とも通常行動に戻る**（利も害も消える）。
採否条件にも「皇帝2〜3人で主力1人へ集中する編成が支配しないこと」とある。

この規則だと集中自体が起きないので、条件は自動的に満たされる。
**規則をこのまま採るかどうか**だけ確認したい。

## 8. 測り方（このセッションで確立した手順を使う）

`docs/アルカナの作り方.md` の「測り方」に沿う。皇帝で特に気をつける点：

- **周回では差が出ない。** 終盤は1ウェーブ1ラウンドの床に張り付くので、
  手番を誰に渡しても結果が変わらない。**相を重ねた場と闘技場で測る**
- **闘技場ハードは敵を倒せなくして測る**（`e.maxHp = 1e15`）。
  そうしないと味方の火力で押し切って耐久も手数も見えない
- **物差しの編成はSP残りを確認する。** 未育成の味方に渡して「皇帝は弱い」と
  誤読した前例がある（アストラ141/259・テオドラ259/259が未使用だった）
- 記録する値: 通算ラウンド・実行技回数・命令回数・本人行動回数・勝敗。
  **命令1回と技1回を二重に数えない**

## 9. 予想される落とし穴

このセッションで実際に踏んだものと同型のもの。

- **ウェーブが1ラウンドで終わると家事が走らない。** 命令状態の後始末を
  `endOfRound` にだけ置くと、周回で一度も走らない（戦車の立ち上がりで踏んだ）
- **`return` すると後続が飛ぶ。** `performAction` の途中で早期 return すると
  出血・棘・反撃が落ちる（死の実装で踏んだ）
- **旗を `passives` に置いただけでは damage.js に届かない。**
  届き先の確認を効果種の登録と同時にやる（手引きの5ファイル7箇所）
- **オートは `skillReady` で候補を絞る。** 禁止を `skillReady` に入れれば
  オート側は自動的に従う（魔術師の連打禁止がそうだった）。
  逆に言えば、`skillReady` の外に禁止を書くとオートだけ素通りする
