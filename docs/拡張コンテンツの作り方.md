# 拡張コンテンツの作り方

このゲーム（灰銀の継承者）に、キャラクター・技・ユニーク装備・敵・スキルツリーの枝を
**既存のファイルを一切変更せずに** 足すための手順書です。

作業者はこの文書だけを読んで進められます。分からない値が出てきたら、
推測せずに「調べ方」の節にある方法で実際の値を確認してください。

---

## 0. 最初に守ること

**`data/` `src/` `test/` `index.html` `styles.css` を書き換えてはいけません。**

追加するものは全部 `content/` の中の新しいファイルに書きます。
これは行儀の問題ではなく、事故の切り分けのためです。
コアに直接足すと、差分の中で「足した行」と「壊した行」が混ざり、
何が原因で崩れたのかが後から追えなくなります。
拡張ファイルなら、おかしくなったときにそのファイルを消すだけで元に戻ります。

例外は1つだけ。**立ち絵を入れたあとに `tools/detect_faces.py` が
顔の位置を書き戻す** 処理は、拡張ファイルのほうへ書き込みます（自動）。

---

## 1. 作業の流れ

```
1. content/ に新しい .js を作る            ← 手で書く
2. python tools/sync_content.py --apply    ← 読み込みリストへ登録（自動）
3. test/index.html を開いて全件合格を確認   ← ここで弾かれたら 1 へ戻る
4. 絵を作る（必要なら）
5. python tools/import_images.py           ← 絵をゲームへ入れる
6. 動作を確認して報告
```

3 で弾かれた場合、**その拡張は丸ごと取り込まれません**。
半分だけ入ると参照切れのまま遊べてしまい、落ちる場所と原因の場所が
離れて追えなくなるためです。他の拡張は巻き込まれません。

---

## 2. ファイルの置き方

`content/` に、内容が分かる名前で `.js` を1つ作ります。

```
content/yoiyami.js        ← 「宵闇編」のキャラと技をまとめたもの
content/moon_gear.js      ← 月がテーマのユニーク装備だけ
```

- 1つのファイルに何種類混ぜても構いません。テーマでまとめるのが読みやすいです。
- **ファイル名が `_` で始まるものは読み込まれません。** 下書き置き場として使えます。
- `content/_example.js` は書き方の見本です。**書き換えないでください。**
  真似するときはコピーして別の名前を付けます。

ファイルの中身は、次の形ちょうど1つです。

```js
RPG.content.add('拡張の名前', {
  skills: { … },
  characters: { … },
  enemies: { … },
  bosses: { … },
  uniques: { … },
  treeNodes: [ … ],
  fields: { … },
});
```

- `'拡張の名前'` は日本語で構いません。**エラーに出る名前** なので、
  どのファイルの話か分かるものにしてください。
- 使わない種類は書かなくて構いません。
- ここに無い名前（`monsters` など）を書くと **取り込みを断られます**。
  書いたのに何も起きない状態を作らないためです。

登録したら必ず実行します。

```bash
python tools/sync_content.py --apply
```

これが `index.html` と3つのテストページへ読み込み行を足します。
手で `<script>` を書き足さないでください。書き忘れると
「本編では動くのにテストだけ落ちる」という追いにくい形で出ます。

## 3. ID の付け方

| 種類 | 頭 | 例 |
|---|---|---|
| 技 | `sk_` | `sk_yo_moonfall` |
| キャラクター | `ch_` | `ch_yo_luna` |
| 敵（雑魚） | `em_` | `em_yo_shade` |
| 敵（ボス） | `bs_` | `bs_yo_eclipse` |
| ユニーク装備 | `uq_` | `uq_yo_moonveil` |
| ツリーのノード | `tr_` | `tr_yo_moonlight` |
| フィールド | `fl_` | `fl_yo_valley` |

- 頭が違うと取り込みを断られます。参照先を取り違えたときに一目で分かるようにするためです。
- **拡張ごとに2〜3文字の印を挟んでください**（上の例では `yo`）。
  別々の拡張で同じIDを付けるとぶつかり、後から読まれたほうが弾かれます。
- 既にコアにあるIDは使えません。**上書きは禁止です。**
  コアの数値を拡張が黙って差し替えると、バランスを測り直したときに
  「直したはずの値」が効いていない事態になります。

## 4. 種類ごとの書き方

### 4.1 技（skills）

```js
skills: {
  sk_yo_moonfall: {
    name: '月墜とし',            // 必須
    kind: 'active',              // 必須。'active' のみ
    plugin: 'multi_hit',         // 挙動。下の一覧から選ぶ
    scaling_stat: 'atk',         // 'atk' か 'magi_power'
    damage_type: 'phys',         // 'phys' | 'magi' | 'reli'
    element: 'dark',             // 属性。下の一覧から
    power: 70,                   // 威力%。100 が「攻撃力ぶん」
    crit_rate: 0.08,             // 会心率 0〜1
    params: { hits: 3 },         // plugin ごとの設定
    desc: '闇属性の3連撃。',      // 画面に出る説明
  },
},
```

**plugin に書けるもの**（`src/plugins/` にあるものだけ。新設は不可）

| plugin | すること | params |
|---|---|---|
| （書かない） | 単体を1回殴るだけ | — |
| `multi_hit` | 単体に多段 | `hits` |
| `all_enemies` | 敵全体 | `hits`（省略可） |
| `poison` | 殴ってから毒を付ける | `turns`, `ratio` |
| `status` | 殴ってから異常を付ける | `status` か `statuses`, `turns`, `ratio`, `all`, `lasting` |
| `multi_debuff` | 複数の弱体を同時に | `turns`, `defIgnore`, `poison`, `statuses` |
| `detonate` | 毒と火傷を現金化する | `all`（全体化） |
| `def_ignore` | 防御を無視して殴る | `turns` |
| `heal` | 回復（量は技の `power` から） | `party` |
| `unique_buff` | 固有バフ（別枠で乗算） | `value`, `turns`, `label`, `party` |
| `tag_buff` | 系統タグの倍率を上げる | `value`, `turns`, `label`, `tag`, `party` |
| `def_buff` | 防御を上げる | `value`, `turns`, `label`, `party` |
| `reduction_buff` | 被ダメージ軽減 | `value`, `turns`, `label`, `party` |
| `lifesteal_hit` | 与えたぶん吸う | `ratio` |
| `hp_cost` | HPを払って威力を上げる | `costRatio`, `perHp`, `maxBonus` |
| `vengeance` | 削られているほど強い | `perHit`, `maxBonus` |
| `mass_revive` | 全体蘇生 | `hp`, `healRatio`, `actNow` |
| `mass_extra` | 全員に追加行動 | `buff`, `turns`, `resetCooldowns` |
| `full_burst` | 手持ちの技を順に撃つ | `ratio`, `maxStun` |
| `barrier` | HPの外側に障壁を張る | `ratio`, `scaling`, `party` |
| `pandemic` | 弱体を他の敵へ写す | `turns`（省略時は元の残りを引き継ぐ） |
| `chain_burst` | 敵から敵へ跳ねながら殴る | `chains`, `decay` または `bonus` |
| `charge_strike` | 溜めて次の一撃を強くする | `ratio`, `critRate`, `capBreak` |
| `combo_finish` | コンボを使い切って一撃に変える | `perCombo`, `maxRatio`, `consume` |
| `counter_stance` | 構えて、殴られたら必ず反撃する | `turns`, `reduction`, `counterSkill` |
| `mark` | 敵に照準を付け、味方全員の火力を上げる | `value`, `turns`, `label`, `all` |
| `sigil_strike` | 刻印を刻む。3つ溜まると弾ける | `ratio`, `count` |
| `borrow_turn` | いま再行動する代わりに次のラウンドを失う | `rounds`, `powerScale` |
| `self_curse` | 自分に弱体を受け入れてから殴る | `statuses`, `turns`, `ratio` |

**後半6つの使いどころ**（Lv255・火力型で実測した倍率。通常攻撃を1とする）

| plugin | 実測 | 注意 |
|---|---|---|
| `barrier` | 魔力の `ratio` 倍を吸う | 回復と違いHP満タンでも無駄にならない。時間では消えない |
| `pandemic` | — | 1体に盛ってから全体へ配る。起爆と繋ぐと大きい |
| `chain_burst` | 4段合計で 1.5倍 | 敵が2〜3体のときに山が来る。1体でも空振りしない |
| `charge_strike` | 2手番で 5.6倍（1手番あたり 2.8倍） | **cooldown を必ず付けてください。** 無いと溜めと攻撃の往復が最適解になります |
| `combo_finish` | 5段で 5.3倍 | コンボはパーティ共有。撃つと味方全員の底上げが消えます |
| `counter_stance` | 反撃は確定 | 殴られる回数が読める場面でだけ強い、という形にしてあります |

比較のため、クラス技「終焉の一撃」は同条件で通常攻撃の **10倍**（3ラウンド目以降・CD4）です。
これを超える技は作らないでください。

**バフは3つに分かれています。** ファイルは `buffs.js` 1つですが、
`buffs` という plugin 名はありません。上の3つから選んでください。

params の名前は `src/plugins/<plugin名>.js` の冒頭コメントに書いてあります。
**知らない params を書いても無視されるだけ** なので、必ずそちらで確かめてください。
plugin 名そのものの綴り違いは取り込みの検査で弾かれます。

**状態異常の種類**（`status` / `multi_debuff` で指定する）

| kind | 効くタイミング | ratio の意味 |
|---|---|---|
| `poison` | ラウンド終了時 | 最大HPに対する割合 |
| `burn` | 攻撃技を使うたび | 最大HPに対する割合 |
| `bleed` | 被弾するたび | 受けたダメージに対する割合 |
| `paralyze` | 行動時 | 行動できない確率 |
| `freeze` | 被弾時 | 受けるダメージの増加率 |
| `curse` | 回復時 | 回復量の減少率 |

6種は **効くタイミングが全部ずれている** ので、どれを撒くかがそのまま
戦い方の選択になります。「毒の色違い」を足さないでください。

**属性**: `none` `fire` `water` `wind` `earth` `light` `dark`
相性は 火→風→土→水→火 の循環と、光↔闇の相互。有利で1.5倍、不利で0.5倍。

**威力の目安**（同レベルの敵に対して）

| 帯 | 威力 | 役割 |
|---|---|---|
| 小技 | 〜80 | 手数。パッシブで底上げされる |
| 中技 | 90〜190 | 弱体を通す・コンボを繋ぐ |
| 大技 | 200〜 | 一撃で沈める。上限減衰を受ける |

### 4.2 キャラクター（characters）

```js
characters: {
  ch_yo_luna: {
    name: 'ルナ',                        // 必須
    title: '月影の狩人',                  // 肩書き
    rarity: 'SUPER_RARE',                // 必須。COMMON | RARE | SUPER_RARE | LEGEND
    element: 'dark',                     // 必須
    base:   { hp: 700, atk: 120, def: 48, magi_power: 70 },   // 必須。Lv1 の値
    growth: { hp: 48, atk: 8.4, def: 3.1, magi_power: 5.0 },  // 必須。1レベルごとの上昇
    unique_skills: ['sk_yo_moonfall'],   // このキャラ専用の技
    common_skills: ['sk_slash'],         // 共通技。既存のIDでよい
    color: '#8f7fd8', accent: '#1d1730', glyph: '月',
    art: { … },                          // 4.7 を参照
    artPrompt: '…',                      // 4.8 を参照
  },
},
```

`unique_skills` / `common_skills` に書いたIDは、**コアか同じ拡張の中に
実在しなければなりません。** 無いIDを書くと取り込みを断られます。

**レアリティごとの強さ**（Lv100 での hp+atk+def+魔力 の合計。コアの実測値）

| レアリティ | 体数 | 最小 | 中央 | 最大 | 排出率 |
|---|---|---|---|---|---|
| COMMON | 5 | 5,700 | 6,783 | 8,543 | 60% |
| RARE | 5 | 6,477 | 7,204 | 11,102 | 30% |
| SUPER_RARE | 4 | 6,447 | 6,867 | 7,419 | 8.5% |
| LEGEND | 21 | 7,239 | 8,008 | 13,699 | 1.5% |

**素の数値はレアリティに比例していません。** SUPER_RARE の中央値は
COMMON とほとんど同じで、レアリティの差は主に固有技とパッシブで付いています。
数値を盛って格を出そうとせず、**中央値に寄せたうえで技で差を付けて** ください。

**レアリティは世界設定に結び付いています。**
`docs/灰銀の継承者 世界設定素案2.md` を参照してください。要点だけ書くと——

- レアリティの高さは **エーテルにどれだけ侵食されているか** を表します。
  強さと佇まいの際立ちは、どちらも同じ1つの度合いから来ています
- **低レアの新顔は、設定上は出にくい**（淡い記録から先に失われているため）。
  COMMON や RARE を足すこと自体は自由ですが、
  **なぜその記録が残っていたのか** を一言添えられると噛み合います
- 侵食が浅い＝目立たない、という関係があります。
  低レアに派手な見た目を与えると、設定と逆を向きます

作業後は「6. 調べ方」のコードで測り直し、自分の追加が中央値から
どれだけ離れているかを報告してください。

### 4.3 敵（enemies / bosses）

```js
enemies: {
  em_yo_shade: {
    name: '宵の影',                       // 必須
    element: 'dark',                     // 必須
    base:   { hp: 500, atk: 80, def: 24, magi_power: 53 },
    growth: { hp: 65, atk: 7.1, def: 2.4, magi_power: 4.4 },
    skills: ['sk_enemy_bite'],
    gold: 14, exp: 12,
    drops: [{ box: 'box_bronze', chance: 0.5, count: 1 }],
    color: '#6fb7ff', glyph: '影',
  },
},
bosses: {
  bs_yo_eclipse: {
    name: '蝕の主', element: 'dark', boss: true,
    // 以下 enemies と同じ
  },
},
```

宝箱のID: `box_bronze` `box_silver` `box_gold` `box_dragon` `box_astral`

**足した敵は、既存のフィールドには出ません。** コアの編成は変更できないためです。
出したい場合は、次の 4.4 で **フィールドごと足してください**。

### 4.4 フィールド（fields）

足した敵を出す場所。**敵だけ足しても既存のフィールドには出ない**ので、
戦わせたいならここまで書きます。

```js
fields: {
  fl_yo_valley: {
    name: '宵闇の谷',                     // 必須
    rec_level: 40,                       // 必須。推奨レベル
    enemy_lv: 44,                        // 必須。出る敵のレベル
    size: [2, 3],                        // 必須。1ウェーブの敵数 [最小, 最大]
    pool: ['em_yo_shade', 'em_wisp'],    // 必須。通常ウェーブの敵（既存IDも可）
    boss: 'bs_yo_eclipse',               // 必須。最終ウェーブの敵
    gold_mult: 0.9,                      // 必須。ゴールドの調整つまみ
    exp_mult: 1.1,                       // 必須。経験値の調整つまみ
    bg: ['#2a2438', '#100d18'],          // 背景のグラデーション（省略可）
    desc: '宵闇が溜まる谷。',              // 必須
  },
},
```

- `pool` と `boss` は**実在する敵ID** でなければ取り込まれません。
  ここが抜けると「入ったのに戦闘が始まらないフィールド」になります。
- `size` は `[最小, 最大]`。逆にすると断られます。
- `enemy_lv` が `rec_level` から極端に離れていると断られます（0.5〜3倍が許容）。
- 一覧は**推奨レベル順**に並びます。宣言順ではありません。

**背景画像**を置く場合は `assets/bg/<フィールドID>.webp`。
無くても成立します（背景が敷かれないだけ）。作り方は
`python tools/make_backdrop.py <元画像> fl_yo_valley`。

#### 経済の調整つまみ（gold_mult / exp_mult）

**ここが一番難しく、テストで落ちやすい場所です。**

`test/balance.html` が、全フィールドを推奨レベル順に並べて次を検査します。

| 検査 | 意味 |
|---|---|
| 1ラウンドあたりの収益が単調増加 | 深いほど効率が良い＝進む動機がある |
| 1周の総収入が単調増加 | 同上 |
| 14周以内で1レベル上がる | 育成が止まらない |
| 2周未満では上がらない | 育成が一瞬で終わらない |
| ガチャ25回以下/レベル | ゴールドが余りすぎない |

**あなたのフィールドは、前後のフィールドの間に収まる必要があります。**
落ちた場合、表とverdictに `（拡張: パック名）` と出るので、どれが原因か分かります。

調整は数値をいじって `test/balance.html` を開き直す、の繰り返しになります。
効くのは4つです。

| 動かすもの | 効き方 |
|---|---|
| `gold_mult` | 直接ドロップのゴールド。1周・1ラウンドの両方に効く |
| 敵の `exp` | 1レベルに何周かかるか |
| 敵の `drops` の箱の種類と数 | 総収入の主。**1周の総収入はほぼこれで決まる** |
| `size` と敵のHP | 戦闘の長さ。1ラウンドあたりの値に効く |

> **1ラウンドの収益は足りているのに1周の総収入が足りない**、というときは、
> 戦闘が短く終わっています。`size` を増やすか敵を硬くしてください。

### 4.5 ユニーク装備（uniques）

```js
uniques: {
  uq_yo_moonveil: {
    name: '月帳',                         // 必須
    base: 'eq_relic_mail',               // 必須。下の一覧から
    desc: '月の光でできた薄い帳。',        // 必須
    color: '#8f7fd8',
    stats: { def: 120, hp: 700 },        // 素の数値の上乗せ
    effects: { guardAlly: 0.2 },         // 特殊効果。下の一覧から
    note: '味方をかばう +20%',            // 効果の要約（画面に出る）
  },
},
```

**base に書けるもの**

| ID | 名前 | 部位 | 系統 |
|---|---|---|---|
| `eq_longsword` | 長剣 | 武器 | 物理 |
| `eq_greataxe` | 大斧 | 武器 | 物理 |
| `eq_rod` | 杖 | 武器 | 魔術 |
| `eq_grimoire` | 魔導書 | 武器 | 魔術 |
| `eq_relic_claw` | 遺物の爪 | 武器 | 遺物 |
| `eq_plate` | 板金鎧 | 防具 | 物理 |
| `eq_robe` | 法衣 | 防具 | 魔術 |
| `eq_relic_mail` | 古代の鎖帷子 | 防具 | 遺物 |
| `eq_ring` | 闘士の指輪 | 装飾 | 物理 |
| `eq_amulet` | 賢者の護符 | 装飾 | 魔術 |
| `eq_relic_core` | 遺物のコア | 装飾 | 遺物 |
| `eq_relic_seal` | 封印の紋章 | 装飾 | 遺物 |

**effects に書けるキー**

ここが一番間違えやすい場所です。**一覧に無いキーを書くと、装備しても
何も起きません。** エラーも警告も出ないので、書いた側は効いているつもりで
先へ進んでしまいます。そのため取り込みの検査で弾くようにしてあります。

| キー | 意味 |
|---|---|
| `midPowerStatus` | 中技で弱体を付ける確率が上がる |
| `midPowerCombo` | 中技でコンボが多く積む |
| `hpToDef` | 最大HPの割合をDEFへ上乗せ |
| `guardAlly` | 味方をかばう |
| `buffPower` | 自分がかけるバフの効果量が増える |
| `taunt` | 敵に狙われやすくなる |

### 4.6 スキルツリーのノード（treeNodes）

**配列** です。他と違ってオブジェクトではありません。

```js
treeNodes: [
  {
    id: 'tr_yo_moonlight',               // 必須
    tier: 'mid',                         // 必須。'basic' | 'mid' | 'high'
    name: '月光の心得',                   // 必須
    cost: 3,                             // 必須。1レベルあたりの消費SP
    maxLevel: 4,                         // 必須
    effects: [{ kind: 'tag_bonus', tag: 'relic', value: 0.12 }],  // 必須
    desc: '[遺物]系統の倍率 +12%',        // 必須
  },
],
```

- `tier` の解放条件: 中級は初級に5レベル、上級は初級＋中級に10レベル。
- `effects` の `kind` は **コアが解釈できる107種のどれか** でなければなりません。
  新しい種別は拡張から足せません（畳み込みの処理がコア側にあるため）。
  一覧は `RPG.tree.KNOWN_EFFECT_KINDS` で確認できます。
- よく使うもの:

| kind | 追加で要る項目 | 意味 |
|---|---|---|
| `stat_pct` | `stat`, `value` | 基礎ステータスの割合上昇 |
| `tag_bonus` | `tag`, `value` | 系統タグ倍率（`phys` / `magi` / `reli`） |
| `crit` | `value` | 会心率 |
| `crit_damage` | `value` | 会心倍率 |
| `reduction` | `value` | 被ダメージ軽減 |
| `grant_skill` | `skill`, `value: 1` | 技を習得する |
| `cap_break` | `value` | ダメージ上限の突破 |

- **SPの費用対効果**: 1SPあたり実効火力 +2〜3% が目安です。
  極端に効率のよい枝を1つ置くと、他の枝が全部死にます。

**綴りの罠**: 遺物系統は `reli` です。`relic` と書いてもどの装備とも
一致せず、倍率が1のまま黙って終わります。この文書を書いたときにも
実際に間違えました。属性・プラグイン名も同じで、綴りを間違えると
エラーではなく「何も起きない」という形で出ます。
これらは取り込みの検査で弾くようにしてありますが、まず一覧から写してください。

### 4.7 アートの指定（art）

立ち絵を用意する前でも、この指定から代用のSVGが自動生成されます。
**全項目を埋めてください。** 1つでも欠けると色が抜けたまま表示されます。

```js
art: {
  gender: 'female',        // 'male' | 'female'
  hair: 'long',            // long | twin | bob | ponytail | hime | wavy | crop
  expression: 'cool',      // calm | gentle | fierce | cool | smug
  accessory: 'circlet',    // ribbon | halo | horn | visor | hairpin | circlet | none
  hairColor: '#c9b6f2', hairLight: '#e8ddff', hairDark: '#6a5a90',
  eye: '#8f7fd8', eyeLight: '#d8ccff',
  outfit: '#2a2340', outfitLight: '#3d3358', outfitTrim: '#c9b6f2',
  accentColor: '#8f7fd8',
  // face は書かない。立ち絵を入れたあと tools/detect_faces.py が自動で入れる。
},
```

### 4.8 生成プロンプト（artPrompt）

キャラや敵の定義の中に `artPrompt` を書くと、画像生成ツールがそれを使います。

```js
artPrompt: 'silver-purple long hair, violet eyes, dark hunter coat, '
  + 'crescent moon circlet, calm confident expression',
```

**書くのは「その対象だけの特徴」です。** 画質・構図・背景・主語（1girl など）は
土台のほうに入っていて自動で足されるので、ここには書かないでください。
重ねて書くと指示がぶつかって絵が崩れます。

- 英語のタグを `, ` で区切って並べます。
- 髪・目・服・小物・表情の順に書くと安定します。
- 実在の作品名・作家名は書かないでください（公開物に残ると問題になります）。

組み上がった全文は次で確認できます。

```bash
python tools/novelai_gen.py ch_yo_luna --dry-run
```

## 5. 絵を用意する

**画像生成には課金の伴うAPIを使います。指示が無ければ実行しないでください。**
プロンプトを用意するところまでが担当です。

生成する場合（依頼されたときだけ）:

```bash
python tools/novelai_gen.py ch_yo_luna --dry-run   # 送る文字列だけ確認
python tools/novelai_gen.py ch_yo_luna             # 実際に生成
```

- 環境変数 `NOVELAI_API_TOKEN` が要ります。**キーを会話やファイルに書かないでください。**
- リクエストは1件ずつ、間隔をあけて送られます。この間隔を縮めないでください。

手元に画像がある場合の取り込み:

```bash
python tools/import_images.py       # 対話で選ぶ
```

取り込むと、背景の透過・顔の位置の計測・生成メタデータの除去まで行われます。
顔の位置は **その対象を定義しているファイル**（＝あなたが作った拡張ファイル）に
書き戻されます。

## 6. 調べ方

推測で書かず、実際の値を見てください。ブラウザで `index.html` を開き、
開発者ツールのコンソールで次を実行します。

```js
// 拡張がちゃんと入ったか。弾かれた理由もここに出る
RPG.content.result

// あるIDがどの拡張のものか
RPG.content.ownerOf('ch_yo_luna')

// 書ける効果キー・効果種別の一覧
RPG.units.UNIQUE_EFFECT_KEYS
RPG.tree.KNOWN_EFFECT_KINDS

// 既存キャラの強さと比べる（Lv100 の合計）
Object.keys(RPG.data.characters).map(function (id) {
  var c = RPG.data.characters[id];
  var t = ['hp', 'atk', 'def', 'magi_power'].reduce(function (s, k) {
    return s + c.base[k] + c.growth[k] * 99;
  }, 0);
  return c.rarity + ' ' + c.name + ' ' + Math.round(t);
}).sort();

// 1発のダメージを実測する
RPG.damage.calc({
  attacker: RPG.units.toAttacker(RPG.units.buildCharacterUnit(
    RPG.state.get().characters.ch_hero, RPG.state.get().inventory)),
  defender: RPG.autoequip.referenceDefender(100),
  skill: RPG.data.skills.sk_yo_moonfall,
  options: { random: 1.0, crit: false },
}).damage
```

- `data/` `src/` `test/` `index.html` `styles.css` を書き換える
- コアにあるIDを再定義する（上書きは禁止）

- 指示なく画像生成を実行する
