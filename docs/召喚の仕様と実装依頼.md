# 召喚の仕様と実装依頼

作成日: 2026-09-21
対象: 灰銀の継承者 / hakusura-rpg
状態: 実装担当への設計資料。召喚の実装・互換性検証・バランス実測は未実施。

## 依頼の目的

戦闘中に一時的な味方を追加できる「召喚」を共通機能として用意する。
最初の利用候補は、アルカナ「悪魔 XV」による戦闘開始時の悪魔召喚。
悪魔固有のHP共有と召喚の基本動作を分け、別の召喚を追加する際にも利用できる構造にする。

既存の戦闘規則との整合性確認、実装可能性の検証、必要な実装とテストは実装担当が行う。
この文書は動作確認済みの仕様書ではない。確認前に「既存処理で問題なく動く」と扱わないこと。

## 合意した範囲と、本書の提案の区別

### 合意済み

- 一時的に味方が増え、召喚された存在も戦う仕組みを検討する。
- 悪魔のアルカナより先に、召喚そのものの仕様を整理する。
- 既存規則の成立確認と検証は実装担当へ任せる。
- 悪魔の構想は「戦闘開始時に悪魔を召喚し、本人とHPを共有する」。全体攻撃では両者への被害が共有HPへ入る。

### 本書の推奨初期仕様

以下は実装担当が確認・検証する初期案。ユーザーが個別に確定した事項と混同しない。
内部構造や関数名は既存実装に合わせて担当が決めてよい。
既存の遊び方を変える変更や推奨仕様からの大きな逸脱が必要な場合は、根拠と代案を整理して確認する。
通常の実装判断のたびに確認を求める必要はない。

## 召喚の基本仕様

| 項目 | 推奨初期仕様 |
|---|---|
| 所属 | 戦闘内の味方ユニット。通常の所持キャラクターとは区別する |
| 編成枠 | 通常の出撃枠を消費しない |
| 保存 | 所持一覧・育成・装備・通常セーブへ加えない。戦闘中断保存の有無と対応は担当が確認 |
| 識別 | 召喚定義ID、戦闘内の一意なID、召喚者IDを持つ |
| 能力 | 召喚定義と召喚時の召喚者から生成。引継ぐ値を明記し、全パッシブを暗黙に複製しない |
| 装備・クラス・アルカナ | 通常キャラの装備枠等は持たない。必要な技と効果を召喚定義から与える |
| 技 | 固有の技一覧を持つ |
| 操作 | 初版は自動行動。手動戦闘中でも召喚体自身の技入力は要求しない |
| 行動順 | 原則として召喚者の通常手番の後。召喚者の再行動のたびに無条件で追従しない |
| 基本手番 | 原則1ラウンド1回。追加行動との関係は後述の適用表を確認 |
| 敵の対象 | 通常の攻撃対象候補となり、全体攻撃も受ける |
| 味方の支援 | 回復・障壁・バフ・庇い等の対象になることを基本にする |
| HP0 | 召喚体は退場する。初版は通常の蘇生対象にしない |
| 召喚者死亡 | 初版は配下の召喚体も退場する |
| 戦闘終了 | 勝利・敗北・撤退のすべてで消滅する |

自動行動の演出、ログ、処理待ちは既存の戦闘進行に接続する。描画のたびに行動したり、手動画面を開いただけで乱数が進んだりしないこと。
召喚体の行動はプレイヤーの手動入力回数に加算しない。手動報酬の分母への影響も検証し、召喚しただけで手動プレイの報酬が変わらない扱いを推奨する。

## 数・登場・持続の制限

- 初版は召喚者1人につき同時に1体、パーティ全体で最大4体を仮上限とする。性能・画面・行動量を検証して確定する。
- 上限到達時は追加召喚を行わない。無言で別の召喚を消したり、既存召喚のHPや持続を回復したりしない。
- 同じ召喚者の同じ召喚が残っている場合、再生成しない。
- 召喚体はさらに召喚しない。初版では再帰召喚を対象外とする。
- 初版の登場経路は戦闘開始時召喚。将来の戦闘中召喚を妨げない入口にするが、召喚技・解放コンテンツの追加まで一括で行わない。
- 初版の持続は戦闘終了まで。一定ラウンドで消える召喚は後続の拡張とする。
- 初版ではウェーブ間で生存個体を維持し、召喚し直さない。死亡個体も次ウェーブで自動再召喚しない。
- ウェーブ間でHP・状態異常・CTをどう更新するかは、通常仲間の処理を確認して明示する。「維持する」を無条件全回復として実装しない。
- 開幕召喚は先制する敵行動より前に配置する案とする。出現直後から攻撃対象・被害対象になる。
- 開幕支援が召喚体へ届くかを含め、ユニット生成・開幕効果・先制攻撃の順序を検証前に確定する。

## 「出撃した仲間」と「戦場の味方」を分ける

既存の party 配列へ追加するだけで、全用途の人数判定へ混ぜないこと。
配列を物理的に分けるか、区分付きで扱うかは担当が決める。重要なのは用途別の意味を保つこと。

| 判定・効果 | 推奨する対象 |
|---|---|
| 出撃人数制限、出撃レベル・属性条件 | 通常の出撃メンバー。召喚体を後から数えて失格にしない |
| 単騎・少人数による編成条件 | 原則として通常の出撃メンバー。召喚で強くなる相乗効果は実測する |
| 全員生存の依頼 | 初版は通常の出撃メンバー。召喚体の退場だけでは失格にしない |
| 全滅・敗北 | 通常の出撃メンバーが全滅したら敗北。召喚体だけで継続しない |
| 敵の単体・全体攻撃 | 戦場の味方。召喚体も含む |
| 回復・障壁・全体バフ | 原則として戦場の味方。召喚体も含む |
| 死者数を参照する効果 | 初版は通常の出撃メンバー。召喚消滅で稼がせない |
| 経験値・好感度・育成対象 | 通常の出撃メンバーのみ |
| 敵レベルの編成参照 | 原則として通常の出撃メンバー。召喚で敵が再スケールしない |
| 撃破報酬 | 召喚体が倒した敵も通常どおり1回だけ支給 |

既存の人数依存式・生存者集計・報酬配分をすべて検索し、この表にない用途も洗い出す。
人数が増えれば敵の単体攻撃が分散するため、召喚の価値は与ダメージ増加だけではない。

## 他の効果との関係

### 初版の推奨

- 召喚体への追加行動付与は通常ユニットと同じ規則で扱い、召喚体自身にも独立した上限を持たせる。
- 皇帝の命令先には召喚体も含める案とする。皇帝側の最新仕様に従い、借りた手番から追加行動を増殖させない。
- 召喚体の反射・棘・回復などは、明示的に与えた効果だけが働く。召喚者の効果を理由なく起動しない。
- 戦闘外の装備変更等で、既に召喚済みの能力を自動再構築しない。初版は召喚時に基礎能力を確定し、戦闘中のバフ等は通常どおり適用する。
- 召喚体が召喚者のアルカナをコピーすることはない。

### 実装担当が確認する対象

号令、皇帝、庇い・肩代わり、反射・棘・反撃、吸収回復、全体回復、障壁、常時支援、状態異常、反動、蘇生、死亡時効果、単騎効果、全員生存、敵の先制・全体化、ウェーブ移行。
恋人・正義などの最新の実装状況も確認し、同時進行の変更に合わせる。
未実装の組み合わせは未確認と記録し、存在しない機能を検査済みにしない。

## 悪魔固有のHP共有は第二段階

召喚の基礎は独立HPの召喚体で確認する。悪魔のHP共有を初期検証の前提にしない。
将来の悪魔では、本人と召喚体が一つのHPを参照する形を候補にする。相互ダメージ転送の再帰で表現しない。

- 両者への全体攻撃は2体分の被害になる。防御条件が同じ場合に2倍となるのであり、固定の被ダメージ2倍補正とは違う。
- HP共有は能力や全パッシブの共有を意味しない。
- 共通の最大HP、回復の集計、全体回復が2回入るか、致死防止、復活、悪魔の退場後の扱いは、悪魔の仕様で別途確定する。
- 基礎側は、後からHPの参照方法や退場処理を拡張できる境界を設ける。未使用の共有HP処理を先に大量に実装しない。

## 実装担当への手順

### 1. 確認 — 変更前に読む・調べる

1. `CLAUDE.md`、`docs/知見の索引.md`、関連の知見元、最新の戦闘・ユニット・UI・オート・測定コードを読む。
2. 作業ツリーと進行中の変更を確認し、他の作業を上書きしない。
3. 味方配列、行動順、対象選択、開幕・死亡・ウェーブ移行・終了処理、人数条件、報酬・セーブへの参照を洗い出す。
4. 本書の初期仕様について、実装可能なもの、既存規則と衝突するもの、未確認を整理する。
5. 変更箇所と実装単位を、作業ログ `docs/作業ログ/召喚の実装.md` にまとめる。

確認の成果物: 適用表、実装箇所一覧、未確定事項、既存変更との関係。
大きな仕様変更が必要な点だけ、根拠と推奨案を添えて確認する。それ以外の独立した確認・検証は進める。

### 2. 検証 — 本実装前に成立条件を確かめる

1. 既存テストの基準結果を取得する。セーブ保護は最新の作業規則に従う。
2. 既存の `test/sim.node.js` 等を使い、必要なら試験用ユニットと最小の検証コードを用意する。まだ完成機能として組み込まない。
3. 4人に召喚体1体を加えた状態で、人数制限、行動順、対象選択、全体攻撃、退場のどこに制約があるかを確認する。
4. 行動順の二重実行・飛ばし・停止、開幕とウェーブの差、全滅・報酬の境界を検査項目にする。
5. 実装後に確かめる必要がある項目は、そのまま未検証として残す。事前検証だけで互換性を保証しない。

検証の成果物: 再現条件、基準結果、必要な変更、実装後の受け入れ条件。
バランス評価を行う段階では `balance-tuning` スキルを使用する。

### 3. 実装 — 小さい単位で組み込み、各単位を再検証する

1. 召喚定義と一時ユニットの生成・識別・管理。
2. 開幕配置、独立した手番、自動行動、対象選択。
3. HP0・召喚者死亡・ウェーブ移行・戦闘終了での処理。
4. 人数条件・報酬・他効果との接続。
5. PCとスマートフォンでの表示、召喚者との対応、退場の表示。
6. 完了条件の通し検査と、召喚あり／なしの実戦比較。

共通基盤の確認用に独立HPの試験召喚を用意してよいが、未調整の試験召喚を通常プレイへ解放しない。
データ追加だけで別の召喚を定義できる部分と、新しい規則が必要な部分を明示する。
索引は手編集せず、確定した知見に印を付けた場合は生成ツールで更新する。

## 完了条件

- 召喚なしの既存戦闘が、意図せず変わらない。
- 通常4人＋召喚1体、および採用した上限までの召喚で、行動と画面が停止しない。
- 召喚体は独立して行動・被弾・支援受領・退場できる。
- 初回ラウンド、ウェーブ移行、召喚者死亡、全滅、撤退で二重生成や残存がない。
- 同一シード・条件で再現でき、描画や候補の閲覧が乱数・状態を変えない。
- 編成条件・育成報酬・撃破報酬・手動入力集計の意味が維持される。
- 一時ユニットが通常の所持キャラやセーブへ混入しない。
- 他効果との適用表について、確認済み・対象外・未確認が区別されている。
- PCとスマートフォンで、召喚体のHP、行動中の主体、召喚者との対応が判別できる。
- 悪魔のHP共有へ進める接続箇所と、残る仕様判断が文書化されている。

## 報告と範囲

実装担当は「採用した仕様」「当初案からの変更と理由」「検証結果」「未確認」「悪魔へ進む際の課題」を報告する。
既存規則との成立検証を依頼元に差し戻さず、実装担当が具体的な結果を揃える。
この依頼は召喚基盤を対象とする。悪魔の効果量・解放依頼・HP共有の完成、他の召喚コンテンツの量産、公開は別工程とする。
