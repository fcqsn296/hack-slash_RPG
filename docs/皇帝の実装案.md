# 皇帝 IV — 実装案

作成日: 2026-09-21
状態: 仕様整理。実装・バランス実測は未実施。

## 目的と札の文面

皇帝は、自分の手番の持ち主を変えるアルカナ。
既存の「継ぐ手」や号令と異なり、待ち時間なしで毎手番を譲れる代わりに、命令先がいる間は本人の全技を使えなくする。

- 利: 自分の手番を、味方1人の即時行動に置き換える。
- 害: 命令できる味方がいる間、自分の技は使えない。
- 詳細: 命令による行動は、受け手の再行動上限を消費しない。その行動から再行動は発生しない。
- 惹句案: 王は剣を抜かない。その一声で、誰かが剣を抜く。

戦車は本人の手数、魔術師は攻撃しながら支援する役、皇帝は手番を誰に使わせるかを担う。
単騎または皇帝だけの編成では、命令対象がいないため通常行動となり、利も害も発生しない。

## 確定する基本仕様

| 状況 | 動作 |
|---|---|
| 命令可能な味方がいる | 「勅命」で相手を選ぶ。本人の技は使用不可 |
| 命令可能な味方がいない | 本人の通常の技選択へ進む。待機は新設しない |
| 皇帝が再行動する | 改めて命令先を判定。いれば命令、いなければ本人が行動 |
| 命令を受ける | その場で1回行動する。本来の手番は残る |
| 受け手が再行動上限に到達済み | 命令を受けられる。上限は消費しない |
| 命令中に既存の追加行動権を持っている | 消費も削除もしない。通常の手番進行へ残す |

命令先は、自分以外の生存する皇帝ではない味方で、命令中に使える合法な技・対象の組み合わせが1つ以上ある者。
再行動上限到達、主力技のクールダウン、麻痺の確率判定があることだけでは除外しない。
反動による行動不能や手番負債などは命令で踏み倒さない。既存の行動開始条件に照らして適格性を判定し、候補を調べるだけでは負債や権利を消費しない。
全技が使えない場合は候補から外す。候補の検査は乱数も戦闘状態も変更しない。

手動は「命令先 → 受け手の技 → 技の対象」の順に選ぶ。
オートは編成順で最初の適格者を選び、受け手の既存のオート判断で技と対象を決める。
専用の命令先保存項目は設けず、編成順を優先順位に使う。説明欄で明示する。

## 手番の所有と再行動

皇帝の1手を受け手の1行動に交換する。受け手の行動完了後、皇帝側の手番終了処理を1回だけ行う。
そこで皇帝の確率再行動等が成立すれば、皇帝に次の手番が来る。命令しただけで無条件に皇帝へ次の手番を与えてはいけない。

- 皇帝の確率再行動は、皇帝自身の既存の `extraActions` 上限を消費する。
- 皇帝が号令で受け取った権利は、既存の号令の規則で処理する。
- 皇帝が技を使わず命令した場合、その命令を攻撃・回復・バフ技として扱わない。技使用履歴や攻撃時効果を偽装して起動しない。
- 受け手の実行技は、受け手の能力・履歴・クールダウン・状態異常を使う。
- 命令による行動からは、確率再行動・撃破時再行動・コンボ由来の再行動を発生させない。
- 命令中は、号令・前借り等の手番を生成する技を選べない。自動選択と実行時の双方で検査する。
- 発生させない効果のために、受け手の再行動回数や取得済みの権利を先に消費してから取り消す方式は使わない。

これにより、皇帝の追加手番への投資は活きるが、受け手から皇帝へ手番が戻る無限連鎖を防ぐ。
既存の `grantedExtra` は真偽値で重複を保持せず即時実行も保証しないため、命令の保存先には使わない。

## 行動失敗と中断

- 皇帝が麻痺で命令に失敗したら、受け手は動かない。皇帝の失敗後の進行は既存の麻痺処理と揃える。
- 受け手が麻痺等で行動に失敗しても、皇帝の1手は払い戻さない。受け手のCTの扱いも通常行動と揃える。
- 命令先・技・対象は確定時に再検査する。不正な入力は実行せず、手動は選び直し、オートは候補を再評価する。
- 有効な候補が消えた場合は本人の通常行動へ戻す。失敗する同じ命令を永久に再選択しない。
- 反射などで受け手が倒れた場合も、実行済みの技の結果と行動後処理を確定してから復帰する。
- 制圧・全滅・戦闘終了では命令状態を破棄する。旧ウェーブの位置へ復帰しない。
- 命令開始後に皇帝が倒れた場合、実行済みの受け手の行動は取り消さず、皇帝の追加行動は発生させずに正規の次の位置へ進む。

## 既存アルカナ・効果との組み合わせ

| 対象 | 維持する挙動 |
|---|---|
| 魔術師 | 同じ技の連続使用禁止、攻撃後の回復と障壁 |
| 死 | 実行した技を刻限へ計上。最後の敵を倒した行動も制圧判定前に数える。麻痺失敗時の計上は通常行動と一致させる |
| 吊るされた男 | 通常どおり行動失敗を判定。失敗時のCTも維持 |
| 戦車 | 借りた1手だけ実行。本人の追加手番の残数は維持 |
| 皇帝 | 他の皇帝へ命令不可。本人の防御・反射・常時支援は残る |
| 累撃・技使用履歴 | 受け手の実際の技使用として更新 |
| 弱点コンボ | 通常の手動／オートの区別を維持。オートに新しいコンボ判断を足さない |

## 実装構成

### 戦闘の中核

`src/core/battle.js` の `commandSkill` は、技の可否・麻痺・実行・魔術師・死・制圧・再行動・行動順更新をまとめて扱っている。
まず行動実行と行動終了／進行の境界を切り分け、通常経路を変えない検査を置く。

命令中の戦闘内状態に、皇帝、受け手、復帰先、行動の由来を保持する。これはセーブ項目にしない。
`currentActor` は命令中だけ受け手を返す。通常の隊列位置は保持し、命令先の位置へ `actorIndex` を移して通常進行させない。
受け手の行動後処理は通常経路を共有し、再行動発生と順番更新だけを命令専用の終了処理へ分岐する。
`executeSkill` だけを直接呼ぶ実装や、`commandSkill` の再帰呼び出しで二重に進行させる実装は避ける。

候補判定、命令開始、命令終了を中核側へ集約し、UI・オート・測定で別々の規則を書かない。
撃破やコンボの再行動は技の実行中にも発火するため、終了処理だけでなく各付与箇所も行動の由来を確認する。

### コマンド・表示・測定

- 命令と技は異なるコマンド種別として扱う。命令を実在しない技IDに偽装しない。
- 通常の `{skillId, targets}` 呼び出しとの互換を維持しつつ、共通のコマンド実行口を用意する。
- `src/core/autoplay.js` は皇帝なら命令候補、受け手なら命令中の使用条件で絞った通常技を選ぶ。
- `src/ui/battle.js` は命令先選択と受け手の技選択を表示し、「誰の命令で誰が行動中か」を示す。命令先候補は中核から取得する。
- `test/sim.node.js` と他のオート実行箇所も共通の実行口へ接続する。既存の `commandSkill` 直接呼び出しを検索して確認する。
- 命令の選択回数と実際の技行動回数は別に記録する。受け手の1行動を2回の攻撃と集計しない。
- 手動／オート報酬の入力集計は移譲した1行動につき1回。途中でオートを切り替えた場合を含め、実行する技の入力方式で計上し、命令選択を重ねて数えない。

### データと登録

- `data/arcana.js`: 皇帝の札と新効果。未実測の強さを実測済みとして書かない。
- `data/effectkinds.js`、`src/core/tree.js`、`data/nodecategories.js`、拡張手順書、`test/tests.js`: 新効果の登録一式。
- `data/quests.js`: 解放依頼。Lv200前後で既存の支援技を使って攻略でき、皇帝自身を要求しない内容。具体的な条件と難度は実測後に決める。
- `assets/ui/arcana-emperor.svg`: 既存に合わせた単色マスク。
- `docs/アルカナの作り方.md`: 皇帝の軸と確定した知見を追記し、古い既存枚数を更新。
- 実測結果は作業ログへ。知見に印を付けた場合は索引生成ツールで更新し、索引を手編集しない。

## 必須の検査

1. 命令先がいる間の本人の技使用を、中核側でも拒否できる。
2. 単騎・他の味方が全員死亡・皇帝のみの編成で本人が通常行動できる。
3. 皇帝より前／後のどちらの隊列へ渡しても、即時に1回動き、他の味方の手番が増減しない。
4. 皇帝の再行動1回で命令が合計2回になる。皇帝側の既存上限を超えない。
5. 再行動上限済みの受け手へ渡せる。受け手のカウンタと既存権利を消費しない。
6. 命令中に再行動生成技が選べず、撃破・コンボ・確率でも再行動を生成しない。
7. 魔術師の連続禁止・支援、死の刻限、麻痺とCTが通常行動と一致する。
8. 初回ラウンドとウェーブ移行直後にも動く。制圧・全滅・死亡で命令状態が残らない。
9. オートが合法な命令／技を選び続け、行動不能の候補で停止しない。
10. 命令選択で乱数や状態を変えず、同じシードで再現する。入力・行動統計を二重計上しない。

## バランスの採否判断

既存の `test/sim.node.js` と実ビルドを使用する。装備・SP・クラス・編成を確認し、皇帝なし／通常の号令支援／皇帝の置き換え比較をする。
相なし5ウェーブと、先制・狙い方等の相を重ねた高難度を分ける。初期比較は各条件30試行、僅差なら試行数を増やす。通算ラウンド、実行技回数、勝敗、命令回数、本人行動回数、失敗回数を記録する。

特に次を採否の条件とする。

- 主力へ渡す利益が高難度で現れる。
- バフ・回復・蘇生・全体号令を失う不利益も確認できる。
- 皇帝2〜3人で主力1人へ集中する編成が、比較した全条件を一方的に支配しない。
- 常時支援だけ残す運用で代償がほぼ消えるかを確認する。消える場合は数値の追加で埋めず、規則を再検討する。
- 通常周回ではラウンド数の床だけで判断せず、実行行動数と画面上のテンポも確認する。

具体的な勝率・改善率は未実測。現時点で成功値として断定しない。

## 実装順

1. 既存の行動進行を検査し、実行と終了処理を切り分ける。
2. 命令の中核、本人行動への復帰、再行動規則を実装して検査する。
3. 手動画面・オート・測定ツールを接続する。
4. 実ビルドで測定し、皇帝の規則を採否判断する。
5. 採用した仕様に解放依頼とアイコンを付け、文書と索引を更新する。

公開は通しの検証後の別工程。今回の成果物はこの実装案のみ。
