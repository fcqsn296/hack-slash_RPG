# 正義 XI — 実装案

作成日: 2026-09-21
状態: 仕様提案。実装・バランス実測は未実施。

## 設計意図

相手に先に最強の攻撃を使わせ、それを耐えて自分の一撃を返すアルカナ。
耐えられる構成を完成させれば、安定して上限増加を得られてよい。安全になったことを理由に防御無視や回復禁止を後付けしない。
代償は、応撃を耐えるために装備・SP・編成を守りへ回す機会費用。アルカナ枠も消費するが、それだけを固有の代償とは扱わない。

反射・棘型には、自分から被弾機会を作ること自体が利益になる。これを正式な用途として残す。
敵の先行攻撃を、すべてのビルドで一方的な害にする必要はない。

## 札の文面案

- 利: 敵の裁きを耐えた一撃は、ダメージ上限が上がる。
- 害: 攻撃する前に、対象から使用可能な最強の攻撃を受ける。
- 詳細: 敵の通常手番は減らない。応撃にも通常の防御・反射・棘が働く。
- 惹句案: 裁く者は、先にその刃を受ける。

上限の増加量は未定。実測後は札に数値を明記する。
本人の技はプレイヤーが選び、最強技の使用を強制しない。オートも既存の選択方針を基礎とする。

## 合意した中核

1. 本人が攻撃技と対象を予約する。
2. 対象の敵が、その時点で使用可能な攻撃のうち本人への予測ダメージが最大の技を先に使う。
3. 応撃には本人側の防御・軽減・障壁と、通常の反射・棘・反撃が働く。
4. 本人が生存し、予約攻撃を実行可能なら、上限を強化して実行する。
5. 予約攻撃が発生させる回復等も通常どおり処理する。全快するかどうかは実装と実測で確認する。
6. 応撃は敵の通常手番を消費しない。再行動で本人が再び攻撃する場合も、その都度応撃が起きる。
7. 応撃への反射・棘等で対象が先に倒れた場合は撃破成立。対象への予約攻撃は行わず、その攻撃による回復も発生しない。

本人が応撃で倒れた場合も予約攻撃は不発で、手番は消費する。
回復・補助のみの技では応撃も上限強化も起きない。攻撃と支援を併せ持つ技は攻撃として扱う。

## 初版の推奨仕様と、実装時に確かめる境界

以下は中核から派生した実装上の推奨案。未確認の既存挙動は実装前に検査する。

### 「最強」の定義

- 技の威力欄ではなく、多段・属性・防御・上限等を含めた本人への直接ダメージの予測合計で選ぶ。
- 残HPで切り詰めて全技を同点にせず、過剰分を含む値で比較する。
- 選択時に確定会心や命中保証は与えない。既存の確率規則を踏まえた予測を用い、実行は通常の乱数判定に従う。
- 自傷、反射で返るダメージ、将来の継続ダメージや支援価値は初版の順位に含めない。「直接攻撃の最大打点」であることを説明する。
- 同点は技ID等の安定した順序で決め、見積もりで乱数を消費しない。
- 敵の予測処理が複合技やボス固有処理を正しく扱えるかを確認する。既存の味方向けオート見積もりを、そのまま敵に使えるとは仮定しない。

現行の `enemiesAct` は敵の技をランダムに選んでいる。味方の `skillReady` と同じCT・解禁条件を敵にも適用しているとは仮定しない。
「使用可能」は敵の実際の制約を基準に定義し、正義だけのために通常敵の行動規則を無断で変更しない。

### 対象と全体攻撃

- 本人の単体技は、その対象が応撃する。
- 本人の全体技は、明示した主対象1体だけが応撃する。敵全員からは受けない。
- 敵の単体技は本人を狙う。敵の全体技や「あまねく相」は、本来の範囲を保つ案を初版候補とする。味方も巻き込む点は説明する。
- 庇い・肩代わりは既存の防御規則に従わせる案とし、正義だけ無効にしない。本人が直接被弾しなくても生存していれば予約攻撃へ進む。
- 主対象が応撃中に倒れた場合、初版では予約した全体技も不発にする。他の敵へ無料で予約し直さず、次の手番から選ぶ。

### 応撃が成立しない場合

- 対象に合法な攻撃技がない場合、本人は通常の攻撃を行う。上限強化は付けない。
- 敵が麻痺等で攻撃を実行できなかった場合も、本人は通常の攻撃へ進み、上限強化は付けない案とする。
- 敵が攻撃を実行し、回避・障壁等でHP被害を防いだ場合は上限強化を認める。防御の成功を罰しない。
- 応撃から受けた状態異常は予約攻撃にも通常の規則で影響させる。麻痺の抽選を予約時と実行時に二重で行わないよう、判定位置を明確にする。

### 予約と消費

- 技の使用条件・対象の検証後に予約し、手番の消費を確定する。
- CTやコンボ資源等は技ごとに現在の消費位置を確認する。初版の方針は「応撃を起こした予約は無料で取り消せない」。不発時にも必要な消費が残るよう整理する。
- 技履歴・攻撃回数・与ダメージ回復・「死」の刻限などは、予約と実際の技実行を区別する。未実行なのに攻撃した扱いへ統一しない。
- 反射による撃破を含め、制圧・全滅・同時死亡の勝敗優先順位は既存の戦闘規則に合わせる。

## 反射・棘を残すための実装注意

現行の反射と棘は被ダメージ処理にあり、独自の上限を持つ。通常攻撃の上限突破がそれらも強くするとは仮定しない。
また、棘・反撃には `isCounter` による連鎖防止がある。

正義の応撃を一律に `isCounter` として実行すると、意図した棘を止める可能性がある。
応撃専用の行動由来を持たせ、次の2つを分離する。

- 応撃に対する通常の反射・棘・反撃は許可する。
- 応撃や、それに対する反撃から、新たな正義の応撃は発生させない。

応撃は1つの技を1回使う。ボスの `actionsPerRound` 回ぶんを呼ばない。
多段技の各ヒットで起きる反射・棘は既存の扱いを維持し、途中で敵が倒れた後の残りヒットも既存の生存判定を確認する。

## 上限強化の適用範囲

- 応撃を経て実行される予約攻撃だけに適用する。
- 通常の上限計算へ一時的な補正として渡し、恒久パッシブへ加算して後で引く方式は避ける。
- 多段・全体は技全体へ適用する案とし、本人のその技以外の反射・棘・別の追撃へ漏れないようにする。
- 元から上限を無視する技へは、余分な利益を新設しない。
- 適用直後に戦闘が終了した場合も、次の技・次のウェーブに補正を残さない。

皇帝の実装が先に進んでいる場合は、その行動由来・中断・復帰の設計を確認して共用する。別々の割込み処理を競合させない。
皇帝に命令された正義も、実際に攻撃するなら応撃を受ける。借りた手番の再行動禁止も維持する。

## 検査項目

1. 予約 → 敵の応撃 → 反射等 → 本人の攻撃 → 回復、の順序が成立する。
2. 最強技の予測が多段・属性・防御を反映し、選択だけで乱数や状態を変えない。
3. 応撃が敵の通常手番やラウンドを進めず、ボスの行動回数を丸ごと実行しない。
4. 本人死亡、主対象死亡、同時死亡、全滅、制圧で予約が残らない。
5. 反射・棘が通常の条件と上限で動き、応撃の再帰が起きない。
6. 回復・補助のみの技に応撃せず、攻撃兼支援技では応撃する。
7. 全体技・庇い・肩代わり・障壁・麻痺・回避が定めた規則に従う。
8. 不発時のCT・資源消費と、実行時の履歴・回復・刻限を区別できる。
9. 上限補正が反射や次の行動へ漏れず、予約した技に一度だけ掛かる。
10. 再行動のたびに応撃し、皇帝による行動でも処理と入力集計が重複しない。

## 測定と採用判断

まず上限増加をゼロにし、応撃を生む規則だけの価値を測る。反射・棘の価値を測る前に倍率を盛らない。

| 比較する構成 | 確認すること |
|---|---|
| 既存攻撃型への付け替えだけ | 守りへの追加投資なしで全条件を支配しないか |
| 正義用に耐久へ置き換えた攻撃型 | 攻撃投資を失う対価と上限強化が釣り合うか |
| 既存耐久型 | 守りへの投資を攻撃力へ転換する役割が成立するか |
| 反射・棘型 | 応撃による実ダメージ、撃破、不発、回復の収支 |

各構成で札なし・既存札・正義を比較し、装備・SP・編成枠は上乗せしない。
相なし周回、相を重ねた高難度、適切な闘技場を分けて測る。解放依頼はLv200前後、終盤の評価はLv255の実ビルドで行う。

記録するもの: 勝敗、通算ラウンド、行動数、応撃回数、応撃での死亡、予約不発、本人の攻撃ダメージ、反射・棘ダメージ、実回復量、耐久へ移した装備・SP。
棘は敵最大HPを参照するため、敵HPの改変が評価へ直結する。HPを人工的に増やした実験だけで採否を決めない。

致死防止と回復で毎回安全になる場合も、完成したビルドの成果としてまず評価する。
構築の対価がなく既存札を一方的に上回る場合に限り、実測を基に上限増加量や規則を見直す。
反射型に価値が出ること自体は弱体化の理由にしない。

## 実装順

1. 敵の技候補、予測、行動制約、反射・回復経路を確認する。
2. 上限増加なしの応撃処理と中断処理を実装し、検査する。
3. 攻撃型・耐久型・反射型で応撃だけの利益と不利益を測る。
4. 必要な上限増加量を1つの調整値として決め、再測定する。
5. 手動画面・オート・解放依頼を通し、採用した仕様を文書と索引へ反映する。

公開は実装・検証後の別工程。今回の成果物はこの実装案のみ。
