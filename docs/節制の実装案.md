# 節制 XIV — 実装案

作成日: 2026-09-21
状態: 設計整理。実装・バランス実測は未実施。

## 設計意図

本人が回復技で生んだ過剰回復を蓄え、次の攻撃1行動の強化に使うアルカナ。
回復と攻撃の両方へ投資し、「回復で蓄える → 強化攻撃で使い切る」という循環を作る。
回復は数千、攻撃は数百万以上に伸びるため、回復量をそのまま固定倍率でダメージへ交換しない。
回復対象の最大HPに対する過剰回復の割合を、攻撃の倍率へ変換する。

攻撃によるHP吸収は最小段階でも与ダメージの2%に達するという指摘がある。
100万ダメージなら2万回復となり、これを蓄積に含めると強化攻撃が次の強化を準備する循環になる。
回復に1手を使う構造を維持するため、発生源を厳密に限定する。

## 札の文面案

- 利: 自分の回復技で余った回復を蓄え、次の攻撃1行動を強化する。
- 数値説明案: 対象の最大HP100%ぶんの過剰回復につき、攻撃を25%強化。複数人への分は合算する。
- 制約: 吸収や自動回復では蓄積できず、蓄えは次の攻撃で全て消費する。

25%は仮係数。蓄積上限は未定。
「制約」は現時点で効果の利用条件であり、独立した大きな害が確定したわけではない。
回復1手と兼業投資がアルカナとして十分な対価になるか実測してから採用する。
既存の回復役が普段どおり動くだけで無条件の最善札になる場合も評価する。追加の害を合意済みとして捏造しない。

## 蓄積対象

| 回復の発生源 | 蓄積 |
|---|---|
| 本人が選んで使った回復技による過剰回復 | 対象 |
| 回復技で実際に減ったHPを戻した分 | 対象外 |
| 攻撃によるHP吸収 | 対象外 |
| 攻撃技に付随する回復 | 対象外 |
| 再生、常時効果、パッシブによる自動回復 | 対象外 |
| 他のキャラから受けた回復 | 本人の蓄積には入らない |
| 回復を起点に連鎖した追加回復・共有回復 | 初版は対象外 |

「本人が選んで使う」は手動操作限定という意味ではない。本人の手番でオートが選んだ回復技も含む。
回復量や対象のHPだけで判別せず、回復を起こした技・使用者・発生経路を参照する。
回復と攻撃を兼ねる技は、初版では蓄積対象外として強化攻撃による自己補充を防ぐ。
既存の技一覧から回復技の分類を確認し、UIと実処理の分類を一致させる。

## 蓄積式

対象iについて、回復直前の最大HPを M_i、現在HPを H_i、補正・回復阻害等を適用した回復可能量を R_i とする。

    過剰回復 O_i = max(0, R_i - max(0, M_i - H_i))
    今回の蓄積増分 ΔB = 0.25 × Σ(O_i / M_i)
    蓄積 B = min(B_max, B + ΔB)
    次の攻撃の目標倍率 = 1 + B

死亡者・回復無効・蘇生・最大HPが0等の例外は既存の回復規則を確認する。
回復不能なのに、表示上の回復予定量だけをすべて過剰回復と見なしてはいけない。
HPが減っていた対象が同じ技の途中で満タンになった場合は、以後の実際の過剰分のみ加算する。
回復量から過剰分を計算する既存処理があれば共有し、UIの数値から逆算しない。

| 条件 | 蓄積増分 |
|---|---:|
| 1人へ最大HP100%分の過剰回復 | +0.25（攻撃+25%） |
| 4人へそれぞれ最大HP50%分 | +0.50（攻撃+50%） |
| 4人へそれぞれ最大HP100%分 | +1.00（攻撃+100%、2倍） |

各対象の最大HPで個別に割ってから足す。パーティの最大HP合計を分母にしない。
B_maxは暴走防止の蓄積上限として設けるが、数値は検証で決める。+100%は損益比較の起点であり、蓄積上限の確定値ではない。

## 次の攻撃への適用

- 次の攻撃1行動の開始時に、使用する蓄積量を固定する。
- 固有の多段、小技の多重発動、連撃を含め、その技1行動の全段を強化する。
- 最初の1ヒットで強化を失わない。
- 再行動で選んだ次の技は別行動。蓄積を持ち越さない。
- 同じ行動中の吸収回復・攻撃付随回復で蓄積を補充しない。
- 強化攻撃による吸収で満タンになり、次の回復技が過剰になりやすくなる相乗効果は認める。必ず回復技の1手を挟む。
- 威力だけでなくダメージ上限も含めて、実効で目標倍率に近づく構造にする。
- 防御・属性・無敵などを無視するダメージは新設せず、通常の攻撃経路に組み込む。

威力と上限を同じ倍率で動かす方式を初期候補とするが、既存の加算・乗算の順序を確認する。
現在のcap_breakに同じ数値を加えるだけで実効倍率が一致するとは仮定しない。
上限無視技や特殊な割合ダメージへの適用は、実装調査で明確にする。

## 累撃との関係

確認時点の実装では、回復行動は累撃の段数をリセットせず、進行もしない。
攻撃技で現在の累撃倍率を適用した後、段数が進む。この順序を節制でも維持する。

比較単位は1撃ではなく、次の2手とする。

- 攻撃継続: 現在の段数で攻撃 → 次の段数で攻撃。
- 節制: 回復して蓄積 → 現在の段数で強化攻撃。

火力一定なら+100%の強化攻撃で、通常攻撃2回と火力上は並ぶ。
累撃が実効で次撃2倍になる仮定なら、攻撃継続はD+2D=3Dとなり、+100%では並ばない。
実際は累撃上限・ダメージ上限・投資配分で異なるため、この単純例を調整値として採用しない。
累撃の立ち上がりと上限到達後を分けて検証する。

## 未確定の境界と初期提案

| 論点 | 初期提案・確認事項 |
|---|---|
| 1人に最大HP400%分の過剰回復 | 合算式どおりなら+100%。単体回復にも用途がある一方、低HPの対象へ集中する強さを検証して確定 |
| 召喚体への回復 | 合算対象にするか未定。人数増による全体回復効率を通常4人と別に測る |
| 恋人・悪魔等の共有HP | 同じ回復を別経路から重複計上しない。共有プールと身体のどちらを単位にするか、最新仕様と合わせて確定 |
| 全体攻撃・余波・独立追撃 | 全段適用と一貫した範囲を決める。別行動へ漏らさず、反射・棘・継続ダメージは初版の強化対象外を推奨 |
| 不発・ミス・麻痺・対象消滅 | 合法な攻撃を確定した後は、不発でも蓄積消費とする案。候補閲覧や不正な入力では消費しない |
| 行動開始と終了 | 開始時にBを行動用へ移し、保管分を0にする案。途中死亡でも強化や蓄積が残らないよう終了処理を保証 |
| ウェーブ移行 | 初版は同じ戦闘内で蓄積を維持する案。戦闘終了時には必ず破棄 |
| 回復の連打 | B_maxまで加算を認める案。1回の強化攻撃だけでなく、蓄積に要した全手番で評価 |
| 通常回復との両立 | 回復技は通常どおりHPを戻す。残った分だけ蓄積し、回復量を奪わない |
| 障壁等への過剰回復変換 | 同じ過剰分から両方発生させるかを既存効果と照合。未確認のまま二重取りを既定にしない |

## オートと表示

現行のオートが満タン時に回復技を選ばない場合、蓄積が一度も起きない可能性がある。
節制の存在だけで回復を優先させず、「今攻撃する価値」と「回復後の攻撃で取り戻せる価値」を比べる。
蓄積上限で回復を続ける、倒し切れる敵を前にチャージする、回復と回復を延々と繰り返す挙動を検証する。
緊急回復の判断も維持し、過剰回復が出ないから必要な回復まで捨てる実装にしない。

表示は現在の強化率、蓄積上限、次の攻撃1行動で消費することを示す。
回復ログには今回の蓄積量、攻撃ログには消費した強化量を記録し、吸収が蓄積しないことを追えるようにする。

## 必須の検査

- 対象ごとの過剰回復比率と合算が表の例に一致する。
- HP補充分、吸収、再生、攻撃付随、他者からの回復、派生回復で蓄積しない。
- 回復阻害・無効・死亡対象で架空の過剰回復が生まれない。
- 累撃は回復で維持され、強化攻撃で通常どおり進む。
- 多段・多重発動・連撃の全段へ補正が乗り、再行動の次の技には残らない。
- 上限補正が通常の防御や無敵を迂回せず、別の行動・反射等へ漏れない。
- 強化攻撃の吸収から蓄積が再生成されない。
- 不発・死亡・ウェーブ移行・戦闘終了が採用した消費規則に従う。
- B_maxを超えず、同じ回復イベントを二重計上しない。
- 手動とオートで同じ計算経路を通る。

## 実測と採用条件

`test/sim.node.js` 等の既存道具と実ビルドを用い、balance-tuningの手順に従う。
装備・SP・編成枠を上乗せせず、同じ条件で置き換える。

比較する型:

- 単発型、多段型、累撃型（立ち上がり／上限到達後）。
- 攻撃特化のまま、回復と攻撃へ配分した兼業型、回復特化。
- 単体回復と全体回復、通常4人と召喚を含む条件。

まず係数25%を仮値として測り、係数と蓄積上限を同時に動かさない。
2手の比較に加え、チャージを繰り返す場合は準備の全手番を含める。

記録する値:

- 回復技の使用回数、実回復量、過剰回復比率、得た蓄積、使わず捨てた蓄積。
- 攻撃2手と回復→強化攻撃の総ダメージ、実際の上限減衰。
- 通算ラウンド、敵の行動回数、強化攻撃まで生存できた割合、勝敗。
- 回復能力へ振り替えたSP・装備による通常火力の減少。

採用条件は、回復と攻撃を整えた構成で、回復の防御的利益に加えて、失った攻撃機会を取り戻す攻撃上の利益が出ること。
全構成で無条件に優位である必要はないが、回復1手を使ったのに強化攻撃が弱いままなら成立扱いにしない。
逆に吸収連打や既存の回復行動だけで無制限に強化される場合は不採用とし、原因を記録する。

## 今回採用しない案

- 攻撃の吸収回復や自動回復による蓄積: 強化が自己補充され、回復技を使う意味が消える。
- 実回復量まで含める蓄積: 今回は回復技の過剰分だけに絞る。
- 回復で累撃をリセットする追加代償: 現行仕様を変えず、攻撃機会の遅れを対価として測る。
- 強化を最初の1ヒットだけに適用: 多段型が攻撃1手を捨てた対価を回収しにくい。
- 攻撃と回復の強制交互使用: 現案では採用しない。蓄積と消費により循環を作る。
- 敵HPを直接参照した回復ダメージ: 今回は対象の最大HP比率から本人の攻撃倍率へ変換する。
