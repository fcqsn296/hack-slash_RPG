# 効果を追加するときの手引き

パッシブや技を足す前に読む文書。
**「書いたのに何も起きない」を防ぐことだけを目的にしている。**

この壊れ方は例外も警告も出ない。値は保存され、説明文は画面に出て、
テストも通る。それでも効いていない。気付くのは何週間も後になる。

---

## 1. パッシブ（効果種別）を足す

### 手順

1. `data/effectkinds.js` に1行足す
2. `src/core/tree.js` の switch に `case` を1本足す
3. ノード（`data/skilltree.js` か `data/classes.js`）から参照する

**順番を守ること。** 登録簿に無い種別は畳み込みで黙って捨てられる。

### 登録簿に書くこと

| 項目 | 意味 |
|---|---|
| `to` | 値がユニットのどこへ入るか。`passives` / `situational` / `build` |
| `shape` | レベルの重ね方。`add` / `max` / `levels` / `keyed` / `special` |
| `needs` | 必須の追加フィールド。無いと静かに既定値へ落ちる |
| `opt` | 省略できるが、書かないと既定値のままになるもの |
| `uniq` | ユニーク装備の `effects` で使うキー名（camelCase）。持てないなら `null` |
| `route` | そのキーを装備から流す先 |

### いちばん間違えるところ

**`to` の3つは見分けが付かない。** 間違えても何も起きない。

- `passives` … `unit.passives.x` を battle.js が読む（75種）
- `situational` … `unit.situational.x` を **toAttacker が拾って damage.js へ渡す**（13種）
- `build` … 組み立て時に個別の変数へ入る（21種）

`situational` のものを `passives` に置いた事故が実際に2回あった
（`critPierce` と `debuffAmp`）。どちらも数値は正しく、画面にも出て、
それでも1ダメージも増えなかった。

**判断できないときは、その値を読んでいる場所を先に探すこと。**
`grep` して `attacker.x` なら situational、`p.x` や `passives.x` なら passives。

### `shape: 'max'` の落とし穴

「高いほうを採る」種別（`last_stand` / `revive` / `wave_revive`）は、
上位ノードが下位を置き換えるためのもの。だが **レベルぶんは伸びなければならない**。

比較に `e.value` を使うと、同じノードを重ねても値が動かなくなる。
実際 不撓(6SP) 不屈の魂(8SP) 輪廻(6SP) 不撓の祈り(2CP) で
**払えるのに何も起きないレベル** が残っていた。必ず `amount`（value×レベル）で比べる。

## 2. 技（アクティブ）を足す

### 手順

1. `src/plugins/` にファイルを1つ作る
2. `index.html` と `test/*.html` の**4か所すべて**に script タグを足す
3. `data/skills.js` から `plugin: '...'` で指す

テストページに足し忘れると、テストだけが古い挙動で通る。

### ctx でできること

プラグインに渡る `ctx` の全体。これ以外は無い。

| | すること |
|---|---|
| `params` | 技の `params` |
| `skill` / `actor` / `targets` / `battle` | 素材 |
| `allies()` / `foes()` | 行動者から見た味方・敵 |
| `damage(t, opt)` | 1発殴る。`opt.powerScale` で威力倍率 |
| `damageWith(t, skill, opt)` | 別の技として殴る |
| `heal(t)` | 回復（量は技の `power` から） |
| `log(text, kind)` | 戦闘ログへ1行 |
| `addStatus(t, effect)` | 状態異常。耐性で弾かれることがある |
| `selfStatus(kind, turns, ratio)` | **自分に**弱体。耐性を通さない |
| `setDefIgnore(t, turns)` | 防御を0にする |
| `detonate(t)` | 毒と火傷を現金化する |
| `addSigil(t, ratio, count)` | 刻印を積む。溜まると弾ける |
| `mark(t, value, turns, label)` | 標的指定。味方全員がその相手に強くなる |
| `borrowTurn(rounds)` | いま再行動し、次のラウンドを失う |
| `addUniqueBuff` / `addTagBuff` / `addDefBuff` / `addReductionBuff` | バフ4種 |

### 手番を増やす技を作るとき

**必ず `MAX_EXTRA_ACTIONS` を通すこと。**
`grantedExtra` は「1ラウンドに1回配られる」前提の仕組みなので、
プレイヤーが好きなだけ撃てる技から素通しで使うと、
再行動 → また撃つ → 再行動 で**手番が無限に増える**。
実際に前借りの技でこの穴を作りかけた。

## 3. 足したあとに必ず測る

### 届いているか

テストが自動で見る。`data/effectkinds.js` に登録した時点で、
46キーすべてが「宣言どおりの場所に届くか」実測される。

自前で確かめるときは **ユニット全体を丸ごと差分で見ること。**
`passives` と `situational` だけを見て「効いていない」と誤判定した
（会心・上限突破などは別の場所に入るため）。

```js
const before = JSON.stringify(RPG.units.buildCharacterUnit(charSave, []));
charSave.equipped[slot] = [item.uid];
const after = JSON.stringify(RPG.units.buildCharacterUnit(charSave, [item]));
```

### 戦闘の長さに対して成立するか

**新しい仕組みは、実装が正しくても成立しないことがある。**

刻印を「敵に積む」形で作ったとき、実装もテストも正しかったが
**12戦で炸裂ゼロ**だった。味方4人が代わる代わる殴るので、
1体の敵に同じキャラが3発当てる前にその敵が死ぬ。

数える前提のものを作るなら、先に見積もること。

| 目安（Lv255・終わりなき回廊） | |
|---|---|
| 1戦あたり | 3〜4ラウンド |
| 1キャラが同じ敵を殴る回数 | 1〜2回 |
| 雑魚が沈むまで | 味方の2〜3発 |

### オートで測れないもの

`readyRound` / `cooldown` / 条件付きの効果はオート戦闘が活かせない。
**オートの数字だけで強弱を判断しないこと。**
狙った戦い方を再現する関数を書いて、それで測る。

詳しくは balance-tuning の手順に従うこと。
