# 女帝検討用：パッシブ算出項目一覧

作成日: 2026-09-22。現在の作業ツリーを参照。実装変更は行っていない。

## 範囲と読み方

主表は `data/effectkinds.js` の `to: passives` 全件。ツリー・クラス・アルカナ共通の登録を含むため、すべてがSPツリーで取得可能という意味ではない。女帝の共有対象を確定する表ではなく、算出値の棚卸しである。

割合20%は0.20。半分なら10%。一方、倍率×2や有無フラグは単純に0.5倍できない。表示のfmtと実際の用途が異なるものはtree/battleの読み方で分類を補正した。上限と端数処理を全件監査したものではない。

## 主表に追加で必要な算出キー

| キー | 単位 | 算出・合成 | 注意 |
|---|---|---|---|
| counterPower | 反撃の倍率 | counterの追加指定powerからも設定され、counter_powerでも加算 | 発動確率counterRateと別。既定の反撃威力との関係を確認 |
| atkScale | 能力への乗算係数（初期値1） | treeの戻り値とunitsの合成に存在。合成は乗算 | 1を半分にすると、何も取得していなくてもATK半減になる。現役の供給元は別途確認 |

## 種類別の表の中身

| キー | 1要素の単位 | 半減の考え方 |
|---|---|---|

`build`には能力%、会心、上限突破、系統タグ、属性補正だけでなく、技習得・属性変換も含まれる。共有可否は個別に決める。装備セット専用効果はさらに別枠であり、上の主表には含めていない。

## 上限の重要な注意

現在の上限は全項目共通の最終上限ではない。tree.jsにはツリー側の上限があり、クラス等の合流後に超える設計もある。例えばextraActionRateはツリー側0.5までだが、クラス由来で超えることを意図したコメントがある。

女帝で「通常上限を超えない」を満たすには、共有分をどの層へ合流するか決める必要がある。共有分のためにクラスの正当な上乗せまで切り捨てないこと。

割合項目でもすべてが100%上限ではない。回復量・反射・確率・上限拡張を同一のclampで処理しない。

## 確定した共有量の規則（2026-09-22）

以下はユーザー指定。各行の「端数を決める」「倍率を別途判断する」等の検討メモより、この規則を優先する。

| 分類 | 共有する値 | 例 |
|---|---|---|
| 割合・確率・加算係数 | 元の値の半分 | +40% → +20% |
| 回数・段数・ターン | 半減後に切り捨て。整数部分が1以上なら共有 | 1回 → 0、2回 → 1、3回 → 1 |
| 倍率 | 共有しない | 累撃を他者へ配らない |
| 有無・規則変更 | 共有しない | 全体化・確定会心・命令等を配らない |
| 種類別の表 | 各要素の実際の単位に上記の規則を適用 | 付与率20% → 10%、持続短縮3ターン → 1ターン |

「倍率」は上の独立分類を指す。火力+○%等の加算係数まで一律に対象外にしない。
追加キーatkScaleのような基準値1の乗算値も共有しない。
表示形式ではなく実際の用途で分類する。doubleHits等のpct表示をそのまま割合として扱わない。

実装案として、共有元の対象効果をキーごとに集計してから半減・端数処理を行う。ノードごとに1回を半減して消す方式は避ける。
共有分は受け手の自前の効果へ合流し、適用先の通常の上限を守る。ただし、上記のツリー上限とクラスの上乗せの区別を維持する。
半減・切捨ての仕様を決めたことは、バランスや全経路の安全性を検証済みであることを意味しない。

## 残る仕様判断

1. 共有元をSPツリーだけとするか、クラス・固有・装備まで含めるか。最終unit.passivesからは供給元を区別できない。
2. 共有対象外の効果と、整数半減で共有量0となる効果について、女帝本人の減少をどう扱うか。今回の確定事項は他者への共有量の規則。
3. passives以外の常時効果まで含めるか。含める場合も倍率・規則変更を除き、実単位で分類する。
4. 上限を動かす効果を半分配る際、共有先の「通常上限」をどう定義するか。
5. 共有で受け取った値を再び配らない構造、複数女帝の重複、死亡時の扱い。
