# 月 XVIII — 実装案

作成日: 2026-09-21
状態: 設計案。実装・整合性検証・バランス実測は未実施。

## 設計意図

本人の攻撃は現実のHPを削らず、敵に「幻傷」を刻む。
仲間がその敵を攻撃すると幻傷が実体化し、仲間自身の攻撃に追加の被害を与える。
自分の強い一撃を仲間へ預けるアルカナ。本人だけでは攻撃を完結できないことを制約にする。

皇帝は他者へ手番を渡す。月は自分の一撃を他者の攻撃で現実にする。
悪魔のように身体を増やさず、ダメージが成立する規則を変える。

## 札の文面案

- 利: 刻んだ幻傷を、仲間の攻撃で実体化する。敵1体につき1ラウンド最大3回。
- 害: 自分の攻撃では敵のHPを減らせない。敵が行動すると、その敵の幻傷は消える。
- 詳細: 幻傷は刻んだ時点の威力で固定され、刻み直しても実体化の残り回数は戻らない。

3回は初期検証値。公開用の説明は最終的に採用した値に合わせる。

## 合意した中核仕様

### 幻傷を刻む

- 月の持ち主の攻撃は、通常の直接ダメージの代わりに幻傷を残す。
- 幻傷は敵1体につき1つ。新しく刻んだ幻傷で置き換え、累積加算しない。
- 別の月の持ち主が刻んだ場合も同じ枠を置き換える。
- 基準値は、刻んだ時点の累撃・防御・通常のダメージ上限等を適用した値。実体化時に本人の現在の能力で再計算しない。
- 幻傷を刻むだけでは敵HPを減らさず、その攻撃による与ダメージ回復は発生しない。

### 幻傷を実体化する

- 仲間の攻撃を起点として、その敵に保存された幻傷を実体化する。
- 敵1体・1ラウンドにつき最大3回を初期値にする。
- 同じ敵への実体化回数は、全員で共有する。キャラごとの権利は設けない。
- 多段でも、攻撃1行動・敵1体につき実体化は1回。
- 再行動による別の攻撃では、その敵の残り回数があれば再び実体化できる。
- 幻傷の実体化から、別の実体化・追加行動・累撃の進行は発生させない。
- 反射・棘・自動反撃は実体化の起点にしない。

### 消滅と回数リセット

- 敵が行動すると、その敵の幻傷は消える。
- 幻傷が消えても、そのラウンドに使った実体化回数は戻らない。
- 幻傷の上書き・術者の変更でも回数は戻らない。
- ラウンドが更新されたときだけ実体化回数をリセットする。
- 撃破・ウェーブ移行・戦闘終了で、その敵の幻傷と管理情報を破棄する。

幻傷の保存と使用回数は独立して管理する。幻傷オブジェクトを置き換えたために使用回数まで初期化される実装は禁止。

## 累撃との関係

| 出来事 | 累撃 |
|---|---|
| 月の本人が攻撃して幻傷を刻む | 本人の累撃を通常の攻撃と同じタイミング・回数で進める |
| 仲間が自分の技で攻撃する | 仲間自身の累撃が通常どおり進む |
| 幻傷が実体化する | 誰の累撃も進めない |

通常の攻撃が「現在の累撃で計算してから進む」なら、幻傷も同じ順序にする。月だけ先に倍率を上げない。
仲間の累撃倍率を保存済みの幻傷へ重ねて掛けない。
月の本人が再行動して強い幻傷へ刻み直すことは認めるが、既に使った実体化回数は回復しない。

## 動作例

敵Aに100万の幻傷がある。初期上限は3回、再現割合は検証用に100%とする。

1. 仲間Bが多段攻撃: B自身の攻撃に加えて100万を1回実体化。残り2回。
2. Bが再行動して攻撃: 100万をもう1回実体化。残り1回。
3. 月の本人が200万へ刻み直す: 敵HPは減らず、残り1回のまま。
4. 仲間Cが攻撃: 200万を1回実体化。残り0回。
5. 仲間Dが攻撃: D自身の攻撃だけが通る。

途中で敵Aが行動した場合、幻傷は消える。刻み直しても、そのラウンドの使用済み回数は残る。
この例は挙動の説明であり、100万・200万・100%はバランスの確定値ではない。

## 実装担当が確認する境界と推奨初期案

ここからは未確定部分を含む。中核仕様との区別を保ち、実装調査後に採用内容を記録する。

| 論点 | 推奨初期案・確認事項 |
|---|---|
| 多段で刻む幻傷 | 技1行動でその敵へ成立した直接ダメージ相当を合算し、行動単位で1つ刻む。最後の1ヒットだけで上書きしない |
| 全体攻撃 | 敵ごとに幻傷を持つ。仲間の全体攻撃は敵ごとに最大1回実体化し、それぞれの回数を消費 |
| 残HP | 保存値を残HPで切り詰めない。実体化時の実損失・撃破・表示は通常のHP処理に従う |
| ミス | 有効な命中がない攻撃では幻傷を刻まない。仲間の全弾ミスでも実体化しない |
| 無効・吸収・障壁 | ダメージの予測値、実損失、吸収の適用段階を確認。無効化を幻傷で迂回しないよう定義する |
| 実体化の順序 | 仲間自身の攻撃解決後に実体化。その攻撃で敵が既に倒れた場合は発生させない |
| 月を持つ仲間 | 月の攻撃は幻傷を刻む側とし、他の月の幻傷を実体化しない。複数の月だけで直接攻撃できるようにしない |
| 召喚体 | 参加を検討できる。人数で上限が増えないため、以前の通常メンバー限定案は必須ではない。召喚の最新仕様と照合して確定 |
| 皇帝の命令 | 命令された者が月なら刻む。月でない味方なら残り回数の範囲で実体化する |
| 敵の行動不能 | 実際の敵行動開始で消すか、行動機会で消すかを定義。初案は技の実行開始時に消し、麻痺で完全に失敗した場合は残す |
| 正義の応撃 | 敵の実際の攻撃なので消滅対象にする案。予約・応撃・実体化の順序を最新実装で検証 |
| 持ち主の死亡 | 初案は既に刻んだ幻傷を残す。戦闘内IDを使い、死亡後も帰属を保持 |
| 回復・補助技 | 通常どおり使える。幻傷を刻まず、実体化もしない |

### ダメージの帰属と付随効果

- 幻傷には刻んだ者の戦闘内IDを保存する。起動した仲間と、傷の作者を区別できるようにする。
- 実体化時に保存済みの上限・属性・防御計算を二重適用しない。一方で、現在の無敵等を不当に迂回しないよう、保存する段階と適用する段階を確認する。
- 初版では実体化を専用ダメージとして扱い、与ダメージ回復・状態異常付与・撃破時再行動等を新たに起動させない案を推奨する。通常の撃破報酬は1回だけ与える。
- 刻む攻撃の付随効果は個別に確認する。命中時効果と実ダメージ依存効果を混同しない。
- 継続ダメージ・反射・棘を月の本人が持つ場合の扱いは未確定。「本人では絶対に倒せない」とは説明しない。直接攻撃を幻傷に置換する仕様との整合を取る。
- 命中やダメージを検証するため、実際にHPを減らしてから戻す実装は避ける。死亡・反射・吸収・報酬が誤発火するため。

## 実装構成の方針

- `battle.js` の攻撃解決に、直接ダメージを幻傷へ置換する入口、仲間の行動終了時の実体化、敵行動時の消滅を設ける。
- 「通常攻撃」「幻傷を刻む攻撃」「実体化によるダメージ」を識別し、反応の再帰を防ぐ。
- 敵に幻傷の値・作者を持たせ、別にラウンド単位の実体化回数を管理する。ラウンドの識別方法はウェーブ間のリセットも含めて既存実装に合わせる。
- 累撃・会心・多段等の計算は通常経路を共有し、月専用に似た式を複製しない。
- オートでは、刻み直しの見積もりと直接ダメージの見積もりを分ける。HPを減らさない攻撃を無価値として選ばなくなる問題と、残り0回でも刻み続ける問題を検証する。
- UIには幻傷の大きさと「今ラウンド残り何回」を表示する。幻傷が消えていても使用済み回数は確認できるようにする。
- 新効果の登録は登録簿、tree、分類、手順書、検査の一式を揃える。
- 札、解放依頼、単色SVGは中核の採用後に整える。解放依頼で月自身を要求しない。
- 既存の皇帝・恋人・正義・召喚の作業状況を確認し、進行中の変更を上書きしない。

## 検証項目

1. 刻む攻撃で敵HPが減らず、通常の累撃タイミングを維持する。
2. 保存後に本人や仲間の累撃・能力が変わっても、既存の幻傷の値が変わらない。
3. 実体化で累撃、再行動、再実体化が発生しない。
4. 同じ敵への実体化は全員合計で上限まで。多段1行動は1回、再行動は別の1回。
5. 刻み直し・別の月による上書き・敵行動による消滅で回数が戻らない。
6. ラウンド更新時にだけ回数が戻り、ウェーブ間に旧敵の情報が残らない。
7. 全体攻撃でも敵ごとの上限が独立し、仲間の通常攻撃で死亡した敵に追加処理しない。
8. 反射・棘・自動反撃が実体化を起動しない。
9. 命中、無効、吸収、障壁、死亡、撃破報酬が確定した適用順序に従う。
10. 手動・オート・皇帝の命令・採用する場合の召喚で同じ中核規則を通る。

## 調整の手順

1. 最初は再現割合を100%で固定し、敵1体・1ラウンドの上限2回／3回を比較する。100%は検証用の初期仮定。
2. 同じ編成・装備・SP・シードで札なし／既存札／月を置き換えて測る。
3. 累撃型、単発大技型、多段型を比較。月の前後で味方の順番を変え、手番配置の意味を測る。
4. 再行動特化、皇帝との連携、複数の月、召喚を含む場合を確認する。
5. 相なし周回と相を重ねた高難度を分ける。敵の行動頻度と、消える前に何回実体化できたかを記録する。
6. 上限回数と再現割合を同時に動かさない。回数だけでは適正域に収まらない場合に初めて割合を調整する。

記録: 勝敗、通算ラウンド、行動数、刻んだ回数、実体化回数、保存値、実体化の実ダメージ、使用前に消えた幻傷、無駄な刻み直し。
強い一撃を仲間が繰り返し利用する利益と、本人が直接HPを削れず敵行動で幻傷を失う制約の両方が出るかを見る。
実測前に適正倍率や勝率を確定しない。
